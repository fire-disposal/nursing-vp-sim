# AGENTS.md — Project Conventions

## Migration Rules (alembic)

**Always use `--autogenerate`**, never hand-write DDL:

```bash
cd backend
alembic revision --autogenerate -m "describe_your_change"
```

This ensures:
- `down_revision` is always set to the current head (prevents branching)
- `upgrade()` and `downgrade()` are auto-generated from model diff
- No manual `depends_on` / `revision` strings

**Two kinds of migration, never mixed in one file:**

| Type | How | Contains | File marker |
|------|-----|----------|-------------|
| **DDL** | `--autogenerate` | CREATE/ALTER/DROP TABLE, add_column, drop_column, indexes, constraints | `# ### commands auto generated by Alembic` |
| **Data** | hand-written | INSERT, UPDATE, seed data, `op.execute()`, sequence fix, NOT NULL enforcement after data fill | `# Manual override reason: data_only` |

**Autogenerated files MUST NOT contain `op.execute()`.** If you need data operations, create a separate data migration after the DDL migration.

**Data migrations MUST include a reason** in the module docstring:
```python
"""describe_your_change

# Manual override reason: data_only
"""
```

If `--autogenerate` produces an empty migration, do not commit it.

Pre-commit hook (`check-migration-autogen.js`) enforces both rules.

## Testing

```bash
# Full test suite (requires local PostgreSQL)
cd backend && pytest -m pg

# Unit tests only (no DB required)
cd backend && pytest -m "not pg"
```

## Pre-commit Checks

All commits must pass:
- `ruff check` / `ruff format` (backend)
- `biome check --write` (frontend)
- `tsc --noEmit` (frontend)

## Commit Format

<emoji> <type>: <description>

Types: feat, fix, refactor, ci, test, style, chore, perf, security, db, docs, remove
