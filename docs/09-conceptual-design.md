# 09-概念设计与创新方向

> 本文档记录对系统未来演进方向的概念性探索，不涉及具体实现计划。用于团队讨论与技术选型参考。

---

## 一、现状评估

当前系统是一个**LLM 驱动的虚拟病人问诊训练平台**，核心流程为：

```
学生选择病例 → 与 AI 病人文字对话 → 自动评分（沟通+病史采集）
```

### 关键特征

| 维度 | 现状 |
|------|------|
| 交互方式 | 纯文本对话（语音输入为浏览器端 Web Speech API） |
| 病人模型 | 静态 JSON 病例文件，无动态状态 |
| 生理模拟 | **无** — 无 HR/BP/RR/SpO2/Temp/疼痛等任何生命体征数值 |
| 视觉呈现 | 10 张固定 PNG 头像（按年龄+性别分 4 组 + 护士 2 张） |
| 情感/态度模型 | 仅 `communication_style` 文本提示 |
| 评分维度 | 沟通技能 14 项 + 病史采集 5 项，**无临床推理/护理操作/文书书写评分** |
| 操作感 | 仅打字/说话，无体格检查、无护理操作、无医疗文书 |
| 训练闭环 | 问诊即结束，无后续记录书写、交班汇报等延伸 |

### 核心 gap

1. **缺乏"活"的病人** — 病人没有动态生理状态，学生无法观察病情变化
2. **缺乏操作训练** — 只练"问"，不练"做"（测体征、做护理操作）
3. **缺乏文书训练** — 真实护理工作中，问诊后必须书写护理记录，当前系统无此环节
4. **缺乏完整闭环** — 问诊→记录→交班→护理计划 是一个完整流程，当前只覆盖了第一步

## 二、创新方向总览

```
                    当前系统
                       │
       ┌───────┬───────┼───────┬───────┐
       ▼       ▼       ▼       ▼       ▼
    A.生理  B.状态  C.情感  D.视觉  E.文书
    模拟    机      模型    增强    写作
```

| 编号 | 方向 | 核心变化 | 新颖度 | 实用价值 | 实现复杂度 |
|------|------|---------|--------|---------|-----------|
| A | **生理模拟引擎** | 构建病人生理数值模型，生命体征随时间演变 | ★★★★★ | 极高：让学生看到"活"的病人 | 高 |
| B | 病人状态机 | 病情阶段流转（稳定→恶化→危重），受干预影响 | ★★★★ | 高：训练临床判断和应急反应 | 中 |
| C | 情感/态度/教育水平模型 | 病人心理状态随沟通质量动态变化 | ★★★★ | 高：训练护患沟通的真实复杂性 | 中 |
| D | 动态头像 + 体征可视化 | 静态 PNG → 实时面部表情/肤色 + 监护仪面板 | ★★★ | 中：沉浸感提升，偏表现层 | 中 |
| E | **护理记录书写训练** | 问诊后增加结构化护理记录书写+AI评分 | ★★★★★ | 极高：补全真实工作流缺失环节 | 低~中 |

> **本文档重点展开 A（生理模拟引擎）和 E（护理记录书写训练），这两个方向对现有系统的增量最小、实用价值最高。**

## 三、方向 A：生理模拟引擎 + 护理操作

### 3.1 概念定位

在现有 LLM 对话系统之外，构建一个独立的**病人数字孪生模型**。该模型模拟病人的生理参数随时间演变，并通过护理操作面板向学生"揭露"这些信息。

**关键设计原则：LLM 病人不知道这些数据。** 生理参数走独立的非 AI 通路，病人通过对话只表达主观感受（"我喘不上气"），不直接报数值（"我的血氧是 92%"），保持沉浸感。

### 3.2 参数范围（护理观察视角，12 项）

| 类别 | 参数 | 数据类型 | 取值/范围 |
|------|------|---------|----------|
| **核心生命体征** | HR（心率） | 数值 | 40-180 bpm |
| | BP（血压） | 数值对 | 收缩压/舒张压 mmHg |
| | RR（呼吸频率） | 数值 | 8-40 次/分 |
| | SpO2（血氧饱和度） | 数值 | 70-100% |
| | 体温 | 数值 | 35.5-41.5°C |
| **评估量表** | NRS 疼痛评分 | 数值 | 0-10 |
| | AVPU 意识状态 | 枚举 | Alert / Verbal / Pain / Unresponsive |
| **皮肤观察** | 皮肤描述 | 文本 | 颜色/温度/湿度 |
| **症状量表** | 呼吸困难度 | 数值 | 0-10（COPD等病例） |
| | 恶心/呕吐度 | 数值 | 0-10（阑尾炎等病例） |
| **出入量** | 尿量趋势 | 数值 | ml/h（心衰等病例） |

**病例专属参数**：以上为基础集，每个病例可额外定义 1-3 个病例专属参数（如糖尿病足的伤口大小评分、关节炎的关节肿胀度）。

### 3.3 模拟引擎设计

```
病例 JSON 定义 → 初始化病人状态 → 时间推进 → 参数按曲线变化
                                         ↓
                              护理操作 → 参数响应（揭露或改写）
```

**核心概念：** 每个病例定义一组"时间-参数"曲线，模拟病情自然演变。

**示例（COPD 急性加重）：**

```
时间轴    0min      5min       10min      15min      20min
HR        98        102        108        112        118
BP(S/D)   138/86    140/88     142/90     144/92     146/92
RR        24        26         28         30         32
SpO2      94%       92%        91%        89%        88%
```

### 3.4 护理操作面板

在对话界面的患者头像面板下方，增加操作区域：

```
┌─── 护理操作 ──────────────┐
│ 📋 测量生命体征            │
│   [测血压] [测体温] [测SpO2]│
│ 📋 护理措施                │
│   [吸氧] [调整体位] [安抚] │
│ 📋 观察记录                │
│   [皮肤观察] [疼痛评估]    │
├───────────────────────────┤
│ ⏱ 操作历史                │
│ 10:23 测血压 142/90       │
│ 10:25 吸氧 2L/min         │
│ 10:28 测SpO2 93% (↑2%)   │
└───────────────────────────┘
```

**操作效果分为两类：**
- **测量类**（只揭露，不改变）：返回当前时刻的参数值
- **干预类**（揭露+改写）：改变参数的未来轨迹（如吸氧 → SpO2+2% → RR曲线下调）

### 3.5 与现有系统的集成方式

**隔离原则：** 生理引擎 = 平行系统，不修改 LLM 对话流。

```
                      ChatTraining 页面
              ┌──────────────┼──────────────┐
              ▼              ▼              ▼
        LLM 对话流      生理引擎面板     现有评分引擎
        （不变）        （新增独立模块）   （不变）
                              │
                    ┌─────────┴─────────┐
                    ▼                   ▼
              操作记录存储          新增评分维度
                                    "护理观察完整度"
```

## 四、方向 E：护理记录书写训练系统

### 4.1 概念定位

在问诊训练结束后，学生进入**第二阶段：护理记录书写**。基于问诊中采集到的信息，书写符合临床规范的结构化护理记录，系统自动评分。

### 4.2 训练流程

```
┌──────────┐     ┌──────────────┐     ┌──────────┐
│ 阶段一    │ ──→ │ 阶段二        │ ──→ │ 评分     │
│ 病史采集  │     │ 护理记录书写  │     │ 文书评分 │
│（当前）   │     │（新增）       │     │（新增） │
└──────────┘     └──────────────┘     └──────────┘
```

### 4.3 护理记录模板（SOAP 格式）

```
┌─────────────────────────────────────────────┐
│  护理记录                                                    │
│                                                              │
│  S - 主观资料（患者自述）                        │
│  ┌──────────────────────────────────────────┐ │
│  │ 患者诉......                                            │  │
│  └──────────────────────────────────────────┘ │
│                                                              │
│  O - 客观资料（观察/测量）                        │
│  ┌──────────────────────────────────────────┐ │
│  │ T: ___°C  P: ___次/分  R: ___次/分      │  │
│  │ BP: ___/___mmHg  SpO2: ___%               │  │
│  │ 皮肤: ___  意识: ___  疼痛: ___/10       │  │
│  └──────────────────────────────────────────┘ │
│                                                              │
│  A - 护理评估                                                │
│  ┌──────────────────────────────────────────┐ │
│  │ 护理问题：                                              │  │
│  │ 1. ......                                              │  │
│  │ 2. ......                                              │  │
│  │ 评估依据：                                              │  │
│  └──────────────────────────────────────────┘ │
│                                                              │
│  P - 护理计划                                                │
│  ┌──────────────────────────────────────────┐ │
│  │ 护理目标 + 护理措施 + 评价指标            │  │
│  └──────────────────────────────────────────┘ │
│                                                              │
│  [提交评分]  [保存草稿]                            │
└─────────────────────────────────────────────┘
```

### 4.4 病历卡区域演进路线

| 阶段 | 病历卡功能 | 说明 |
|------|-----------|------|
| **当前** | 占位符 | `"病历记录区域预留"` |
| **步骤 1** | 随堂便签本 | 训练中可打字记录关键信息，结束可回顾 |
| **步骤 2** | 结构化模板 | 训练结束后弹出 SOAP 模板，学生填写 |
| **步骤 3** | 独立文书模块 | 不绑定问诊训练，可独立进行文书写作练习 |

### 4.5 文书评分维度（Rubric 草案）

| 维度 | 权重 | 评分要点 |
|------|------|---------|
| **信息完整性** | 30% | 主诉、现病史、既往史、用药史是否在 S 中有体现 |
| **客观数据准确性** | 20% | O 部分与病例数据是否一致 |
| **护理评估质量** | 25% | 是否识别出关键护理问题，优先级是否正确 |
| **护理计划规范性** | 15% | 目标可测量、措施具体、有评价指标 |
| **文书格式规范** | 10% | 专业术语使用、结构清晰、无口头语 |

### 4.6 技术实现思路

- **前端**：新增 `NursingRecord` 组件（SOAP 表单），嵌入训练结束流程
- **后端**：新增 `nursing_records` 表，新增 `/api/records/{id}/nursing-record` 端点
- **评分**：复用现有 LLM 评分基础设施（`llm_service.call_llm_json`），新增 `rubrics/nursing_record_v1.json`
- **数据库**：与 `training_records` 一对多关联（一次训练可对应多次文书练习）

## 五、方向 B/C（状态机 + 情感模型）简述

### 5.1 病人状态机（B）

为病人定义病情阶段状态流转：

```
稳定期 → 代偿期 → 失代偿期 → 危重期 → (护理干预后) → 稳定期
```

每个阶段对应不同范围的生理参数区间和不同"力度"的触发隐藏信息。学生能否及时识别病情恶化阶段并采取相应行动，成为新增评分维度。

### 5.2 情感/态度/教育水平模型（C）

在 LLM prompt 中注入动态的"病人心理状态"：

| 维度 | 范围 | 影响 |
|------|------|------|
| 焦虑度 | 0-10 | 回复长度、信息组织逻辑 |
| 配合度 | 0-10 | 是否愿意回答、回答详略 |
| 健康素养 | 低/中/高 | 用词水平、对医学概念的理解 |
| 疼痛耐受 | 低/中/高 | 症状描述的夸大或淡化程度 |

这些维度随学生沟通方式变化。粗暴提问 → 焦虑↑、配合↓。安抚、共情 → 配合↑、焦虑↓。

## 六、演进优先级建议

```
Phase 1（当前系统稳定迭代）
  ├─ 病历卡：从占位符 → 随堂便签本（步骤 1）
  ├─ 护理记录书写：SOAP 模板 + AI 评分（方向 E 核心）
  └─ 新增护理文书评分维度

Phase 2（生理引擎基础建设）
  ├─ 生理模拟引擎：时间-参数曲线模型
  ├─ 护理操作面板：测量型操作（只揭露）
  └─ 操作记录存储 + 后端 API

Phase 3（深度模拟）
  ├─ 干预型操作（操作改写病人状态）
  ├─ 病人状态机（病情阶段流转）
  └─ 动态头像增强

Phase 4（智能化扩展）
  ├─ 情感/态度动态模型
  ├─ 多人协作训练
  └─ 跨会话能力追踪
```
