## 一、决策：先减小上下文内核，再完成可用性研究候选

### 1.1 原始问题

项目服务的原始训练缺口是：

1. 课堂角色扮演与标准化患者训练的情境真实性有限；
2. 护生缺少可重复、低风险的临床前练习机会；
3. 练习后难以得到及时、具体、可用于自我纠正的反馈；
4. 护生在提问逻辑、情绪回应和复杂情境应对上缺少持续练习。

权威需求研究为 Zeng et al., *BMC Nursing* (2026) 25:826，
[DOI 10.1186/s12912-026-04942-z](https://doi.org/10.1186/s12912-026-04942-z)。
该研究得到的是**系统使用前的期待、需求与边界**，不是系统教学效果证据。学生期待的是连接课堂与临床的
补充性训练工具：支持情境练习、重复使用、即时反馈和自我纠正；不替代教师、标准化患者或真实患者接触。

### 1.2 U0 唯一研究问题

> 护理本科生能否独立完成一次虚拟患者训练、理解系统反馈，并认为整条流程易于使用？

U0 评价**系统可用性**，不评价沟通能力提升、临床迁移、AI 评分效度或能力等级。系统内部训练分只作为
本次反馈界面的组成部分，不作为 U0 的研究结局。

### 1.3 代码侧下一步

```text
删除上下文链路中无消费者、无跨轮效果的抽象
  → 收敛为一个可测试的患者上下文编译入口
  → 修正已知的患者机械问答约束
  → 让固定病例的场景与任务在开场可理解
  → 走通问诊、工具、评估提交、结束、反馈、问卷
  → 真实 LLM 与浏览器预演
  → 冻结 usability-u0 候选
```

本批允许做保持行为的上下文内核减法，但不在 U0 前建设通用实验平台。上下文热发布、A/B 分配和效果对比
只作为 U0 后的受控扩展；不得以“热重载”为名改写进行中的训练。

## 二、当前基线与剩余缺口

### 2.1 已交付且继续复用

| 能力 | 当前事实 | U0 处置 |
|---|---|---|
| 正式训练闭环 | `history_taking` 已支持患者对话、床旁活动、护理评估提交、结束、异步评分与教师复核 | 原样复用 |
| 可信状态 | 保存、完成、评分、失败、离页暂停与语音降级已有真实状态；终态持久化缺陷已修复 | 只修预演发现的阻断问题 |
| 反馈 | 逐项原始分、证据引用、关键选择、教师意见、同例重练与变式入口已存在 | U0 只验证学生是否看得懂，不继续扩建 |
| 研究身份 | 病例 revision、患者 prompt/rubric 快照、评分提示词身份、模型/映射/政策身份可追溯 | 用于冻结候选和解释数据 |
| 实验批次 | `EXPERIMENT_BATCH` 或开始请求的 `experiment` 可写入 `practice_snapshot`，并随评分和导出保留 | 固定为 `usability-u0` |
| 问卷 | 已有 `after_scoring` 触发，支持 `likert_5` 与 `short_text` | 配置 SUS 与少量开放题，不建新问卷系统 |

### 2.2 上下文债务（C0 已闭环，2026-09-27）

链路曾同时存在**控制面缺失与运行时抽象过多**。C0 按下表逐条处置（证据见 §四 C0）：

| # | 债务 | 处置 |
|---|---|---|
| 1 | `PromptContext` 名为多命名空间注册表，患者与评分调用点都只注册一个命名空间再展平 | 删除该模块；两处直接用各自的类型化变量字典 |
| 2 | `STATE_PATIENT_CONTEXT_KWARGS` 名为跨轮缓存，实为一次调用内写一次、读一次 | 删除；病例变量改为每次编译现算（纯函数） |
| 3 | `STATE_ASSEMBLER` 只写不读；`WorkflowDefinition.context_profile` 无消费者 | 两者删除 |
| 4 | token 账本只写 debug 日志；自适应预算入口（估算/实际用量回流）无生产接线 | 账本、`resolve_token_scale`、`MAX_TOKEN_SCALE` 与 `reconcile_tokens` 全部删除；真实用量仍由 `llm_call_logs` 逐条承载 |
| 5 | `context_policy_version` 只覆盖常量，单改装配算法身份不变 | 身份改为 `ContextPolicy` 字段 + `COMPILER_SCHEMA` + 结构标记 |

处置原则是**删除无消费者的抽象**，不在旧层次上继续叠加数据库模板、缓存失效或在线分流。

### 2.3 进入 U0 前必须修正

1. **患者回答被全局约束成机械问答。**
   `prompts/patient.py` 同时要求“每次回答 1–3 句话”“问一句答一句是常态”“未明确问到不主动提供”，
   容易复现需求研究中明确担忧的机械、程序化互动。回答详略应由病例、人格、当前病情和对话语境决定，
   不能由一个全局句数上限决定。
2. **病例场景没有形成稳定的内容基线。**
   `context/case_vars.py` 的静态场景（`_DEFAULT_SCENARIO`）仍是通用“在医院采集病史”；运行时虽支持
   `case_data.scene → runtime_state.scene → prompt`，内置病例当前没有 `scene`。
   U0 选定病例必须有明确环境、患者可见状态和任务边界，并发布为新的不可变 revision。
3. **开场说明偏操作提示。**
   `WelcomeScreen` 已展示患者、主诉、活动步骤和建议开场，但结尾只说明“提问→结束评分”；
   U0 需要让学生在开始前知道自己的角色、要完成的产物以及结束后会看到反馈。
4. **研究候选尚未冻结。**
   当前没有一份同时钉住应用版本、病例 revision、模式、模型配置、患者 prompt、rubric、问卷模板和
   批次名的 U0 候选记录。

### 2.4 当前不能声称

- 不能声称患者互动已经达到真实患者的真实性；
- 不能声称 AI 分数已经校准、具有测量学效度或可解释为能力等级；
- 不能声称同例重练后的分数变化代表迁移；
- 不能以完成率、均分、优秀率或满意度单独证明教学效果；
- 不能把需求研究中的预期收益写成系统使用后的实际学习效果。

## 三、`usability-u0` 固定协议

### 3.1 固定条件

正式 U0 数据必须来自同一组条件：

| 条件 | 固定要求 |
|---|---|
| 应用 | 同一提交与 `APP_VERSION` |
| 环境 | 同一部署实例；不得混合本地、测试与生产记录 |
| 批次 | `experiment.batch = "usability-u0"`；U0 不设 arm |
| 病例 | 同一个经护理教师确认的 `CaseRevision` |
| 模式 | 同一个训练模式；不混合 guided / assessment / blind_box |
| 模型 | 同一 patient/scoring profile 与供应商配置 |
| 提示词与评分 | 同一患者 prompt 内容、rubric 内容与映射口径 |
| 问卷 | 同一份 SUS 模板与开放题 |

候选冻结后若修改任何会改变参与者体验或结果解释的条件，新记录必须进入新批次，不得继续标作
`usability-u0`。

### 3.2 统一参与者任务

```text
阅读患者与任务说明
  → 完成病史采集和治疗性沟通
  → 按病例要求使用床旁活动
  → 提交护理评估
  → 结束训练并等待评分终态
  → 查看关键选择、逐项证据与反馈
  → 完成 SUS 和开放题
```

教师复核可在研究后补充，不作为学生完成 SUS 的等待条件；否则教师响应时间会混入学生端系统可用性。

### 3.3 收集边界

主要结果：

- SUS 十个条目及按标准规则计算的总分。

补充材料：

- 训练是否完成、各阶段阻断与技术降级；
- 训练时长、消息与工具使用仅作过程描述；
- 三个开放题：最不顺的步骤、最有用/最不可信的反馈、最不像真实情境之处。

系统内部评分、能力标签、班级排名和前后变化均不是 U0 结果。问卷统计和论文结论不在本代码计划中预填。

## 四、实施顺序

### C0：患者上下文运行时收敛（已实施，2026-09-27）

**实际改动**

1. 装配合并为唯一纯入口 `context/compiler.py::compile_patient_prompt`（原 `ContextAssembler` 类 +
   `assemble_patient_messages` 双入口 + `patient_state.py` 三处归一）；入参用 `role` / `scenario`
   与槽位词汇一致，返回 messages，不再返回内部账本。
2. 删除 `pipeline/prompt_context.py` 与 `pipeline/prompt_context_builder.py`：病例模板变量移到
   `context/case_vars.py::build_case_vars`，病例生成侧文本块移到 `modules/cases/prompt_format.py`。
3. 删除伪跨轮缓存 `STATE_PATIENT_CONTEXT_KWARGS`、只写不读的 `STATE_ASSEMBLER` 与无消费者的
   `WorkflowDefinition.context_profile`。
4. 预算收敛为单一 `ContextPolicy`（`context/budget.py`）；删除未接线的自适应预算链路与 token 账本，
   截断/折叠的可观测面改为**消息结构与告警日志**，真实用量仍由 `llm_call_logs` 承载。
5. 策略身份 = `ContextPolicy` 字段 + `COMPILER_SCHEMA` + 槽位/示例/摘要标记；改算法必须显式升
   `COMPILER_SCHEMA`。
6. PROMPT 阶段不再写任何 `ctx.state`；动态模板渲染失败不再静默退化为"没有病例信息的患者"。

**通过条件（已达成）**

- 21 组夹具（短/长/饱和历史、零预算、示例段、场景状态、片段截断与丢弃、越权来源、守卫追加）的
  messages 与收敛前实现**逐字节一致**（临时工作树对比 HEAD 实现，21/21）；
- 越权与超预算贡献从"只记账本"变为**记 warning 日志**，越权内容与行为断言不变；
- 新训练仍冻结精确 prompt 原文与可重算的策略身份；旧记录仍可读；
- 后端全量 1623 项测试、`ruff` 与 `ty` 全绿；
- 真实 provider 冒烟通过：真实病例渲染 → 编译 → 患者回复 → 泄漏守卫命中 → 守卫修正追加后再调一次。

C0 不引入数据库上下文表、在线编辑器、A/B 分配或活动中会话热更新。

### U0-A：患者自然度与场景（提示词与链路已实施，2026-09-27）

**实际改动**

1. `prompts/patient.py`：删除全局句数上限（原“每次回答 1-3 句话”），改为**说多少由情境决定**——
   详略由性格、说话风格、当前情绪与问题分量决定，并显式禁止“每轮答成同样的长度和句式”。
2. 同文件删除“问一句答一句是常态”，改写**保持人物真实感**：允许犹豫、含糊、啰嗦、跑题、答非所问、
   抱怨与反问，但**不允许**用故意拒答或“没说对关键词就不开口”来制造难度。
3. `patient_ai/emotion/behavior.py`：逐轮情绪注记里的数字句长（“通常 1 句以内 / 1～3 句 / 2～4 句”）
   改为相对描述（话明显更少 / 该简的简该细的细 / 回答会展开），语气描述里的“问一句答一句”同步改写。
   情绪标量（`verbosity` 等）与其阈值不变，只改对模型的措辞。
4. 保留全部既有契约：含义问法即算问到、已说信息不重问、顺着线索给细节、事实跨轮一致、不知道就说不知道、
   情绪不是信息门锁、辱骂升级与边界。

**通过条件（已达成）**

真实 provider、真实病例（`data/cases/case1.json`）、脚本化 7 轮问诊（含真实情绪行为注记）：

- 四类对话齐备：简短事实（20 字/3 句）、线索展开（给出“上到 2 层就喘”）、记不清
  （“血氧……我真想不起来了”，**未编造数字**）、情绪顾虑（“我怕我这肺是不是出了大问题”）；
- **不问不说**：7 轮 0 次隐藏主题泄露（`咯血` / `停药` / `家属担忧`）；
- **不改口**：同一事实换问法两次都答“3 天”；
- **换词追问仍作答**：问“痰里有没有带过血”得到“痰里带过一点点血丝”，非关键词解锁；
- **篇幅不单一**：句数 {3,4,5,6}、字长 20–71（最长/最短 3.55），未退化为同长度同句式。

**剩余（归 U0-C）**：场景注入的**机制**已确认并有回归——`runtime_state["scene"]` → PER-TURN 消息，
含坏场景降级不失败（`tests/training/test_prompt_builder.py`）。U0 病例 `scene` 的**内容**需在选定病例后
由护理教师确认并随新 revision 发布，本轮不凭空编造（内置病例当前无 `scene`）。

**相邻缺陷处置（2026-09-27）**

- **已修：豁免窗口只看本轮**。学生第 3 轮问过吸烟史、患者第 5 轮又提到烟，原实现判成"主动说出医生视角
  信息"并触发一次**错误的**纠正重试；纠正话术还会让患者收口，压掉学生**已经问到**的信息——与本节通过条件
  「学生合理追问能得到对应细节」直接冲突。现在 `asked_text` = 历史学生消息 + 本轮输入
  （`llm_caller._asked_so_far`；主动追问路径用最近两轮上下文，与生成输入一致），带回归用例。
- **仍开放：换词漏判（T7/PIP-13）**。判定仍是子串匹配：键「咯血」抓不到回复里的"血丝"，键「停药」抓不到
  "把药停了"。本轮实测到一次漏判——学生换词问到时**行为正确**，故不影响 U0-A 通过条件；但患者**主动**
  说出同类信息时护栏不报。修法需要作者可声明的别名（病例 schema 变更 + 门禁登记）或语义判定（每轮多一次
  LLM 调用），属独立决策，不在本轮擅自定。

### U0-B：开场、交卷与反馈衔接（已实施，2026-09-27）

**实际改动**

1. 开场屏 `WelcomeScreen` 自读 manifest（不再由 `ChatArea` 透传 activity 清单），首屏给出：角色（责任护士）、
   按服务端活动生成的步骤（必交产物标「必交」+ 产物状态徽章、不可用活动单列原因）、「还缺什么」原样引用
   `blocker.message`、必交产物说明、如何交卷、结束后路径（等评分 → 关键选择回看 → 逐项判定与证据 → 反馈问卷）。
   开场**不新增完成条件判定**，只做呈现（docs/15 §四）。
2. 交卷一跳：`CompletionChecklist` 增加 `onNavigated`，结束确认弹窗内的「去处理」在打开面板的同时收起弹窗
   （此前弹窗压住面板＝跳了等于没跳）；blocker 有 `target` 但本端定位不到落点时给「请手动打开处理」，
   不再给假按钮；`target` 为空（如「训练已结束」）不加动作。
3. 失败归因分开：草稿落盘失败不再被说成「结束训练失败」，而是「护理记录未能保存到服务器，交卷已中止」
   并直接打开护理记录面板；到点自动交卷被拦下时把完成清单重新摆出来（不再只留一条会消失的 toast）；
   评分重试的退避窗口改为可转述的类型化错误（`请等待 N 秒后重试`）。
4. 产物状态一致：首次草稿落盘（服务端状态 `empty → draft`）后立即失效 manifest 查询，消除侧栏/能力条
   「未填写」最多滞后一个 15s 轮询周期的问题；判据是服务端已下发状态，不是前端自算。
5. 问卷可见性：`has_pending=true` 但题目拿不到时**必须可见且可重试**（结果页红色提示「问卷加载失败 /
   你的作答尚未被记录」；`before_training` 必答问卷同理，不再卡死而无法重试）；`check` 失败单列黄色提示，
   不阻塞成绩查看；`has_pending=false` 仍然什么都不显示（不误报）。
6. 结果页口径：逐项判定行新增来源徽章（`AI 初评` / `教师复核`），来源以服务端字段为准——`score.review.detail_scores`
   非空则逐项展示教师判定，否则标注 AI 初评并在总分已复核时说明关系；删除无生产者的 `_reviewed` 死分支。

   （头像 36 + 姓名/主诉一行，大图按需展开，情绪行常驻）、横屏收为 88px 窄条；侧栏/能力条命中区提到 44px；

**本轮实测发现的阻断级缺陷（不在 U0-B 范围，U0 施测前必须修）**

一次完整训练（真实 LLM 对话 3 轮 + 完整 ADPIE 护理评估）评分落 **0 分 + `fallback.kind=llm_empty`**，
重试仍复现。证据链：

1. `llm_call_logs`（purpose=scoring，record 12）：三次调用的 `completion_tokens` = 14000 / 7882 / 6633
   （`max_tokens=16384`，评分 profile 开启 thinking）；
2. 落库的 `response_text` 中 `{` 比 `}` 多 1 —— **顶层对象未闭合**，`json.loads` 在文本末尾抛
   `Expecting ',' delimiter`，`safe_parse_json` 的三层兜底（去尾逗号/截断修复/字段正则）均未救回；
3. `_stream_attempt` 把解析失败当作 `{}`，两次尝试皆空 → `scoring_fallback_zero` 写入 0 分；
4. 另一处独立偏差：模型把分值写成**带范围批注的字符串**（`"total_score": "20(0~48)"`、
   `"score": "13(0~28)"`），`_coerce_numeric_fields` 对这类值明确「无法转换」并保持字符串——
   即使修好截断，这些字段仍会以字符串进入校验。

**根因**：`_repair_truncated_json` 的括号/引号扫描不做转义感知（中文长串里的 `\"` 让计数错位，多补了 3 个 `}`），
补出的串自身都解析不过却仍被返回 → 三层兜底一次性全废；而 `_stream_attempt` 把"解析失败"一律当成
"模型返回空"，于是重试用**同一套提示**再产出一份同样长的输出、同样被截断，最后按"空"落 0 分。

**修复（2026-09-27，同批）**

1. `parsing.py`：新增 `TruncatedJSONError(ValueError)` 与 `_looks_truncated()`，把**截断**与
   **根本不是 JSON** 分开（前者要压缩输出重试，后者重试无用）；分类保持 `ValueError` 契约，既有调用方不受影响。
2. `_repair_truncated_json` 重写：结构扫描改为转义感知；**补完必须自身可解析才返回**；字符串内部截断时
   丢掉不完整的字段，而不是补一个空串（补空串等于伪造"该字段为空"）。
3. `_stream_attempt` 返回 `(结果, 是否截断)`；`_stage_with_retry` 在截断时改用**压缩输出**专用重试模板
   （`SCORING_RETRY_TRUNCATED_USER` / `FEEDBACK_RETRY_TRUNCATED_USER`），不再拿同一套提示重复长输出。
4. `prompts/scoring.py`：输出前自检新增篇幅与数值纯度约束（`reason` ≤ 60 字、`evidence` ≤ 40 字；
   分值必须是纯整数，不得写成 `"20(0~48)"`；不输出 `max`；必须完整闭合）。
5. `validation.py::_coerce_numeric_fields`：带批注/后缀的数值字符串按**开头数字**转换（`"20(0~48)"`→20、
   `"13(0~28)"`→13、`"35.5分"`→35.5），被忽略的批注记 info 日志；`"N/A"`、`"分20"` 仍保持字符串 + warning。
6. `engine.py::_fallback_scoring`：两次都没有可用结果时抛 `ScoringUnavailableError`（不再写 0 分）——
   执行器据此置 `scoring_status=failed` + `scoring_error`，前端展示失败态并可重试。历史 `llm_empty` 行仍可读
   （`score_source`、判例入选），但不再新写。
7. `infra/llm/client.py`：采集并上报供应商的 `finish_reason`（`stop` / `length`），`length` 时告警；评分阶段把它
   写进截断日志。**此前全仓不读该字段**——没有它，"截断"只能靠 JSON 形状猜，也就分不清"模型说完了"与
   "被输出上限切断"（两者处置完全不同：前者改提示词结构，后者调输出预算）。真实链路已验证回调收到 `stop`。

**验证**

- 用**故障原文**（落库的 `response_text`）直接喂 `safe_parse_json`：修复前抛错，修复后**完整还原**
  `total_score` + 3 维度 + **24 个条目**；
- 真实 provider 对同一记录复评：`0 分 + fallback=llm_empty` → **50 分（原始 24 分）、三维度、条目级证据齐全、
  `fallback=null`**；
- 回归：后端全量 **1646 项**通过（新增解析 4 / 流式分类 4 / 数值批注 8 / 契约 1），`ruff`、`ty` 干净。

## 七、U0 后的 E1：受控上下文发布与对照实验

只有出现至少一次真实的重复实验需求，才进入 E1。目标不是“全局热改”，而是**发布新的不可变上下文 revision，
让未开始的任务选择它；已开始记录永远使用原快照**。

| 切片 | 最小能力 | 复用现有事实 | 明确边界 |
|---|---|---|---|
| E1-A 上下文发布 | 草稿编辑、契约校验、预览、发布不可变 revision、归档 | `CaseRevision` 生命周期、`prompt_snapshot` | 首期只编辑患者模板与场景文本；槽位、守卫、历史算法仍由代码控制 |
| E1-B 任务分流 | 作业草稿/发布时钉住病例 revision、上下文 revision、问卷与受众；受众发布时固定 arm | `Assignment`、`AssignmentRecipient` | 分配单位是学生；同一学生同一作业的重试永远同 arm |
| E1-C 数据冻结 | 开始训练时把 batch、arm、上下文 revision 和精确 prompt 快照写入记录 | `practice_snapshot.experiment`、记录快照 | 请求不能临时覆盖已发布作业，运行中不能换版 |
| E1-D 效果对比 | 按 batch/arm 导出完成、技术失败、问卷和可比评分来源 | 现有导出、版本归因、问卷记录 | 应用内不自动判胜，不代替外部统计分析，不跨不可比量尺合并 |

运行时不需要监听文件、轮询数据库或做缓存广播：训练开始时解析一次发布 revision 并冻结即可。所谓“热”仅指
发布后新训练无需重新部署；不是让已经开始的会话随全局当前值漂移。

E1 前先按 U0 的主要问题选择一个后续研究问题：

| U0 主要发现 | 后续最小实验 |
|---|---|
| 患者仍显机械 | 固定同一病例，比较两种患者互动策略 |
| 反馈难理解或不可信 | 固定训练记录，比较证据化反馈与简化反馈 |
| 情境过于单薄 | 以病例数据构造逻辑组织、情绪回应、复杂情境三类协议 |
| 操作流程阻断 | 先修可用性，不包装为教学实验 |
| 无明显阻断 | 保持固定候选，完成论文范围内的可用性报告 |

每批只改变一个主要因素。U0 仍由现有 `experiment.batch`、冻结快照与导出承载；E1 不成为 U0 的前置依赖。
