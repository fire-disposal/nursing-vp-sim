## 一、为什么另开一轨，且不替代老系统

四个症状都能指到根，且都指向同一件事：**今天"体验"被写死在代码里，且全局唯一**。

| 症状 | 根（证据） |
|---|---|
| 复制粘贴即通关 | `required_inquiries` 在引导模式**对学生可见**（记录详情 `useRecordMeta().requiredInquiries` → 引导清单面板），输入框接受任意长文本且一轮无成本；评分对象正是"这些条目有没有被问到" |
| 清一色低分 | 判读是**固定总量表**（`scoring/rubric.json`：沟通 14 + 病史采集 5，启用护理记录再加 10），分母固定、未完成即固定失分；实测一条对话正常、护理记录五段齐全的会话得 **44/100（原始 21/48）**。这是"完成度"伪装成的"质量分" |
| 千篇一律 | 病例同模板长出（患者 + 六段病史 + 3–5 示例 + 清单 + 一间病房），变化只进"病名"不进"结构" |
| 对话像审讯 | 生成者只有一个且角色固定为患者（`prompts/patient.py`），学生能做的只有 `ask` |

**为什么不在老系统上改造**（三条，逐条有据）：

1. **老系统正在做研究冻结**：`usability-u0` 要求条件固定（[19](19-training-experience-next-generation-plan.md) §三），任何体验改动都会作废该批次；
2. **老路径刚被收敛**：C0 把上下文装配收敛成唯一入口、删掉无消费者抽象（[19](19-training-experience-next-generation-plan.md) §四 C0），再往里塞 DM 与声明式解释器会立刻把它重新打散；
3. **本阶段要允许犯错**：原型期的试错需要一个**可以随便坏**的实验特性——坏的实验不该碰到正在收集的数据，也不该牵动老系统的任何契约。

## 二、承载形态、资源隔离与异构自由（最高约束）

**不新建服务、不新建部署单元**：本轨与老系统同应用、同进程、同数据库实例、同部署；隔离只发生在**模块、数据、路由、提示词与判读**层面。

### 2.1 共享 / 隔离清单

| 资源 | 处置 | 说明 |
|---|---|---|
| **LLM 基础设施**：`infra/llm/**`（供应商配置、客户端、流式、取消、`finish_reason` 采集、JSON 解析） | **共享** | 唯一按本次指令共享的面；本轨**复用** `safe_parse_json`，不自建第二套解析 |
| **平台底座**：`core/**`（DB/会话/事务 `unit_of_work`/鉴权依赖/配置常量） | **共享** | 实测必需：DB 与鉴权依赖都在 `core/**`，不在 `infra/**`；共享它们不引入训练域耦合 |
| 应用进程、部署单元、数据库实例 | **共享** | 同仓同应用；不新建服务、不新建实例 |
| LLM 调用日志 | **共享表 + 独立用途标识** | 复用 `llm_call_logs`（它属 LLM 基础设施的可观测面），本轨 `purpose` 加 `st_` 前缀便于分流统计；若要求物理隔离可改独立表（§十二） |

| 训练运行时状态（`runtime_state` 及 `patch_runtime_state` 契约） | **隔离** | 本轨自己的状态存储与写入契约（可异构，见 2.2） |

| 判读与换算 | **隔离** | 本轨自己的抽取/判定/投影与**唯一换算点**；不调用老系统 `scoring/**` |
| 呈现与路由 | **隔离** | 前端 `src/scenario/**` + 路由 `/scenario`；API 命名空间 `/api/scenario/**` |
| 病例/包发布、版本钉住、分发 | **隔离** | 本轨自己的修订与批次机制（老系统的 `CaseRevision`/作业/批次**不被复用**） |
| 迁移、测试夹具、导出脚本 | **隔离** | 同库独立表命名空间；迁移只增 `st_*`，不改老表 |

### 2.2 异构自由（不为异构而异构）

**允许在第 2.1 表中标为"隔离"的资源上采用与老系统不同的实现范式**，只要对本轨的核心问题确实更好。例：

| 资源 | 老系统范式 | 本轨可异构的理由 |
|---|---|---|
| 运行状态 | 多个 owner 键共用一个 JSONB + 单写者契约 | 本轨的核心是**动作驱动的事件流**：append-only 事件日志天然支持反应链、经历时间线与趋势投影、以及坏实验的回放 |
| 判读 | 单次 LLM 评分 → 总量表 | 本轨是**抽取 + 规则判定**：可复算、可解释、判读面更小 |
| 呈现 | 前端按活动 id 注册组件 | 本轨**声明驱动 + 通用渲染器**（封闭词汇表内） |
| 热载 | 代码常量 + 随版本发布 | 本轨**声明即数据**：加载期校验 + 钉版本 |

**不得为异构而异构**：语言、Web 框架、鉴权、数据库、迁移链、LLM/TTS 客户端、测试与 CI 基础设施与仓库一致——这些换掉只增加维护面，不解决任何本轨问题。

### 2.3 可机器检查的隔离规则

1. **import 方向**：`backend/modules/scenario_training/**` 只允许 import 标准库、三方库、`infra/**`、`core/**`（平台底座）与自身；**不得** import 其他 `modules/**`（唯一例外：共享账号入口 `modules.auth`，本项目实际未用到）。反向也禁止：老模块不得 import 本轨。（已写成测试。）
2. **表命名空间**：本轨只允许读写 `st_*`；迁移与查询中不得出现老表名。
3. **路由与提示词**：本轨提示词文件不出现在 `modules/training/prompts/**`，路由不出现在老 router 集合。
4. **老系统零改动**：本轨不得修改 `modules/training/**`、`modules/cases/**`、`modules/scoreboard/**`、老前端训练页面。

### 2.4 诚实的代价

- **重复实现**：DM 装配、状态存储、呈现投影、判读三段、分发与导出都要在本轨再写一份；老系统 C0 的收敛成果**不被继承**（这是隔离的必然代价，不是疏漏）。
- **两套判读并存**：老系统的换算口径**不适用**于本轨；本轨的分数只能与本轨的数据比较，**绝不与老记录混算**。
- **同一实例同库**：坏实验的爆炸半径靠**表隔离 + 入口开关**控制，而不是靠另一个实例；因此"只写 `st_*`、不碰老表"是硬红线。
- **代价换取**：老系统的 U0 数据、提示词快照与历史成绩不会被任何实验污染；本轨可以随便坏。

| | 老系统 | 情境训练 |
|---|---|---|
| 生成者 | 一个 LLM，角色 = 患者 | **AI DM**：患者/家属/护士/电话那头/环境叙述都是它的角色帽 |
| 学生能做什么 | 白名单活动（`activities.py`：查体/记录/测验/护理诊断） | **声明式 affordance**，界面呈现为**情境按钮** |
| 判读 | 固定总量表逐项打分 + 映射成 0–100 | **决策点 + 三档锚点**；事实抽取与规则判定分离 |

## 四、场景单元 `ScenarioPack`

一份**可版本化、可热载、只被解释不被编译**的声明。运行时是它的**解释器**。包**只声明观察，不含分数**。存储、修订与钉版本全部在本轨（`st_*`）。

```python
ScenarioPack {
  identity:   pack_id @ revision, pack_schema_version     # ⊳ 内容身份与形状分开（docs/17 规则）
  state:      experimental | reviewed                    # ⊳ 草案可直接分发
  scope:      cohorts / batches                          # ⊲ 本轨自己的分发机制

  situation:                                             # 谁在场、知道什么、处境如何
    actors[]:  { role, presence: on_site|remote|callable|inaccessible,
                 knowledge: {...},                         # 知道什么 = 防泄漏边界
                 style, disposition: {trust, comfort, compliance}, goals[],
                 demand: loud|quiet,                       # ⊳ 主动索取注意力的强度
                 degrade_when_unattended: <predicate> }    # ⊳ 未被注意时的恶化
    setting:   { place, visible_cues[], resources[] }
    asymmetry: hidden_from_player: [...]                   # ⊳ 学生看不到什么（防泄漏 + 真实感）
    initial:   { ... }                                     # ⊳ 无时钟

  player:    { role, attention_per_turn: 1,                # ⊳ 学生也是场景中的角色
               can: [affordance_type...] }

  affordances[]:                                           # ⊳ 类型封闭、参数与文案开放（§六）
    { type: ask|observe|measure|act|document|summon,
      label, params, visible_when,
      effects[]:        { target, key, op, value },         # ⊳ 动作改变处境
      perceptible_by[]: [actor_id],
      reveals:          [cue_id] }

  reactions[]:                                             # ⊳ 由动作/状态谓词触发，不由时钟
    { when: <predicate>, by: actor_id, does: say|do|withhold|leave|escalate,
      intent: <生成指令>, effects[] }

  judgment:                                                # ⊳ 只声明观察
    facts_to_extract[]: { fact_id, intent, type: measured|reported, critical }
    decision_points[]:  { id, options[], anchors: {strong|adequate|missed}, evidence_required }
    dims[]:             { dim_id(from 受控词表), agg: coverage|slope|latency }

  presentation:                                            # ⊲ 受词汇表约束
    hud[]:    { slot, source: cue|state|affordance, visible_when }
    nudges[]: { trigger, direction_hint }                  # ⊳ 只给方向，不给条目
    panels[]: { type: timeline|emotion|coverage }

  failure:   recoverable | irreversible                    # ⊳ 做错之后能不能救回来
}
```

标注：**⊳ = 最小必需**；**⊲ = 延后**。

## 五、AI DM

每回合**一次**生成调用，输出 = 叙述 + 台词 + **结构化尾部**：

```json
{ "narration": "他扶着腰，脸色比刚才更白。",
  "lines": [ {"actor": "患者", "text": "…"}, {"actor": "护士", "text": "…"} ],
  "delegate": [ {"actor": "患者", "intent": "…"} ],
  "facts_declared": [ {"fact": "左肩放射痛", "evidence": "…原话…"} ],
  "effects": [ {"target": "患者", "key": "comfort", "op": "decr", "value": 1} ],
  "reveals": ["脉搏细速"],
  "ad_hoc_cues": ["…"],
  "images": [ {"asset_id": "a_room", "caption": "病房"} ],
  "image_request": { "prompt": "…", "caption": "…" },
  "options": [ {"label": "追问放射痛", "type": "ask", "params": {}} ] }
```

平台侧：**校验 → 应用 → 记录**。校验失败（非 JSON、词表外的键）→ 重试一次；再失败则**退化为"只叙述 + 通用选项"**，学生永远看不到坏回合（与老系统泄漏守卫的重试同构，但实现独立）。

**三条硬规则**

1. `options` 只能来自 `affordances` 与可见线索，**绝不能来自 `facts_to_extract` 的具体条目**——否则按钮直接给答案。
2. `effects` 只允许**本轨已登记的状态键**与词表内操作——DM 有想象力，但改动必须声明式。
3. DM 不得发明与 pack 冲突的事实；冲突以 **pack 为准**，并在记录里标记"DM 即兴"。

**即兴额度（已确认）**：可**引入新的可见线索**，不得与 pack 冲突；"凭空造角色/造事实"只留给实验包。

**DM 的"方言"以实测为准（裁定 2026-09-27：DM 习惯怎样就怎样，符合实测操作直觉第一）**

对 57 次真实 DM 调用做字段统计，结论是**契约本身没问题**，唯一偏差在效果操作写法：

| 观测 | 结果 | 处置 |
|---|---|---|
| 顶层字段 | `narration/lines/facts_declared/effects/reveals/ad_hoc_cues/options` 57/57 命中 | 无需改名 |
| `options.type` | 全部落在词表内（ask/act/observe/measure/document/summon） | 无需放宽 |
| 非法 JSON / 截断 | **0 次** | 无需改解析器 |
| `op` 写法 | `set` 58 · **`add` 17** · `incr` 4 · `decr` 4 · `sub` 1 · `delta` 1 | 等价归一（`delta` 按符号定向） |

原则：**平台说 DM 的方言，不让 DM 迁就平台**；归一表只依据实测证据扩充，不做投机性放宽。
（这也是"改提示词让 DM 用 `incr`"的反面：`add` 是它的第二常用写法，改提示词等于每回合多花一次纠正。）

**为什么这样判读反而更准**：判读**只读世界事实**（线索是否揭示、动作是否发生）——
`facts_declared` 只是 DM 的叙述证据，不作为判据（实施修正 2026-09-27：避免"DM 说采集到了"直接变成分数）。
另两条实施口径：
- **泄漏守卫豁免已揭示的事实**：学生已经看到的线索，DM 可以在按钮/文案里谈论它；
  未揭示的仍然不许提（`banned_terms(pack, world)`）。
- **图片**：`images` 只能引用 pack 声明的 `assets`（未声明即丢弃）；`image_request` 只在
  `image_generation="allowed"` 时成立。绘画者 AI 未接入时**诚实跳过**（记录 `image_generation_unavailable`，
  不生成占位假图）。
- **DM 可以临时拉人开口**（`lines` 里带 `as_role` 的未知 actor）：走廊里的护工、走廊广播、隔壁床、电话另一头
  这类**不在名册、只出现一次**的人有显示名与气泡（前端按 `avatar_seed` 派生头像），但不进在场者名册、
  不承载状态改动。**要有人说话就让他本人说，不要用旁白替人开口**——这是 DM"开口能力"的落地方式。

## 六、动作与呈现词汇表（**已定稿**）

> 定稿口径：**类型封闭、参数与文案开放**。实现即真相——`schema.py` 的枚举就是词汇表；
> 新增类型必须同时给出「可改状态键 / 证据形态 / 渲染原语 / 判读钩子」四项。

### 6.1 三层定义

| 层 | 谁定 | 自由度 | 例 |
|---|---|---|---|
| **类型**（动作类型 / 呈现原语） | 平台（代码） | **封闭** | `act`、`measure`、数值卡、按钮组 |
| **参数**（params / effects / 可见条件） | 包 | 开放 | "吸氧" vs "镇痛"；科室选项集；目标床号 |
| **文案**（label / narration / intent） | 包 | 开放 | 全部可见文字 |

### 6.2 判据：什么必须成为"类型"

> **当且仅当需要平台承担语义**——①能改状态、②能出证据、③能进判读、④需要新的渲染原语——才必须是类型。其余一律是参数。

| 需求 | 落在哪 |
|---|---|
| 吸氧 / 镇痛 / 安抚 / 分诊分区 | **参数**（都是 `act`，不同 label / effects / 选项集） |
| 血压 168/98、复测取值 | **参数**（`measure` 的值与单位） |
| 点击患者身体部位查体 | **类型**（需要图像热区原语） |
| 电话音频通话 | **类型**（需要音频原语） |
| 拖拽排优先级 | **类型**（需要排序原语） |

### 6.3 初版清单

**动作类型（6）**

| type | 平台侧语义 | 参数 | 渲染原语 | 产出证据 |
|---|---|---|---|---|
| `ask` | 向在场者发问 | 目标、意图、文案 | 文本输入 | 采集到的事实 |
| `observe` | 查看/注意 | 目标、cue 集 | 只读揭示条目 | 观察到的线索 |
| `measure` | 取数值 | 项、单位、范围 | 数值读数卡 | 测量值 |
| `act` | 施加动作 | 目标、选项集、effects | 按钮（单选/多选） | 动作与顺序 |
| `document` | 产出记录 | 字段模板 | 表单/自由文本 | 产物（理解证据） |
| `summon` | 呼叫/拉人 | 对象、条件 | 按钮 | 在场者变化 |

**呈现原语**：文本消息 · 只读条目 · 数值卡 · 按钮组 · 表单 · 在场者列表 · 时间线 · 曲线 · 覆盖地图 · HUD 槽位 · **图片（资源包内预定义 / 预留的绘画者 AI）**。（**无倒计时**：无时钟 ⇒ 不提供时间压力类原语。）

### 6.4 扩展流程（自由度留口）

类型**可以扩，但只由平台扩**：一次发版，此后所有包永久可用。新类型必须同时给出四项声明：**可改的状态键 / 证据形态 / 渲染原语 / 判读钩子**。差别就在这——接口的实现住在平台里，不在包里；包能发明类型，平台就无法保证"效果合法、可记录、可判读"。

### 6.5 用五个场景验证词汇表够不够

## 七、判读与展示

```text
抽取（LLM 擅长）       → 判定（规则，可复算）        → 投影（经历量化）
facts_declared + 证据   决策点 / 覆盖 / 顺序            时间线 / 情绪曲线 / 覆盖地图 / 趋势
```

**每场景自写 rubric（裁定 2026-09-27）**：判据不是通用方案——`pack.rubric` 由作者按这个场景的需要写
（判据用同一套封闭规则保证**可复算**，条目数/标题/权重各自不同），最终按**得分率**汇总：

```
rate = Σ(权重 × 锚点得分) / Σ权重     # 锚点得分默认 strong=1 / adequate=0.5 / missed=0（可按条目覆盖）
权重 = 1–100 的**正整数**             # 平台侧算、LLM 看不见；**不要求合计 100**——`20 20 80` 同样合法，按 Σw 归一化
```

- **加权部分 LLM 看不见也不处理**：权重与判据 id 都不进任何提示词（有守卫测试）；平台侧可复算。
- 作者口径建议：每包权重合计 100，教师与学生都能心算（如 `25 30 30 10 5`）。
- **"没做过"不等于"做得对"**：例如④的"不重复无效动作"在一次都没吸过痰时只算**合格**，不白拿满分。
- **展示分层**：学生侧看得分率 + 逐条 `title/锚点/detail/证据`，**看不到权重**；权重与加权和在管理侧可查。
- 这仍是**可解释的加权汇总**，不是能力等第，也不是把历史分数重新缩放（历史记录一字不动）。

- **事实分型**：`measured` 与 `reported` 分开——③"量出高血压但患者否认"这类矛盾正是判读对象，而不是把"未采集到高血压史"判成扣分。
- **决策点**：每题 2–4 个；锚点**三档**（strong / adequate / missed），容得下"正确的折中"（如⑤先快速确认 A 再直奔 B）。
- **不启用能力等第**：未校准不启用；本轨的等第若将来启用，必须有自己的校准证据，**不得借用老系统的判例或阈值**。
- **换算唯一（本轨内）**：情境训练有**自己的唯一换算点**，位于本轨代码内；**不调用老系统 `scoring/mapping.py`**，也**不与老记录混算**。包不含分数，热载动不到量尺。
- **经历量化是投影不是评分**：图形由派生的计数/斜率/时间线生成，**零 LLM、零新判读**；语气用"本次经历"，不用"能力评估"。

### 8.1 五题与结构轴

| # | 场景 | 结构轴 | 学生角色 | 判读核心 | 新增单元字段 |
|---|---|---|---|---|---|
| ① | 预检分诊·藏脾破裂 | 隐藏危重 + 分区 | 分诊护士 | 是否识破"腰闪了"假象 | 选项型 `act` |
| ② | 夜班医生·电话 | 远程 + 信息转述 | 值班医生 | 要哪些数据、下一步检查、干预 | `asymmetry`（无面板） |

| ④ | 吸痰无效 | 动作失败 + 升级 | 夜班护士 | 不重复无效动作、及时重新评估 | `failure: irreversible` |
| ⑤ | 两床同铃 | **注意力资源 + 优先级** | 夜班护士 | 先看谁、可等待的怎么管 | `attention_per_turn`、`demand`、多床呈现 |

**⑤ 两床同铃：会叫的能等，不叫的危重**（追加场景，补"多人竞争 + 注意力稀缺"轴）：

```python
player:  { role: "夜班护士", attention_per_turn: 1 }
actors:  [ A床(术后第1天, demand: loud, knowledge: {疼痛5分, 生命体征平稳, 家属助威}, goals: [被关注]),
           B床(慢阻肺,     demand: quiet, knowledge: {SpO2: 88%, 呼吸浅快, 意识开始模糊}) ]
setting: visible_cues: [A 床铃响、家属站走廊、B 床灯关着]
asymmetry: hidden_from_player: [B 床低氧]
reactions:
  when: 学生把回合花在 A 上    by: B床  effects: [{SpO2, ↓}, {意识, ↓}]
  when: 探视 B 并 measure      reveals: [SpO2 88%、呼吸浅快]
  when: 探视 A 且安抚到位      by: A床  effects: [{呼叫, ↓}]          # 可等待也可被正确管理
judgment.decision_points:
  优先级: { strong: "先快速确认 A 再直奔 B / 直接先 B",
            adequate: "先 A 但一个回合内转 B",
            missed: "在 A 床连续处理家属情绪，把 B 留在黑暗里" }
failure: irreversible              # 连续 2–3 回合未探视 B → 意识模糊
```

教学价值：打掉"谁喊得响谁先处理"这个真实存在的错误启发式。

### 8.2 试金石：每题必须落地的体验点（成效判据）

判据是**观感**——维护者或教师看一条真实会话即可判断，不是自动化分数。每题的关键体验若落地，说明该题背后的机制真的成立；一旦出现"失败观感"，说明模型退化成了清单或提示。

| # | 必须落地的体验 | 失败观感（一出现即未达标） |
|---|---|---|
| ① | 学生**差点**把危重患者放进门诊/骨科，某个动作（测体征、追问外伤与放射痛）让判断翻转——"我差点放错" | 患者开场就自曝腹痛与左肩痛；按钮把"测生命体征"高亮成唯一正解 |
| ② | **信息只能问到**：挑哪几项数据决定下一步；护士回报**新数据**后判断改变；全程看不到患者 | 一屏摆出全部数据；医嘱选项里隐含"正确答案" |
| ③ | 学生**自己**发现"他说没有、可这是 168/98"，并知道照清单式问法这条会被判成"没问到" | 追问一次患者就改口承认（矛盾消失）；界面替学生标注"体征与陈述不一致" |
| ④ | **同一动作第二次失灵**：学生感到"按老办法做，反而更糟"，进而重新评估并升级 | 第二次吸痰就见效（退化成普通操作题）；系统提示"请尝试其他方法" |
| ⑤ | **响的那个不是要命的那个**：学生在照顾 A 的过程中 B 静默恶化，回看时间线时"心里一惊" | B 床也会自己叫（"安静"的教学点消失）；系统提示"请注意 B 床" |

**推进梯子**（每加一题 = 只加一份包；新能力一次只引入一个）：④（效果/反应/不可逆）→ ③（事实分型）→ ①（选项型动作）→ ②（无面板/远程）→ ⑤（注意力资源/多床）。**五题齐且各自体验落地 = 初具成效。**

### 8.3 首片 ④ 的实测证据（2026-09-27）

真实 LLM、真实会话（本地开发库，`/api/scenario/**` 全链；三次独立会话，均成功）：

| 观测 | 结果 |
|---|---|
| 开门 → 测血氧/听诊 | 患者按人格说话；听诊揭示"左侧几乎听不到"，机制线索浮现 |
| **第一次吸痰** | 吸出少量血性黏痰，**症状无缓解**，患者"我是不是不行了"（`r_suction_first`） |
| **第二次吸痰** | **失灵且更糟**：血氧 86→83、患者转为近乎沉默；维护者在时间线看到"再次吸痰不仅无效"（`r_suction_repeat`） |
| 提示 | "同一措施两次无效时，值得停下来重新评估原因"（`nudges`，只给方向） |
| 呼叫医生 | 医生到场并给出具体指令（`r_doctor_arrives`），按钮随在场者变化 |
| 加压给氧 | 血氧回升（89），但 `lost=true`——重复无效动作已越过不可逆线 |
| 结算 | `2 strong / 1 adequate / 2 missed`：`dp_recognize=strong`、`dp_no_repeat=adequate`、`dp_escalate=missed`（第 5 回合才升级，窗口 3）、`dp_sequence=strong`、`dp_document=missed` |
| 经历量化 | `coverage=1.0`（2/2 必采事实）、`latency=5`、`slope=+1`、`count=6` |
| 热载与钉版本 | 三次会话分别钉 revision 1 / 2 / 3；改包只影响新会话（进行中的会话不变） |
| 自动化 | `ruff`/`ty` 全绿；`tests/scenario_training/**` **64 项**（含 API 级：关闸 404、假 LLM 全链、越权 404） |

**③ 的实测（正确路径：量 → 问 → 用第三方证据求证 → 记录）**

`dp_conflict / dp_no_dismiss / dp_trust / dp_document` **全部 strong**，`coverage=3/3`（测得值、患者否认、第三方证据），
`latency=3`。要点：老清单式评分会把"未采集到高血压史"判成扣分，而这里的正确行为（**识别并核实矛盾**）得到满分——
这正是 ③ 存在的理由。

**⑤ 的实测（错误路径：只响的那个先处理）**

学生连续 3 回合耗在 A 床（喊得响）→ **B 床静默恶化**：血氧 88→86→84，nudge 触发
"响的那个不一定是最危险的：安静的那床，你已经多久没看了？"；转向 B 床后处置让血氧回升。
结算：`dp_priority=adequate`（先 A 后 B）、`dp_recognize_b=strong`、**`dp_stabilize_b=missed`**（第 6 回合才处置，窗口 4）、
`dp_manage_a=strong`、`dp_document=missed`；`d_redirect=4` 回合。

**一处实测修正**：DM 习惯把效果操作写成 `add` / `-=` / `delta` 等自然写法，原枚举只接受 `set/incr/decr` →
每回合白花一次重试（多次会话复现）。已在 `Effect` 加别名归一（`delta` 按 `value` 符号定向），
修复后 `problems` 清空、单会话耗时 23s→15s。

**② 的一处内容修正（2026-09-27）**：「先留观复测、明早再说」原本留在"下医嘱"的多选项里，
于是下错医嘱也会拿到化验与超声结果（内容近似）。已拆成独立动作 `hold_observation`，
带自己的后果（护士沉默后报警变密、血压下降）——判 `missed`，且**关键检查从此不再出现**。

**① 的实测（错误路径：核了体征却仍分到骨科）**

学生测了生命体征、追问了受伤经过（`dp_see_hidden=strong`，coverage 2/3），却把病人分到骨科：
世界立刻回应——同事追出来问"这不是骨科的事吧？你刚才量的血压到底多少？"、抢救区医生电话进来问主诉与体征；
血压 92→82、意识下降到 `lost=true`。判读 `dp_zone=missed`、`dp_document=missed`。
**要点**：判读把"**是否核实体征**"与"**分到哪儿**"分开评——这正是老清单式评分混在一起的地方；
而"系统替学生发现"的失败观感没有出现：**是世界在反应，不是按钮在提示**。

**② 的实测（正确路径：多选下医嘱）**

`dp_gather / dp_next_test / dp_escalate / dp_plan` **全部 strong**，其中
`dp_next_test=strong — 选择「急查乳酸＋血常规、床旁超声」`（**多选被正确读出**），coverage 3/3、延迟 3 回合。
全程无病人画面（`presentation.hud` 不含状态槽）——远程决策的"看不见"由内容表达，不需要额外机制。

## 九、交互：情境按钮

```text
[ 按钮区 ] ← 每回合由 DM 的 options[] 提供（受 affordances 约束，随情境变化）
   询问诱因   追问放射痛   测生命体征   分诊分区   呼叫二线
[ 输入框 ] ← 自由通道保留
```

- 按钮 = **affordance 的可见形态**，不是清单 → 直接消灭"复制粘贴通关"。
- 时机由 DM 决定：卡住时给方向，顺利时少给甚至不给 → 脚手架自然递减；`nudges` 只给**方向**，不给条目。
- 按钮文案不得出现隐藏事实的同义条目（可自动检查，§十三）。
- **自输入恒在**（照 omp 提问工具的 "Other (type your own)" 同构）：选择型动作（`select: single|multi`）
  与 `document` 表单，除列出的选项外**由前端无条件附加"其他（自己输入）"入口**，内容作为 `custom_text`
  提交；**平台/DM 都不得自行提供该选项**（DM 提供即丢弃并记 `dm_supplied_free_input`）。
  判读侧：`accept_custom` 里的词若出现在学生自输入中，可被认领（每回合最多 +1，见 §七）。

### 9.1 招牌界面方向（跳出"聊天 + 表单"）

界面主次与老系统训练页**刻意不同**：**画面与动作是主角，聊天是配角**。

```
┌────────────── 场景画面区（hero）──────────────┬──── 经历时间线（常驻侧栏） ────┐
│  图片/资源 ｜ 地点·时间线索 ｜ 可见物          │  你的动作（第 1 回合…）        │
│  在场者条：谁在场 / 谁能被叫来（点一下=搭话）  │  世界的回应（反应线）          │
├───────────────────────────────────────────────┤                                │
│  读数 HUD（数值 slot，大字、高对比）            │  线索（已揭示 / 你注意到的）    │
├───────────────────────────────────────────────┴────────────────────────────────┤
│  **动作区**：一排"此刻能做的事"（大按钮）                                       │
│  自由通道：默认折叠成一行输入，展开即可自由发问                                  │
└───────────────────────────────────────────────────────────────────────────────┘
```

- 旁白（`role="scene"`）用字幕条叠在画面下方；角色台词按说话人区分；`origin="entity"` 标注"独立实体"。
- `session.lost` 不弹窗：画面转冷色 + 顶部一条"已达到不可逆结局"。
- 结算后同一页切换为**经历页**：时间线放大 + 决策点锚点 + 维度数值 + 证据引用。
- 图片：`assets` 缩略图条（点开大图）；`images` 占据画面主位并显示 `caption`。
  **加载必须走鉴权**（仓库既有 `components/ui/auth-image.tsx`：axios 取 blob → objectURL），不用裸 `<img src>`。

### 9.2 消息渲染矩阵（**必须逐类渲染**，裁定 2026-09-27）

> 「训练 UI 要确保合理渲染各类消息，布局合理信息展露适当。」——下表是验收清单，逐条成立才算 UI 可用。

| # | 后端会发出的东西 | 渲染要求 |
|---|---|---|
| 1 | `messages[].role="scene"` | 旁白字幕条（不与角色气泡混排） |
| 2 | `role="student"`（学生自己做过的事） | **右对齐**一行：自由表达用他的原话、点按钮/选项用 affordance 标签（`action.text or action.label(pack)`）；1px 边 + 底色分层，不加头像、不写「你」；同一回合排在世界回应之前。**提交瞬间**先按同一结构出"待定"气泡（只降不透明度、不加"发送中…"），权威 `view` 一到由正式消息接管（去重判据：同回合 + 同文案）；失败/409/422 撤下气泡并把自由表达的原话还回输入框 |
| 3 | `role="actor"`（声明角色） | 气泡 + `actor_role` 标签 + 派生头像 |
| 4 | `ephemeral=true`（临时角色） | 虚线头像 +「临时」徽章；**不进在场者条** |
| 5 | `origin="entity"`（独立实体） | 明确小标 |
| 6 | `images[]` | 主位图收成一条**紧凑图带**（有图才给）+ 作者写的 `caption`；生成来源（`origin`）不进学生面 |
| 7 | `visible_cues` / `noticed` | **分开展示**（已揭示 vs 你注意到的） |
| 8 | `hud[]` 四类 source | **只渲染 `state`**（仪器读数）；`cue`/`actor`/`affordance` 与白板/在场者/动作入口重复，不再重复渲染（一个 `state` 都没有就整块不出现） |
| 9 | `options` vs `affordances` | `options` = **气泡流末尾的提示 chip（≤3）**，随对话推进；`affordances` **不上界面**（没有能力清单）——学生靠自由表达行动 |
| 10 | `nudges[]` | 轻提示，只给方向 |
| 11 | `session.lost` | 冷色 + 顶部横幅，**不遮罩**、不阻断 |
| 12 | `timeline[]` | 按回合分组：动作行（正文色）+ 世界行（弱化色）；**不署名**（不写「X 的回应」）、不用色条/圆点 |
| 13 | `dims[]` | **顶栏**：一条细进度 + 数字（比例/次数两类，其余不展示）；全部读数与 `detail` 在点击展开的弹层里；`value===null` → 「—」 |
| 14 | **`problems[]`** | **学生侧不展示原始诊断串**（`dm_parse:*` 等）；DM 走保底时给**一句**中性说明（`本回合的世界回应出自既定情境。`）；原始串归管理侧 |
| 15 | `actors[].presence` | 三态给动作词（`on_site`搭话 / `remote`通话 / `callable`可呼叫）；`inaccessible` **不给提示词、不给按钮**（只灰着）——「不在视野」是平台在解释自己的投影规则 |
| 16 | 动作属性 | 自由输入是**主控件**；`confirm=true` 二次确认；`free_input=false` 不给输入行；`select` 单选/多选与 `document` 表单**只能由 DM 的提示 chip 带出**（需要参数的动作仍走表单） |
| 17 | 空态/加载/错误 | 空即不渲染（无面板、无图、无资源**都不留空壳**）；404（未开启）、409（已结束）只给最短事实 + 出口 |
| 18 | 长内容 | 不撑破布局；新消息自动滚到底，用户上翻时**不抢**滚动 |
| 19 | HUD 可见性 | 只显示 pack 声明过的 slot；不暴露内部字段名（如 `scene.spo2`） |
| 20 | `board`（线索板） | 只读、单行、分条；`count>1` 给 ×N；`evidence` 次行小字；`superseded` 划线+「已订正」；`more>0` 给「还有 N 条」；空版块不渲染 |
| 21 | `devices`（设备面） | 数值大字 + 单位 + 状态配色（**不闪烁**）+ 趋势箭头与克制折线；门控未满足则整台不出现 |
| 22 | 设备提示音 | `sound="beep"`：低频滴滴、节奏随状态、**默认静音**、可持久化开关、页面隐藏即停；**不做报警** |

  `prompt` / 归一后的字节；对外引用 `gen:<行 id>`。**不走文件系统**（不落盘 ⇒ 容器重建不丢、管理端可见、

- HUD 槽位名由 pack 声明（人话标签），前端只渲染投影，**不暴露内部字段名**（如 `scene.spo2`）。

### 9.4 白板与设备面：按需具现的两种面

**信息不该焊死在界面上**——「根据需求存在」落成两种固定区域，都是**只读投影**（学生只能通过"做事情"让它长出来）：

| 面 | 装什么 | 何时出现 | 谁写 |
|---|---|---|---|
| **线索板（白板）** | **已确立的事**：现场看到的 / 注意到的 / 已确认的（含原话证据）/ 已处置 / DM 的判断 | 版块与条目按门控逐个出现（`visible_when` / 事件） | 平台从事件流推导 + DM 的 `facts_declared` 与 `notes`（可 `supersedes` 订正，旧条目保留并标记被取代） |
| **设备面** | **实时读数**：监护仪的血氧、值班电话回报的乳酸…（数值/状态/趋势全由平台算） | 设备与**通道**都可按需求出现（B 床监护仪要你真去看了那床；化验回报要检查真下过） | 平台（不含 LLM） |

- **通则：同一读数优先由设备展示，白板自动让位**（`device_refs` 过滤），同一信息不出现两次。
- **白板必须简洁**：每条单行限长（线索 60 / 事实与笔记 40 字）、去重、重复动作合并计数（`某动作 ×3`）、
  自由发问不进板、每版块上限 20 条（超出给 `more`）。
- **设备面的声音**：`sound="beep"` 时是**低频提示音**（节奏随状态轻微变化），**不是报警**——
  默认静音、用户显式开启、标签页隐藏即停。
- HUD 保留"现场线索 / 可做动作"这类非读数槽；读数一律归设备。

### 9.5 开场与叙事（DM 真正当 DM）

- **开场回合**：会话一建立就由 DM 立场景（第 0 回合），学生进场先看到世界，而不是一间空房间。
- **叙事手艺**（写进 DM 提示词）：每回合至少推进一件事；1–2 处具体感官细节；**呼应前情**；
  处境两回合没动就由世界自己前进一步；用行动与台词推进，不点评学生、不出现"任务/关卡/提示"这类元话语。
- **老侧断开接线（裁定 2026-09-27）**：传统问诊界面**不再使用监护仪**——其"已测体征"汇总已下线，
  查体结果仍在 `ExamResultCard` 逐项展示（信息不丢），数据（`scene.vitals`）原样保留。

### 9.6 增量渲染：展示可以增量，状态仍等完整回合

DM 单次输出里有多个内容块（叙述 / 台词 / 图片 / 选项 / 笔记）。**块写完了就该先渲染**，
而不是等整段 JSON 结束——学生先看到旁白，再看到台词，最后按钮出现，接近真人说话的感觉。

- 接口：`POST /api/scenario/sessions/{id}/actions/stream`（SSE，`data: {...}` 逐行）；
  事件 `{"kind":"blocks","blocks":{…}}`（增量，只推**已经完整**的顶层字段）与
  `{"kind":"view","view":…}`（权威结果）。
- 实现：`dm/stream.py` 的转义感知扫描器只认"自身完整"的顶层值——**宁可等下一片，也不先渲染可能是错的数**
  （尾随裸数字一律视为未完成）。
- **纪律：展示增量，状态不增量**。效果、揭示、事件、判读全部只在**完整回合校验后**落地，
  绝不出现"半应用的世界"；流式中途失败自动退回非流式路径（行为与今天一致，不得更差）。
- 生产注意：SSE 必须带 `X-Accel-Buffering: no`（否则 nginx 会缓冲，前端失去增量效果）——已设置。

## 十、热载、版本与分发

- **热载**：包存在本轨自己的表里；`pack_schema_version` 管形状；**加载期校验**（坏包在加载时失败，不在会话中途炸）。
- **钉版本**：会话开启时把 `pack_revision` 冻进本轨的记录 → 热载只影响新会话，运行中会话永不受影响。
- **换算不随包变**：包不含分数（§七）。
- **多 worker**：默认包解析**读库**（按 revision 键缓存），不依赖进程内缓存。
- **回退**：把默认指回旧 revision，1 个操作；包可禁用。
- **草案分发**：`state = experimental` 可直接发给小范围/实验批次（本轨自己的分发机制）。
- **门禁降级为检查器**：本轨的包校验只**报风险、不阻断**——原型期需要允许犯错。
- **数据分组**：不同包版本按批次分开统计；坏的版本不污染好的。
- **入口形态**：`SCENARIO_TRAINING_ENABLED` 是**运行时开关（kill switch）**，生产由 `deploy/.env` 置 `true` 开启；关闭时整个命名空间 404，对老系统零可见。当前阶段是在**生产中接收测试**（学生侧栏可见入口），不再有"实验期"。
- **与老系统的关系**：因资源完全隔离，本特性**天然不进入** `usability-u0` 批次，无需额外批次约束。

## 十四、学生面 UI 与文案规范（2026-09-28 定稿）

这一节是**学生面**（`/scenario`，含管理侧回放复用的组件）的规范；改学生界面先读它。

### 14.1 只出现叙事内（diegetic）信息
世界里成立的话、别人的话、可做的动作——只有这些。**系统/作者/平台的解释、教学口吻、
免责声明、占位说明一律不出现**：不写「（看不到）」「（未测到）」「（占位）」「你可以点击…」。
系统状态用**视觉**表达而不是旁白解释：不在视野 = 没有按钮、灰着；没有图 = 没有图区；
被折叠 = 一个中性的数量控件。需要引导时用**最短的动作词**（作者侧：`nudges[].direction`
写「先要齐能改变判断的证据」，不写「值得停下来重新评估原因」）。

### 14.2 按需展示，不一次性列出一切可行性
DM 是主持人，界面只给他**此刻递上来的东西**：`options` ≤3 条，渲染为紧跟最新一条消息的
chip，随对话推进更新；`affordances` 是"理论上可做的事"，**完全不上界面**，学生靠自由表达
行动。默认屏幕上除了这条提示与输入框，不应有任何其它可点击动作。

### 14.3 同一事实只出现一处
线索/注意到的只在白板；在场者只在在场者条；量化只在顶栏细进度（细节在弹层）；
地点与时间只在图带那一行；资源只在那行小字。历史与复盘信息（时间线、逐条判读）
只在侧栏时间线页签与结算页出现，不常驻主界面。

### 14.4 视觉：与系统主题同一套刻度（不另立语言）
- 颜色**全部**取 Mantine CSS 变量（`--mantine-color-*` / `--mantine-primary-color-*` / `--mantine-color-{语义}-{text,light,light-color}`），
  亮/暗两套主题随 `data-mantine-color-scheme` 即时生效；`scenario.css` 内**不得出现硬编码 `#` 色值**。
- 半径：控件层 `--mantine-radius-sm`(4px)、容器/卡片层 `--mantine-radius-md`(8px)（= `theme.radius.{control,container}`）；唯一圆形是头像。
- 字号：`xs`12（元信息/状态词）、`sm`13（次级正文）、`md`15（台词/读数正文）、`lg`17（结算页标题/总分）。
- 间距：容器内边距用 `--mantine-spacing-sm|md`(12/16)；2/4/6/8 这类小于 10px 的步进主题刻度里没有，
  仅在行内微调时按字面量使用（Mantine 组件自身同样如此）。
- 不用渐变、发光、玻璃质感（`backdrop-filter`）、字距与全大写；阴影只给弹层（`--mantine-shadow-xs`）。
  唯一例外：压在场景大图上的那条细遮罩必须恒为黑色（图像覆盖层，见 `scenario.css` 文件头注释）。
- 数值一律等宽 + `tabular-nums`，且不超过正文字号；语义色（正常/注意/危急）只用于状态本身，不整块染色。

### 14.5 无障碍
`focus-visible` 环（品牌色）覆盖全部可点元素；触屏（`pointer: coarse`）控件高度抬到 44px；
`prefers-reduced-motion` 下所有动画关闭；自建页签是标准 `tablist/tab/tabpanel` + 左右方向键。

### 14.6 沉浸壳与出口
`/scenario` 跑在 `PracticeShell`（无系统顶栏/侧栏），因此控制台自带一条最简顶栏：
返回（→ `/training`）+ 病例名 + 回合/进度 + 会话动作；会话视图 `height: 100dvh`，
**页面级不滚动**，滚动只发生在对话流与侧栏内部。
