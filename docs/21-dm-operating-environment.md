# 21 — DM 运行环境：把 DM 当成一个有工具的 agent

> 状态：**设计**（2026-09-28）。**尚未实施**。与 [20](20-situational-training-design.md) 配套：20 定义场景单元与交互契约，本文定义 **DM 的内部操作环境**。
> 核心判断：**学生面对的不是一张动词表，而是"这个世界"**。让这个世界活起来的关键，是给 DM 一个**类 agent 的运行环境**——可观察的状态、可调用的工具、可维护的任务、可开子代理；锚点只是它的任务列表，不是机制本体。

## 一、问题：现在的 DM 是"一次性输出器"，不是"在环境里做事的人"

现状：DM 每回合收到一段拼好的 prompt，吐**一次**结构化 JSON（叙述 + 台词 + 效果 + 选项 + 图片 + 笔记），平台校验后应用。这带来三个后果：

1. **它不能"先看再做"**：无法查询"患者此刻知道什么/已揭示过什么/哪些检查做过"，只能靠 prompt 里塞进去的摘要；
2. **它不能"分头做事"**：多角色场景里所有台词都出自同一次调用，角色之间没有各自的立场与记忆；
3. **它的"任务"只存在于 prompt 里**：没有可校验、可拒绝、可回放的任务状态（参见 21 旧版的锚点设计，现降为其中一个工具）。

## 二、环境由四层组成

| 层 | 内容 | 谁拥有 |
|---|---|---|
| **世界状态** | 事实键/可见物/位置/时间线索、设备读数、已揭示线索、已应用效果、事件流 | 平台（确定性、可重放，20 §五） |
| **在场者** | 每个 actor 的**私有知识**（知道什么/不知道什么/会隐瞒什么）、情绪、意图 | pack 声明 + 会话内事件 |
| **任务** | 叙事锚点（阶段化的关键节点） | pack 声明；状态**重算**自事件流 |
| **工具箱** | 见 §三 | 平台提供，pack 只能声明用法不能新增实现 |

**不变量（20 §六的硬规则继续成立）**：效果只能作用于**已登记的状态键**；`pending` 锚点的线索**不得提前出现**；冲突以 pack 为准；DM 的输出**不能直接写状态**，只能通过工具。

## 三、DM 的工具箱（每回合可调用的一批操作，引擎逐条校验）

**观察类（只读，廉价）**
- `world.state()`：当前可见事实键、设备读数、时间线索；
- `actor.knowledge(who)`：某人在 pack 声明里**知道**什么、**已被告知**什么（由事件流计算，不是模型记忆）；
- `history.lastN(n)`：最近 N 回合发生了什么（学生做过什么、世界怎么变）。

**作用类（写世界，全部经校验 + 落事件）**
- `actor.say(who, text, tone?)`：让某人说话（多角色各自独立）；
- `world.effect(key, op, value)`：改状态（**只能用在已登记键上**，越权即拒绝）；
- `world.reveal(cue_id)`：把某条线索变成可见；
- `scene.set(place|time|hud)`：调整场景呈现（受 pack 声明约束）；
- `image.request(spec)`：请求一张图（既有能力，走绘画者）。
- `options.offer([...])`：给学生的提示（≤3，且**不得**泄露 `pending` 锚点线索）。

**任务类（= 旧版的锚点机制，作为工具存在）**
- `anchor.list()` / `anchor.start(id)` / `anchor.done(id)` / `anchor.block(id, reason)`：维护叙事推进；引擎**只采纳与重算一致的状态变更**，不一致就拒绝 + 下回合纠偏。

**自语类**
- `note.write(text)`：DM 的草稿纸（落事件、教师回放可见、学生不可见）——用来在长会话里维持"它在想什么"。

**子代理（本轮明确不做：暂缓）**
- 曾预留 `patient.spawn(persona)`：独立 LLM 上下文的"专用患者实体"。**本批不做**，且不允许后续实现依赖它。
- 现状核实（2026-09-28）：**没有任何 pack 声明 `entity="dedicated"`**，因此 `dm/entity.py`、`st_patient` profile 与 `contract.py` 里的 `delegate` 校验是**从未被使用的预留路径**——**冻结**（不加功能、不作依赖；若将来确有病例需要"每角色独立上下文"，另开一份带成本评估的方案）。
- **替代机制（本批采用）**：角色一致性靠两件更便宜的东西——① 平台算出的**知识地图**（`actor.knowledge`：谁在 pack 里声明知道什么、已被谁告知什么，全部由事件流推导）；② DM 的**草稿纸**（`note.write`：它自己记"患者说过什么、我承诺过什么"）。同一轮里它照样让多个角色开口（既有契约不变）。

## 四、每回合的循环形态（多步为默认，单步为降级）

> **实施状态（2026-09-28）：已落地**。提示词已是 agent 形态；受限多步循环默认开启（`SCENARIO_DM_MAX_STEPS`，默认 3，0=单步）；
> 动作归属（§4.1）与反应补求值已实现；`dm_step` 落事件并进 `/api/diagnose`。
> 实测残差：① 模型**可能选择不读工具**（这是它的判断，不是 bug，步数是成本旋钮）；② 流式路径的 `dm_step` 落库早于 `unit_of_work`，回合中断时只影响统计；
> ③ `fired`/`state_history` 尚未带回合标记（世界侧变化目前由下一回合的场景叙述与状态块体现）。

前提：DM 是**与我同级的 agent**（现代 LLM + 工具）。因此**先看后做是默认形态**，不是可选特性：

- **默认：受限多步循环**（上限 3–5 步）。典型一步是"读一下 `actor.knowledge` / `history.lastN` → 再决定说什么、做什么"。每步的工具调用都落事件；超预算即中止并以**保底输出**收尾（学生面给一句中性说明）。
- **降级：单次批量调用**（低成本模式）。延迟/成本敏感或模型不稳时使用：一次输出 = 一批工具调用 + 最终可见产出。引擎同样逐条校验；任何一条失败按"整条丢弃 + 隐藏提醒"处理（`todo` 口径）。
- 形态由**运行时**决定并可切换（按模型能力/预算），两种形态对**学生侧完全一致**；步数/调用数/耗时进 `/api/diagnose` 的 scenario 分区。
- **最终可见产出是"信封"，不是思考方式**：提示词按"角色 + 环境 + 工具 + 不变量"写；结构化输出（叙述/台词/效果/选项/图片）只是交付形状。

### 4.1 动作归属：DM 自己把学生意图映射到已声明动作
自由表达成为主动作路径后，学生用文字行动**不带 `affordance_id`**（引擎只认 `payload.affordance_id`），直接后果：判读的 `ACTION_USED` 系列子句漏记目标动作、白板「已处置」不收、`dims` 处置数偏低。
- **正解（本批做）**：在 DM 的结构化输出里加 **`interpretation.affordance_id`**——它读得懂学生那句话（"给病人吸痰"），把意图映射到 pack 已声明的 affordance；平台在写 `ActionRecord` 时回填该字段，判读/白板/维度全部无需改动。
- **约束**：只能映射到**该回合已解锁**的 affordance（`unlocks`/门控之外一律拒绝，避免"说出关键词就得分"）；映射不出就**留空**，不编造归属（宁缺毋假）。
- **第二道保险（可选、纯确定性）**：请求边缘用 affordance label/别名对自由文本做精确匹配→命中才回填。**它只作兜底**，不作为正解，更不能为了它把动词菜单加回界面。

## 五、投影：谁能看到什么

| 面向 | 可见 |
|---|---|
| 学生 | 只有**世界的呈现**：叙述、台词、设备读数、可做动作与 DM 的提示。**不看**工具调用、锚点、note、被拒绝的操作 |
| 教师/管理员（回放） | 每次工具调用的输入输出、锚点面板、DM 的 note、被拒绝的调用与纠偏提醒——"与 `todo` 面板对操作者可见、对用户不可见"同一分工 |
| 判读/报告 | 用**过程证据**判读：哪些锚点自主达成、哪些被催办、患者是否被安抚、是否走了不可逆的错路 |

## 六、实施边界

- **不新增第二套工作流、不接 `clinical_reasoning`/`simulations`、不动老系统**；
- 工具箱**由平台实现**（pack 只能声明与使用）；新工具必须同时给出「可改状态键 / 证据形态 / 渲染原语 / 判读钩子」四项（20 §六）；
- 状态仍**不新增真源**：锚点/知识/note 都是"事件流 × 声明"的函数；将来重放成本成问题再做**检查点物化**；
- 迁移路径：先落地"批量工具调用 + 校验/拒绝/纠偏"（与现有单次结构化输出兼容，改的是**契约形状**不是架构），再视需要开多步循环与 `patient.spawn`。

## 七、验收（实施时的门）

1. **契约**：一次输出 = 一批工具调用；非法工具/越权键/未登记键一律拒绝且不写状态（守卫测试）。
2. **防泄漏**：`options.offer` 与 `actor.say` 均不得包含 `pending` 锚点的 `cue`（守卫测试，不看输出像不像）。
3. **知识隔离**：`actor.knowledge` 返回的是事件流算出的知识；构造"患者被问到自己不知道的事"用例，断言它不编造（或按 persona 明确表达不知道）。
4. **纠偏**：伪造一个与重算不一致的 `anchor.done`，断言被拒绝 + 下回合注入纠偏 + 留下事件。
5. **动作归属（4.1）**：① 学生自由表达"给病人吸痰"→ 记录的动作带 `affordance_id=suction`；② 映射到**未解锁**的 affordance 一律拒绝；③ 映射不出时留空（不得编造），且判读按"未出现"处理；④ 兜底匹配器命中与 DM 归属冲突时**以 DM 为准**。
6. **回放**：一条真实会话从开场到结算，回放能逐条复现工具调用与状态变化；`/api/diagnose` 显示步数/调用数。
7. **不回归**：`tests/scenario_training/**` 全绿；20 §六 硬规则成立。

## 八、明确不做

- 不做面向学生的工具/清单可视化（学生只看到世界）；
- 不做"自动替学生推进"；
- 不把工具调用变成第二次评分体系；
- **不在本轮实施**：先完成 20 的界面重做与线上收口，再开这一批。
