# 22 — 下一阶段优化规划（对齐大版本目标）

> 状态：**规划**（2026-09-28）。对齐根 README 的**大版本目标**：*我们是训练上下文的发布与管理平台：为用户带来一次体验，并记录该次体验。*
> 三条腿：**一次体验**（在场 / 时间 / 对话）· **记录该次体验** · **发布与管理**。
> 现状：情境训练（[20](20-situational-training-design.md)、[21](21-dm-operating-environment.md)）已在生产；老问诊轨的 U0 计划见 [19](19-training-experience-next-generation-plan.md)。
> **本文只排"完善完整体验"的活，并显式列出"不做"。**

## 一、缺口盘点（按三条腿）

| 腿 | 目标 | 老问诊轨 | 情境轨 | 判定 |
|---|---|---|---|---|
| **一次体验 · 在场** | 患者在场感 | 立绘 + 说话光环 + 呼吸节奏 ✓ | 舞台 + 在场者 + 设备面 ✓ | 情境轨**缺语音在场**（见 §二.1） |
| **一次体验 · 时间** | 会变的情境 | 情绪状态 + 场景播种 ✓ | **动作驱动的世界（事件溯源）✓✓** | 已成立（回合=序号、不碰墙钟 ✓ 见 [20](20-situational-training-design.md)） |
| **一次体验 · 对话** | 双工语音 | 流式 TTS 分块 + `abort` ✓，双工对谈已在代码中 ✓ | **无**（只有一句提示音） | 情境轨**完全没接**（见 §二.2） |
| **记录该次体验** | 可导出的体验记录 | 导出面已存在（时间线+情感+判读证据+gaps）✓ | 只有站内「报告」，**无导出** ✗ | 情境轨**差导出面**（见 §二.3） |
| **发布与管理** | 声明式上下文 + 变体 + 分组，版本化下发 | `CaseRevision` + 指纹 + 批次 + 问卷 ✓ | pack/修订 + 病例工作区 ✓，**无编辑器 ✗ 无变式 ✗** | 见 §二.4 / §二.5 |

## 二、要做的（按优先级；每条都给验收）

### P0-1　情境轨接通语音（补齐"在场/对话"）
复用既有语音基础设施（流式 TTS 分块 + `abort` + 失败降级显式呈现），让 `lines[]` 按角色朗读；
顶栏保留既有「提示音/静音」开关，扩成「语音：关 / 患者 / 全部」。**不做**双工拾音（那是 P2）。
- 验收：真机听到患者台词；打断（`abort`）生效；失败时界面显式降级且不阻塞文本；静音偏好持久化。

### P0-2　情境轨的「体验记录」导出（补齐"记录"）
一次会话导出**一份文件**（Markdown + JSON 双份，或单选其一）：时间线（回合 / 学生动作 / 世界变化 / 揭示的线索）+
对话全文（含学生原话与临时角色）+ 体征与设备读数序列 + 判读逐项证据 + **锚点轨迹**（自主达成 / 被催办后达成 / 受阻与被拒提案）+ 缺口清单（缺什么证据、哪些锚点未达成）。
管理端给「导出」按钮；学生侧给「下载我的经历」（可选）。
- 验收：一条真实会话导出后**逐项可核对**（回合数、读数序列、锚点轨迹与面板一致）；无原始诊断串泄漏到导出文件；文件在无网络时也可读。

### P0-3　作者面（编辑器 + 人类格式 + 机制修剪）
1. ✅ **编辑器**（病例工作区内的「编辑」）：从**最新修订**载入（可切指定修订）；表单 + 「JSON 原始」双页签双向同步（解析失败保留文本并给可读错误、不覆盖表单）；**只暴露必须由人决定的少数必填**（标题/一句话/玩家角色/场景/在场者/动作/线索与事实/判读/锚点/呈现），列表字段可增删排序，其余字段按原值保留并折叠；保存先过**同一套加载期校验**、失败按字段路径定位到节，成功显示"将追加修订 #N，改动字段：…"后确认——**永不原地修改**（保存一律追加新修订）。
2. ⏸ **人类源格式改 TOML**：**暂停**（用户另行决策，本批不动）。`packs/` 仍是 JSON，loader 只读 JSON，编辑器原始页签也按 JSON 走。
3. ⏳ **机制修剪**（一个概念一个机制）：删 `deadline_turns`（催办改用**既有条件词汇**并由引擎给默认值）；`requires`/`blocked_by` 只留一个；`ad_hoc_cues` 与 `reveals` 合并；`facts_declared` 与 `notes` 边界写清或合并。
4. ⏳ 提示词的形状约束**从 pydantic 模型生成**（取代散文白名单）。
- 验收：编辑器保存必追加新修订且先过校验（`test_scenario_admin_api.py` + `ScenarioEditor.test.tsx`）；修剪后全量测试与真实一局不回归。

### P0-4　治理两项（"转正式"的合规面）
管理端写操作（上传包/传图/删生成物/改状态/编辑器保存）落**审计留痕**；特性关闭时 `/openapi.json` 不再列举情境路由。
- 验收：一次上传/删除各留一条可查记录；关闭开关后 openapi 无 `/api/scenario` 路径。

### P1-1　完成率：先诊断，再决定是否加"收束"
现状：生产 10 局 / 28 回合、**完成率 0**（都停在 0–2 个动作）。
先做**回放诊断**（逐回合走向：学生在哪一步停下、是否缺一个"可以结束了"的信号、是否是入口/开口引导问题）；
若确认缺收束，再用**锚点**表达（全部 satisfied 后由 DM 在叙事内给出收束暗示），**不新增机制**。
- 验收：诊断报告（含每局停点与假设）；若实施收束，则以"下一批真实会话的完成率"为准，不以自评。

### P1-2　变式（同病例的另一情境）
大版本目标里"发布与管理"明确含**变体**：同一教学目标的第二个情境（换患者/换班次/换阻力），可标记为"练习/迁移"配对。
最小实现：pack 之间声明 pair（`variant_of` + `purpose: practice|transfer`），入口与报告标注配对关系；**不新增运行时机制**。
- 验收：同一病例的两个变式在入口成对出现、报告里能对照"同类线索是否被识别"。

### P2-1　双工语音（对话腿的终点）
在情境轨上接持续拾音 + 端点检测 + 打断（复用老轨已实现的链路）。**排在 P0/P1 全部落地之后**。

### P2-2　绘画者 AI 接通
pack 目前 `image_generation: disabled`；接通需同时定：生成时机、成本上限、生成物入库与病例内管理（后者已就绪）。
**排在语音之后**（画面不如声音对"在场"重要）。

## 三、明确不做（防止复杂度回潮）

1. **不再新增编排机制**，直到 P0 全部落地且真实会话完成率有起色；
2. **不引入墙钟时间**（不按秒压人、不破坏回放确定性）；
3. **不把作者面复杂度转嫁给运行时**（编辑器负责隐藏可选字段，而不是砍掉运行时能力）；
4. **不为异构而异构**：不引入第二套组件库 / 样式栈 / 评分体系；
5. **不做平台化**（无插件目录、无多租户、无通用工作流引擎）——见 [16](16-v2-maintainable-monolith-objectives.md)。
