# 23 — 情境机制重设计：让 DM 演出一个诚实响应的世界

> 状态：**已实施（2026-09-29）；生产切换与运维见 [docs/ops/scenario-training.md](ops/scenario-training.md)**。设计正文不变；机制已按本文实现并切换，不声明教学创新已被证明。
> 定位：情境模块是开拓系统新方向的实验；常规测试与研究仍由老问诊轨承载。`experimental` 是正常状态，不是本轮需要消除的问题。
> 权限与范围：允许重写情境模块有关实现，但不改老问诊轨业务、既有研究数据及部署拓扑。
> 优先级：本文覆盖 [20](20-situational-training-design.md)、[21](21-dm-operating-environment.md) 中冲突的机制规定，以及 [22](22-next-phase-plan.md) 的情境轨实施顺序。旧文保留为历史依据；本轮实现以本文为唯一入口。

## 1. 要证明什么，不要建设什么

**目标：用更少的机制，让学生的选择引起合理、可观察、可回看的不同后果。**

本轮要验证三个产品假设，而非宣称已经成立：

1. **行动性**：自由表达不是聊天装饰；相同意图经自由输入或结构化入口提交，得到相同的世界结算。
2. **情境性**：学生面对的不是隐藏任务清单；多个问题可以并存，合理路线不必只有一条。
3. **教学性**：DM 能呈现问题与后果、给适量机会和反馈，但不替学生识别风险、完成操作、拼出标准答案。

不以教师判例校准、课程成绩、审批发布、多租户或能力等级作为前置条件。本轮也不扩展双工语音、生成图能力、任意回合分叉、独立患者 agent、通用工作流引擎。现有非冲突能力保留；不因重设计移除已用的图片资源、文书、设备、自由表达或历史查看。

**工程可靠性仍要做，但只围绕实验有效性：**不能把世界状态漂移、泄题、错误归属、重复执行和网络故障误当成学生的选择与后果。

## 3. 四个职责，只有一个世界真源

| 所有者 | 负责 | 不负责 |
|---|---|---|
| 场景包 | 固定事实、人物立场、可执行行为、行动约束、确定性后果、教学关注点、呈现声明 | 脚本语言、任意工具定义、标准答案流程图 |
| 引擎 | 接受／拒绝动作，应用效果，触发反应，记录事实与来源，决定可见性，重建世界 | 编写人物台词、替学生作临床判断 |
| DM（同一个角色，不拆子代理） | 理解自由表达；在约束内决定人物反应和演出方式；把已经结算的处境自然呈现 | 自判锚点完成、直接写临床数值、用旁白替学生做操作、写入评分结论 |
| 前端 | 对象与输入、已确认的世界变化、消息、设备、回看 | 推断动作归属、重做触发求值、把未确认的生成草稿当事实 |

真源仍为 **不可变 pack 修订＋已提交事件**。World、角色知识视图、白板、教学关注点和报告是投影，不建立第二份可独立修改的真相。

### 3.1 世界的三类信息

- **事实**：pack 固定事实、测量／动作／反应产生的事实。必须有来源，能够被引擎引用。
- **言论**：角色说过什么、学生说过什么。说“已通知医生”不自动等于通知成功；患者自述不自动变成已测量数值。
- **表现与推断**：语气、表情、环境细节、基于证据的旁白。不能因被 DM 写出就升级成病情、设备读数、动作成功或判读依据。

保留这三层边界，不采用 22 中直接合并 `ad_hoc_cues` 与 `reveals` 的方案：声明线索揭示与即兴细节具有不同的可信权限。对外呈现可以统一为消息，对内来源不能混同。

## 4. 唯一回合管线：解析 → 结算 → 演出 → 提交

### 4.1 固定执行顺序

1. **接收请求**：校验会话、修订、对象、请求身份及基线事件序号；读取已提交 World。
2. **解析意图**：自由输入由一次短结构化模型调用生成 `IntentResolution`；结构化动作直接由平台构造同一对象。此阶段不向学生展示模型生成内容，也不写世界。
3. **确定性结算**：引擎校验解析结果，在暂存 World 上执行动作自身效果、线索揭示和反应，得到 `ResolvedTurn`。
4. **演出**：同一 DM 角色根据结算结果和允许可见的信息，生成 `SceneDelivery`。此阶段没有状态写权限，也不再申请工具或重新解释动作。
5. **校验交付**：检查引用、角色知识边界、可见事实、结构与内容约束；不能通过的内容不得进入学生流。
6. **原子提交**：复核基线序号，把动作、结算差量与交付一次性追加为本回合事件；提交成功后才发送权威视图。

**有意选择的代价：**自由表达通常两次短调用，显式动作与开场通常一次演出调用。两次调用不是两个 agent；共享同一套角色与世界契约，但输入权限不同。相比“一次生成动作解释、状态变化和完整旁白，再事后丢弃非法部分”，固定边界更容易保证语义一致。删除任意读工具循环并不等于所有路径强制一次调用；调用数、总延迟与体验必须一起实测。

演出调用失败不允许倒过来修改结算来迁就文案；意图解析失败也不允许把一局伪装成正常推进。

### 4.2 意图解析契约

下列是目标契约，不是现行 API。实现用同一组后端模型生成 JSON schema 与前端类型，禁止另写一份散文枚举规范。

`IntentResolution` 最小字段：

| 字段 | 含义 |
|---|---|
| `kind` | `speech`／`action`／`clarification`；分别为说话、尝试执行、需要澄清 |
| `target` | 已声明 actor／device／scene 的类型化引用，允许无目标；不靠最近聊天对象暗中补全临床动作对象 |
| `affordance_id` | 可归属的声明动作，或 `null`；平台仍需校验当下可用性 |
| `selection` | 已声明表单／选择参数；非法值拒绝，不静默凑成一次有效处置 |
| `utterance` | 学生原话引用，不是模型替写的“学生实际说了……” |
| `clarification` | 只在需要澄清时提供简短问题，不含答案提示 |
| `social_updates` | 可选的有限人物状态提案，见 §5；不能混入临床状态 |

规则：

- 学生已经明确选定动作、对象与参数时，DM 不得改写。按钮与自由输入只在解析入口不同，后续路径完全相同。
- “准备做”“是不是应该做”“如果做会怎样”不能当成已执行。`say` 不能被偷偷解释成学生已完成物理处置；呼叫、询问等言语行为可以归属声明的言语动作，但不自动意味着对方已执行医嘱。
- 多对象歧义先澄清。学生一次列出多个相互依赖的操作，不一次性全部算完成：本轮要求选定首先尝试的动作，后续继续输入。普通复合台词不拆成许多计时动作。
- 没有建模的行为记为未建模尝试，明确反馈当前不能模拟其临床后果；不要等同于临床错误，也不要“找个最接近的动作”给它记成功。
- 澄清不消耗情境回合、不触发恶化；实际尝试（包括被世界阻止）与正常交流消耗一个情境回合。请求次数、显示消息序号和情境回合数不是同一个计数。
- 判读与教学关注点只引用已结算的行为，不读取模型的归属提案或被拒提案。

### 4.3 确定性结算与反应链

`ResolvedTurn` 至少包含：请求身份、基线序号、实际动作与执行结果、效果旧值／新值、揭示线索、触发反应、已发生的可见事件、结算后的学生事实视图、角色可知信息、教学关注点。每项效果和可见事件带源动作／反应与回合引用。

执行结果区分 `performed`、`blocked`、`unmodeled`；澄清不进入世界动作结算。`blocked` 要记录处境原因，不能只返回“非法输入”。

反应处理采用一个确定性算法，不保留“先求一遍，动作认领后再补一遍”：

1. 先应用被接受的动作效果与揭示。
2. 找到条件相对本回合基线由假变真的反应，按包声明顺序执行；每轮求值使用上一轮效果应用后的世界。
3. 继续求值由已发生效果激活的新反应，直到没有新反应；同一反应每个情境回合最多执行一次，因此上界是本包反应数。
4. `once=true` 继续保持会话内只触发一次；`once=false` 需要后续回合条件重新形成边沿，不能因为条件一直为真就每轮无限重复。
5. 初始就成立的反应在开场结算一次，开场基线按“尚未评估”处理；空触发条件禁止保存，不能同时被文档解释成恒真、代码解释成恒假。

反应不得再隐式触发一个学生动作。并行风险按条件共存，声明顺序只裁定同一结算批次的执行次序，不是教学路线。

### 4.4 演出输入与输出

演出输入不复制完整隐藏真相与所有未揭示线索。提供：角色风格与立场、各角色允许知道的信息、学生原话、本回合已经发生的可见事件、必要的可见状态、近期转录、相关教学关注点。解析阶段可以读取动作约束与隐藏的引擎依据；演出阶段无须再次获得这些隐藏内容。

`SceneDelivery` 只含：

- 有序的 `messages`（环境叙述／角色台词；每条有来源事件或角色引用）；
- 可选的方向性提示与已声明资源引用；
- 本回合应突出显示的**已可见**变化引用。

它不含 `effects`、`reveals`、`interpretation`、`anchor_*`、`facts_declared`、自由白板笔记或委派字段。设备数值和白板事实由引擎直接投影，不让 DM 重写一份。

临时角色可以有显示名和一次性台词，但没有持久状态写权限，也不能成为隐藏事实、检查结果或行动成功的新来源。图像若保留生成能力，只作非权威辅助呈现，不承担临床结算；本轮不扩展该能力。

结构校验不能证明自然语言绝不撒谎。通过缩小演出输入、关键数值使用引擎组件呈现、现有防泄漏检查与真实对抗回合降低风险；不得把“有证据 ID”误称为已经解决语义幻觉。

### 4.5 失败、提交与流式展示

- 解析／交付结构失败最多各纠正一次，错误反馈限定于该阶段；共享预算耗尽或供应商故障则返回明确失败。不能重试已提交的世界动作。
- 默认失败不推进回合、不提交半个世界、不生成“情境继续”假回合。输入保留，可重试。
- DB 事务只包提交，不跨越模型等待。提交时锁定会话并复核 `expected_seq`；并发已有推进返回冲突并刷新，不用过期 World 继续提交。
- `request_id` 在会话内唯一。相同 ID 与相同输入重发返回已提交结果；相同 ID 不同输入拒绝。唯一约束与检查位于数据库提交边界，不只靠前端 busy。
- 模型调用日志可独立记录失败，但未完成的模型步骤不是世界事件。取消发生在提交前则丢弃暂存；提交后丢失响应则通过同一请求身份取回结果。
- SSE 与普通 JSON 调用同一回合执行器。SSE 仅发送 `phase`、已校验且标明待提交的 `delivery`、提交后的 `committed` 或结构化 `error`；不推模型原始 effects、notes 或半截 JSON。
- 第一版学生 UI 在提交前只显示阶段状态和待发送学生消息，不展示待提交的世界后果。接受暂时减少逐字流式的代价；不要用虚假的快速响应换事实撤回。后续若恢复增量演出，必须证明被展示内容已通过相同安全边界。
- 断流先查请求结果再决定重发；未提交的输入不得消失。客户端按稳定消息 ID 接续，不按文案或猜测回合去重。

## 5. 不把 DM 降成念稿机，也不让它随意改病情

### 5.1 保留的自由

DM 可以决定谁先说话、台词长短、沉默、犹豫、解释方式、合理的非临床环境细节，以及本回合重点演出哪个**已经有依据**的后果。不同合理措辞无需被代码枚举。

人物关系确实需要跨回合影响时，包可声明少量 `dm_writable` 人物状态键：初值仍来自 `state_keys`，附类型、范围、允许的单次变化上限和语义说明。解析阶段只提议这些键，平台在结算前验证；演出阶段只读取结算结果。

- 默认没有 DM 可写状态。只迁移现有场景确实使用的信任、舒适、配合等人物变量，不造全局人格系统。
- 同一键不能既由本回合动作／反应修改，又由 DM 重复修改；冲突以确定性规则为准，拒绝模型提案并记录。
- 社会状态变化必须引用当前交流依据；“同意配合”不是“已经完成操作”。
- 临床数值、测量结果、风险结局、设备状态与学生动作完成状态永远不在此写集。
- 若某个人物变化需要确定的医学含义，改成场景声明的效果／反应，而不是放宽 DM 权限。

### 5.2 删除自语作为长期记忆

删除 `note.write` 与提示词回注的自由草稿纸。长期上下文由平台装配：当前状态、已揭示事实、已执行动作摘要、持久人物状态和最近完整回合。近期窗口按完整回合截取，不截成只剩台词的零散行。

不承诺无限长会话记忆。首次实施不另建 LLM 摘要服务；确有不可由现有事件重建的持久承诺，再用具体场景提出有来源、可核验的字段，不恢复任意便条真源。

## 6. 教学关注点取代锚点任务机

删除 `NarrativeAnchor` 的 `pending/active/satisfied/blocked/abandoned` 状态机、唯一 active、阶段排序、`unlocks`、`deadline_turns`、三级自动催办和模型完成提案。

保留教学意图，但用轻量的 **`teaching_focus` 列表** 表达，每项只有：

| 字段 | 用途 |
|---|---|
| `id`、`intent` | 作者希望学生遇到的判断问题；仅作者与 DM 可见 |
| `relevant_when` | 当前处境下是否值得关注；复用现有 Trigger，省略表示始终相关 |
| `addressed_when` | 已有事实／已执行动作是否提供了处理证据；复用同一条件词汇 |
| `evidence_refs` | 该关注点可引用的声明事实／动作／反应；用于回看定位，不是学生提示清单 |

一个关注点没有“推进权”，也不解锁世界。多个相关但未处理的关注点可以同时存在。投影仅给出相关与已处理的布尔值及证据，不另立状态存储。字段 `addressed_when` 只表示本包观察条件成立，不等于学生能力达标。

- 动作可用性只由 affordance 自身条件决定；不能因为“教学还没轮到”阻止现实中可执行的动作。
- 病情变化、呼叫打断、忽略后恶化，全部用已有 reactions 表达；不用教学关注点的计时再做一次。
- 回合阈值只是模拟推进近似，不代表临床分钟，不引入墙钟压力。
- 世界真实会出现的线索不能被“尚未 active”压住；隐藏事实仍需实际获取条件，取消锚点顺序不等于提前泄题。
- 学生主动求助时允许方向提示，但提示事件要与自主行动区分；默认不每轮给三条“正确下一步”。已有建议入口保留，提示不是强制组成部分。
- 情境结束由已有不可逆结局、学生主动结束，或场景声明的可结束条件表达；DM 可以在叙事里建议收束，不能因关注点全打勾擅自终止。

**DM 的教学策略：先响应行动，再呈现后果，有必要才提供机会或提示。** 不要求每轮推进目标，不因学生走了另一条合理路线而把他拉回预设次序。

## 7. 场景作者与学生界面

### 7.1 作者只编写一次因果

编辑器按“处境与人物 → 行为与后果 → 教学关注点 → 呈现”组织。事实来源、条件与引用在同一位置选择，不让作者分别维护锚点前置、动作门控和反应条件三份同义配置。

- 保留表单／JSON 双向编辑、同一加载校验、追加修订；本轮不改 TOML。
- `rubric` 可以继续存在，但不参与 DM 上下文、动作解锁或世界结算；不要求五包都先写评分才可练习。
- 增加“保存并试跑”，固定刚保存的修订，复用学生页面。试跑会话显式标记并从普通使用统计默认排除。
- 在已有教师回放中显示输入、归属、结算与拒绝原因、最终交付及来源；不把模型生成的“思考过程”当执行证据。
- 历史修订只读；复制到当前形状再编辑，不能在读取时静默裁剪未知字段并宣称语义兼容。

### 7.2 学生只需要理解对象、行动与后果

- 保留“对谁说／我要做什么”。行动可指定 actor／device／scene 目标；点击对象只改变输入目标，不直接执行处置。
- 对多患者显式展示行动对象；目标离场或当前不可达时要求重新选择，不能静默换人。
- 保留自由表达，不恢复完整 affordance 菜单。结构化表单用于确实需要的记录／选择参数，而不是替学生列标准步骤。
- 本回合新出现的读数、线索与已执行处置可轻量高亮，点击定位来源回合；不高亮学生看不到的潜在风险状态。
- 移动端以对话和当前处境为主，设备与线索按需展开，不新增常驻诊断面板。
- 结果页先展示结局与关键事件，再看证据；分数降为可展开的旧能力。没有证据不生成因果结论，不把 `blocked/unmodeled` 算成临床错误。

### 7.3 训练 UX 的主次：处境第一，表达第二，资料第三

**学生界面不是 DM 调试台，也不是考试控制台。** 第一眼应回答“我在哪里、我是谁、眼前发生了什么”；下一步能明确向谁说话或对谁行动；需要查证时再打开已有资料。

代码核查所见：`ScenarioStage` 已区分旁白、角色台词与学生表达，窄屏侧栏已按需展开，这些保留。与此同时，舞台只取最近五条消息，学生行动与说话主要用小图标区分，图片失败直接隐藏。以下是针对这些结构的设计裁定，**不是本次浏览器视觉审计结论**。

| 场合 | 主信息 | 次信息 | 不出现 |
|---|---|---|---|
| 进入前 | 当前处境的一句话、学生角色、开始／继续 | 最近经历、场景说明 | 隐藏诊断、应做步骤、修订号占据主视觉 |
| 进行中 | 最新完整回合、人物回应、输入目标与输入框 | 已获得的读数／线索、历史消息 | 分数、锚点状态、完成百分比、内部工具过程 |
| 查看资料 | 已知事实及来源、设备读数、必要历史 | 来源回合跳转 | 系统推测的“你应该关注什么”伪装成已知事实 |
| 结束后 | 结局、关键选择与后果、原话证据 | 逐项判读、再练一次 | 以大号百分比替代整段经历的解释 |

桌面沿用“主对话＋可折叠资料栏＋底部输入”，不做三栏仪表盘。手机沿用单主列与资料抽屉；一次只打开一层，关掉后回到原阅读位置和原输入草稿。导航壳保留，进入训练不剥夺退出应用的路径。

页头只保留场景名、必要状态与次级操作。“资料／回看”与“结束本次”语义分开，不把两者都叫“经历”或“进展”；进行中的“进展”不能暗示任务完成率。开始按钮是入口主操作，发送是局内主操作，结束不与发送争同等视觉权重。

### 7.4 输入区：少一步操作，但不能少一个语义

输入区建议形态：

```text
说话 / 行动    对象：2 床患者（可切换）
输入你要说的话或要尝试的行动……
                                    发送
```

这是信息层级，不要求增加一排固定控件：沿用现有对象 chip 与统一输入容器即可。

- 保持已明确选择且仍有效的模式与对象，不要求每回合重新声明；目标始终可见，切换后草稿不丢。第一次不能静默猜定多床目标。
- 说话／行动同时有文字标签与形态差异，不能只靠 12px 图标或颜色；发送后的行动消息也应可读出目标，例如“对 2 床患者 · 行动”。
- “行动”表示尝试，不在乐观气泡上标成“已完成”。明确结算后才展示世界后果；被阻止要说明世界原因，系统失败要明确是系统失败。
- 建议默认不固定铺三条。学生需要时展开“给我一点提示”；建议先填入草稿供阅读、修改、确认，不一点就把临床处置执行掉。显式动作按钮仍遵守其表单与危险动作确认契约。
- 求提示是教学交互，不当作一次临床处置，不触发恶化；保留提示记录与来源以区分自主行动和受提示行动。它走只读交付路径，不能借提示揭开未获准的线索。
- 不自动纠正学生的临床表达为“标准正确操作”。对象歧义就问对象，参数缺失就问参数，不借澄清暗示诊断或最优路线。
- 中文输入法合成期间 Enter 不能发送；桌面 Enter 发送、Shift+Enter 换行有可发现说明；手机保留明确发送按钮，不让软键盘确认候选词触发提交。
- 回合处理中可以编辑下一条草稿，但不能提交第二个世界动作；失败保留原文本与目标，重试复用原请求身份。不要每次返回响应都强拉焦点或弹起手机键盘。

### 7.5 对话与变化：一回合是一组因果，不是一堆消息

- 以“学生尝试 → 世界回应 → 可见变化”组成完整回合。较长台词正常换行；同角色连续发言可合并显示，但不改变事件身份。
- 不再用“最近五条消息”裁掉尚在阅读的一回合。默认定位最新回合，向上能连续读历史；若需要分页，按完整回合加载并保持滚动锚点。
- 学生向上回看时不自动滚底；出现新回合显示轻量“有新回应”入口，由学生决定返回。保留现有不抢滚动的方向。
- 读数属于对应设备／患者，显示单位与最近更新回合；未测量、未知、未连接不能用零代替。不能把纯回合数显示成真实分钟。
- “本回合变化”优先突出刚得到的信息，而非持续闪烁整个设备。已过时读数能回看，新旧值有来源；红色只用于有依据的已观察异常，不给隐藏危重程度上色。
- 不把同一段旁白完整复制到线索板。对话负责经历顺序，资料栏负责当前可用事实；二者用来源链接关联。
- 多个角色同时有诉求时可以同时可见，但不弹多个模态框强迫处理顺序；明显与安静的线索可以有表达差异，不能靠 UI 直接给出“先救谁”的答案。
- 临时人物明确显示身份；不可接触的人可见但不能被误认为可操作目标。点击角色或设备只选目标／看资料，不暗中消耗回合。
- 图片未声明时不占空间；**已声明且当前应可见的图片加载失败时给重试与失败说明**。不能把技术失败伪装成“世界里没有这件东西”。

### 7.6 等待与恢复：不拿沉浸感掩盖系统状态

进行中只给真实阶段状态，例如“正在处理本次行动”“正在生成回应”；不显示 DM 工具名、推理内容、伪造百分比或机械轮播的“正在检查生命体征”。后台没有执行的临床动作，不能用作等待文案。

| 状态 | 学生看到什么 | 可做什么 |
|---|---|---|
| 等待回应 | 原输入＋局部忙碌提示；已有世界仍可读 | 查资料、回看、编辑草稿 |
| 需要澄清 | 一条具体问题，原行动尚未执行 | 补充对象／参数；不因澄清推进病情 |
| 动作被阻止 | 场景内可理解的原因与已发生后果 | 改变行动；不是“网络重试” |
| 系统生成失败 | “本次未执行／未提交”的明确说明，以服务端状态为准 | 重试或修改输入；旧世界不变 |
| 连接中断、结果未明 | “正在确认本次结果”，不声称已成功或已失败 | 等查询结果；不自动用新 ID 再执行 |
| 已提交但连接丢失 | 恢复原回合，不插入重复消息 | 继续训练 |

处理结束与离开也要分清：离开页面默认保留可继续的会话；“结束本次”明确意味着不能继续该局，确认框只用于这一终止动作及包声明的危险动作，不为普通对话增加确认。结束请求与在途动作按同一会话序号串行提交，不让结束页随后又长出新处置。

### 7.7 复盘页：先看事情，再看评价

建议顺序：

1. **当前结局与处境**：真实世界终态；主动提前结束就写提前结束，不补成“已完成训练”。
2. **关键回合**：你做了什么、当时有什么证据、发生了哪些已记录的变化。点开原话与读数，不默认铺满全文。
3. **值得再想的一处决策**：只基于已有事件提出反思问题，不在没有因果证据时声称“正是你导致了……”。
4. **判读详情**：现有 rubric 与分数放次级区域，明确是场景规则反馈，不冒充能力诊断。
5. **再练一次／返回场景列表**：本轮只是新开局，不承诺同随机轨迹或“回到过去修改历史”。

开发者／教师回放另有“解析、结算、交付”细节；学生复盘不复用管理 JSON 展开器。一个界面不同时承担沉浸训练、内容编辑和引擎调试三个角色。

### 7.8 UI 约束与实际验收

- 复用现有主题与 `--sc-*` 刻度，不为情境再建一套组件／配色体系；角色色只作辨识，不与异常告警色混用。
- 正文、行动标签和读数保持高可读性；次级信息降层级而不是缩成无法阅读的小字。普通文字对比度至少 4.5:1，触屏主要点击区域至少 44×44 CSS px，键盘焦点可见。
- 正常消息、旁白和系统错误既有视觉差异，也有可读标签／语义；不能只靠颜色。新回应使用克制的辅助技术通知，避免逐 token 播报。
- 手机软键盘展开、200% 缩放、长角色名、长文本、多床、多设备时，输入、发送和当前对象仍可达；不产生页面与抽屉互相争夺的双重滚动陷阱。
- 动画只说明新增或状态切换，不持续闪烁、不强制打字机速度；尊重减少动态效果偏好，提示音可关闭。
- 以 390px 手机视口和 1440px 桌面视口分别走“进入→说话→指定对象行动→查资料→回看→失败恢复→结束→复盘”，另检查窄屏边界、键盘和浅／深主题。设计文档中的线框不能替代真实浏览器结果。
- UX 成功的现场判据：首次进入的人能找到表达入口、发送前说出当前对象、区分“我尝试了”和“已经发生”、找到一条读数的来源，并知道如何离开后继续。若做不到，先改交互而非增加教程弹窗。

**训练 UI 的创新不在更像游戏或更像仪表盘，而在学生不用理解引擎，就能感到自己正在影响一个情境。**

## 8. API、事件与模块关系

### 8.1 请求与响应

学生请求统一携带 `request_id`、`expected_seq`、声明类型、目标引用、自由文本或结构化动作参数。认证身份由服务器给出，不能相信客户端的 user ID。目标引用必须属于本包且当下可接触；权限继续由现有入口约束。

后端为 `IntentResolution`、`ResolvedTurn`、`SceneDelivery`、学生视图、管理回放及 SSE 事件定义明确模型。通过现有 API 类型生成流程迁移消费者，不手改生成文件。内部结算模型不是直接对外返回模型：学生只收可见投影，管理侧才有拒绝原因、隐藏依据与教学关注点。

事件序号是提交顺序；`turn` 是情境推进数；`request_id` 是幂等身份；消息 ID 是显示身份；pack 修订是内容身份。不要把其中任意两个合并为同一个概念。

### 8.2 事件收敛

目标新增业务回合事件为一条 **`turn_committed`**，载荷包含该回合的学生输入、有效结算差量、来源引用和最终交付；形状带事件 schema 版本。开启、澄清交流与关闭保留独立事件。澄清交流可记录但不产生状态差量，也不增加情境回合数。

- 不再分别写 `action_attributed`、`dm_step`、`anchor_*`、`entity_line`；不再从模型事实声明触发后续规则。
- 请求身份唯一约束必须覆盖所有会改变会话记录的请求，包括澄清与关闭；实现时更新模型和 DDL，不只在 JSON 载荷里约定。
- 一个业务回合只追加一次，原子存储结算与可见交付；事件保留实际旧值／新值，而非以后根据新版包重新执行效果。
- 历史回放折叠已提交差量，不重新调用 LLM、不重跑新版本反应、不重算历史评分。
- 不为本轮引入消息队列、分布式工作流或检查点物化。数据库行锁与短事务足以约束单实例下的提交；内存暂存可以丢弃。

### 8.3 模块职责与删除范围

| 现有位置 | 实施方向 |
|---|---|
| `schema.py`、`validation.py`、`pack_loader.py` | 升版场景形状；增加目标引用／人物可写范围／教学关注点；统一加载与编辑校验 |
| `runtime/session.py` | 唯一回合协调器：解析、结算、演出、提交；不把领域逻辑放 router |
| `runtime/world.py` | 纯结算与事件折叠；动作、反应、事实来源唯一实现 |
| `dm/prompt.py`、`dm/contract.py`、`dm/runner.py` | 两个权限清楚的模型阶段；共用基础调用设施；协议从模型生成 |
| `dm/tools.py`、`dm/entity.py` | 删除运行期读工具／自语与未使用独立角色路径；同步删除专用配置和调用方 |
| `runtime/anchors.py` | 删除旧任务状态机；轻量教学关注点作为世界投影实现，不保留别名壳 |
| `router.py` | HTTP／SSE 适配、鉴权、错误映射；删除预演世界和重复求值 |
| `runtime/view.py`、`board.py`、`devices.py`、`judge/rules.py` | 消费同一份已结算事实；白板不再采信 DM 任意笔记；现有判读随事件消费者迁移 |
| `frontend/src/api/scenario.ts`、`scenario/stream.ts`、`ScenarioConsole.tsx` | 使用生成契约、稳定身份、统一阶段与权威视图；删除原始模型块镜像转换 |
| `frontend/src/scenario/admin/` | 编辑器切换新形状；锚点面板替换成关注点／结算来源回放；加入固定修订试跑 |
| `models/scenario_training.py`、`migrations/versions/` | 原子回合事件、请求身份约束、归档存储；仅迁移 `st_*` |

不是以文件数或行数作为减复杂标准。完成标准是同一因果不再有两个解释器，同一事实不再由模型和平台各写一份。

## 9. 切换与历史数据：单一新运行时，不悄悄重解释旧局

不保留新旧执行器长期分流，不建兼容别名或双协议入口；但删除代码不等于删除历史。

1. **先导出只读基线**：使用旧实现将旧会话物化为不可变归档（原始事件与修订、最终学生视图、按回合可定位的经历／管理回放投影、已有报告）。报告原来不存在就标记未结算，不能替它生成一份新成绩。
2. **归档存储**：新增本模块专属 `st_session_archives`，按原会话 ID 唯一存储归档投影及形状版本；保留原 `st_sessions`、`st_events`、`st_pack_revisions`。不覆盖原始内容，不需要旧引擎在线读历史。
3. **切换窗口**：暂停新局和新动作，等待正在执行的请求结束，再完成归档。未结束旧局保留进度并明确标记“机制切换，旧局仅可回看”；以 `abandoned` 加原因结束其可写生命周期，不能冒充学生主动完成。恢复入口后重新开局使用新修订。
4. **包转换**：五个包逐个追加新 schema 修订；动作效果、反应、知识、设备及判读规则按新语义审阅迁移。旧锚点不是机械改名：依赖变成实际行为条件，临床压力变成 reaction，教学意图变成 teaching_focus；不能静默丢掉旧 `unlocks` 或阈值。
5. **历史作者源**：旧修订显示原始 JSON 与历史标识；复制为新草稿通过显式转换并重新校验。新会话拒绝直接加载旧 schema，不沿用“裁掉未知键就算兼容”的运行策略。
6. **清除旧链路**：所有五包、学生与管理界面、安装入口、判读、相关测试、配置、诊断消费者同步迁移之后，删除旧工具循环、锚点提案、实体委派和旧写事件路径。
7. **回退边界**：在恢复新流量前验证归档数量、会话身份、事件尾序号与回放内容，并备份。恢复新流量后不能把旧二进制直接指向新格式继续写；优先关闭情境入口，保留数据，修复新运行时。部署脚本与运维文档必须写清此边界。

归档转换须先 dry-run 给出数量与差异，再在维护窗口执行；不能由应用普通启动自动封存活动会话。此次文档变更不执行任何迁移、封存、删数据或部署。

## 10. 实施顺序与可交付切片

旧问诊轨与现有研究路径保持不变。开发中可以有过渡提交，但切换前不得宣称新机制已完成；开发基线用于比较，不作为永久双运行时开关。

| 顺序 | 交付 | 完成判据 |
|---|---|---|
| A：基线与新契约 | 固定五包当前修订；保存真实旧运行轨迹；定好解析／结算／交付模型和新包形状；验证归档方案 | 能说明每个旧能力移到哪里；现有会话可保真归档，未执行的验证明确标记 |
| B：唯一结算器 | 显式／自由动作统一入口；效果、反应与来源收敛；实现人物状态边界与教学关注点 | 同意图两入口得到相同结算；并行风险成立；反应链有限且可重放 |
| C：DM 与传输切换 | 固定两阶段 DM；统一 HTTP／SSE；原子事件、幂等与冲突；删除旧协议 | 真实模型完成一局，屏幕、世界与回放一致；失败不假推进，断流不重复执行 |
| D：作者与学生闭环 | 五包迁移；新编辑器字段与试跑；对象输入、变化引用、报告重排 | 每包从编辑→固定修订试跑→结束→回放走通；学生视图不泄露内部字段 |
| E：实际切换 | 归档、追加包修订、封存旧活动局、删除旧实现及配置、同步文档与消费者 | 五场景真实验收通过；归档可看；运行入口只有新链路；旧轨不被污染 |

B 与 C 的核心工程收益优先于语音、导出、图片扩展与分支重玩。运行指标沿用既有 LLM 日志／诊断入口，不为此次比较新建观测平台；调整旧 `dm_step` 消费者时须同步接口契约，不能留名为步数实为别的数据。

## 11. 验证：证明新体验，不用编译成功冒充创新

### 11.1 必须保持的行为不变量

永久回归只覆盖消费者可感知边界：

- 同一声明动作经按钮和等价自由表达输入，目标、效果、揭示与反应相同；原话不同不要求台词逐字相同。
- 计划、询问、已执行操作彼此区分；多目标歧义不误操作，未知行为不误判临床错误。
- 确定性效果不会被模型重复叠加；人物状态提案不能修改临床变量。
- 同回合反应不重复、链式激活可重放；初始条件与空条件语义明确。
- 模型生成内容不能写世界，未提交回合不能进入正式历史；重试与重复请求至多提交一次。
- 过期基线与同 ID 异输入被拒；提交后断流能取回原结果。
- 学生响应／导出不含隐藏事实、教学关注点、拒绝诊断与模型内部提案；管理权限不向学生投影扩散。
- 新旧历史均可回看，原始事件与已有报告不被重算覆盖。

不保留对提示词逐字内容、旧字段副本、模型说明文本或组件拼接方式的测试；删除这类实现绑死的断言，不通过重新钉住文案来“修绿”。结构化输入的结算不变量可确定性测试；自由表达理解与教学表现必须用真实模型运行，不能由 mock 回声证明。

### 11.2 两个主场景先证明机制

| 场景 | 必须实际尝试的路线 | 要观察的差别 |
|---|---|---|
| 吸痰无效 | 重复无效处置；先复核再改变行动；只说“准备做”；提出未建模替代做法 | 无效操作不能因为文案积极就改善世界；合理调整有已声明后果；DM 不替学生完成前置；未建模诚实说明 |
| 两床同铃 | 先回应声音大的；先核查安静的一床；交换顺序；行动对象含糊；处理一床时另一床仍有诉求 | 两个问题能并存；不被唯一 active 强制串行；处理顺序产生可见区别；不把另一床自动处理好 |

另三包不是可放弃的范围：高血压矛盾须保留矛盾证据与复测路径，预检藏危重须保留未主动核查就不会凭空出现的关键线索，夜班电话须区分口头报告、求援与实际执行。主场景机制成立后，三包也要逐一跑完整局。

### 11.3 真实比较与否决条件

- 使用固定包修订、相同模型配置与相同起始学生输入，对旧基线和新实现分别运行；后续按实际反馈继续，不假装随机生成结果完全可控。
- 两个主场景每条关键路线至少重复三次，记录动作归属、事实漂移／泄漏、是否替学生完成、是否强拉路线、首个可见响应与整回合耗时、模型调用数、失败与重试。小样本是工程探查，不是教学有效性统计证明。
- UI 必须实际用桌面与手机视口操作：目标选择、一次动作、世界变化、断流恢复、结束、回看；同时观察屏幕和落库事件，不只看测试通过。
- 成功标准是关键路线确实形成不同且合理的经历，用户能看到“自己的选择→后果”，而不是工具调用更少或提示词更短。
- 任一真实用例出现幽灵处置、提前泄题、旁白与状态矛盾、旧数据被改写或并行问题被强制排队，均阻止切换。
- 若两阶段造成的等待使体验明显变差，先缩小上下文与输出、复用可确定的解析；不得通过重新混合世界写入与演出来掩盖延迟。是否保留该分工须依据实际延迟及一致性收益复审，不能预先宣称最佳。
- 若新旧经历没有可观察差异，只能报告工程简化，不可宣称创新已经验证；继续改场景因果与 DM 教学策略，而不是追加 agent 数量、面板或治理流程。

## 12. 本轮文档交付与下一步

本轮只确立设计和实施顺序；运行代码、数据库与部署未改变。下一次代码工作从 A 的真实基线及契约开始，再进入 B 的唯一结算器；不要先实现新面板、语音或泛化工具系统。
