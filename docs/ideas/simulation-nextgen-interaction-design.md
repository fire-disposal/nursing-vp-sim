# 临床推理模拟 — 新一代交互范式设计（Clinical Workbench）

> 状态：设计定稿（feature/simulation-workbench 首轮落地范围）
> 适用范围：`/simulation` 临床推理模拟（生理引擎子功能）
> 背景：斜杠指令终端是过渡形态；Mantine 迁移在另一分支进行；本设计为交互层的「北极星」，
> 后端以服务器驱动的结构化契约先行落地，前端先用原生实现预览，Mantine 界面届时直接消费同一契约。

## 1. 现状审查（为什么要换范式）

对现有 `/simulation` 交互特性逐项审查，结论如下（评分为主观体验判断）：

| 现有特性 | 现状 | 审查结论 |
|---|---|---|
| 斜杠指令 + 中文别名 | 命令头与参数均支持中英双语 | ✅ 表达力强；❌ 依赖「知道命令存在」才能用 |
| 自动补全面板（分组折叠） | 输入 `/` 后按 信息/评估/检查/给药/对话/处理 分组提示 | ✅ 发现性优于裸终端；❌ 仍要求先输入 `/`，且折叠态信息密度低 |
| 分级帮助 `/help <主题>` | 评估/检查/给药/对话/处理五主题 | ✅ 内容完整；❌ 深藏在文本里，新用户不知道去读 |
| 时间轴可视化 | 时钟游标 + 时间线图例 | ✅ 时间感好；❌ 只展示宏观，不展示 pending 检查的 ETA |
| 结构化消息（7 类带色） | SYSTEM/ASSESSMENT/MONITOR/LAB/TALK/WARNING/CRITICAL/AUDIT | ✅ 语义清晰；❌ 全部是文字，读数趋势要靠读 |
| 资源预算（检查点/治疗点） | 顶栏 chips | ✅ 可见；❌ 行动前不显示单次代价，用户事后才知道扣了多少 |
| 病例切换/重新开始 | 顶栏按钮 | ✅ 直接；❌ 切换无确认，误触即丢进度 |
| 诊断记录面板 | 折叠式文本域 + 保存 | ✅ 有；❌ 折叠入口不显眼，用户常不知道有这功能 |
| 结局横幅 | 成功/失败一句话 | ✅ 有结果；❌ 不展示「目标达成明细」，复盘信息不足 |
| 开局引导 | 交班一行 + 基线一行 | ❌ 唯一引导；没有任务拆解、没有资源说明、没有「下一步做什么」 |

### 1.1 核心问题诊断

1. **行动不可见（discoverability）**：玩家能做的所有事都藏在命令语法里。不知道 `/assess drain` 存在，
   就不会去评估引流；不知道 `/give` 有什么药，就不会治疗。**认知负担 = 记忆命令面**，而不是思考临床。
2. **代价不透明（cost opacity）**：行动的时间消耗、资源消耗在行动前不可见，反馈滞后（`扣 35 检查点，剩余 365`）。
3. **反馈单薄（thin feedback）**：一次评估返回一行文字；趋势要靠人脑对比上一次读数。
4. **患者无在场感（no patient presence）**：患者是消息流里的文本，没有持续存在的「床旁状态」——
   监护仪、意识、主诉都不连续，玩家感受不到「一个正在变化的病人」。
5. **引导缺位（no guidance loop）**：没有目标清单、没有卡住时的阶梯提示、没有行动后果的解读。
6. **互动感低（low engagement）**：纯文字进出，像在用终端调接口，不像在管病人。

### 1.2 保留与复用

以下特性经过验证、应保留并融入新范式：
- 结构化消息体系（7 类语义 + 颜色）→ 升级为「护理记录流」；
- 时间轴 → 保留并增强（pending ETA）；
- 中英双语命令 → 保留为高级/键盘路径；
- 确定性引擎与可见性白名单 → 新契约继续遵守（不泄露 hidden state）。

## 2. 新一代范式：「临床工作台」（Clinical Workbench）

**一句话**：把模拟从「输入命令驱动」翻转为「临床场景呈现 + 点击行动」，玩家像站在床旁工作，
而不是在敲终端。

### 2.1 交互原则（五条）

1. **行动可见**：所有可做的事以按钮/卡片呈现，按临床工作流分组（评估/检查/治疗/沟通/处理）；
   不必记忆任何命令。
2. **代价透明**：每个行动在点击前就显示时间与资源代价；资源不足/条件不满足时按钮置灰并说明原因。
3. **即时反馈**：每次行动后立即呈现结果卡（读数 + 与上次的对比箭头）、对资源/时间的影响、目标进度变化。
4. **渐进揭示**：隐藏病程永不直接暴露；信息随评估/检查/监护逐步公开；教练提示按阶梯升级，低阶不剧透。
5. **引导内建**：开局简报 → 常驻目标清单 → 阶梯教练提示 → 结局复盘，全流程有人带。

### 2.2 工作台布局（信息架构）

```
┌────────────────────────────────────────────────────────────┐
│ 顶栏：病例名 · 墙钟 · 状态 · 监护开/关 · 检查点 · 治疗点 · pending │
├──────────────────────────────┬─────────────────────────────┤
│ 左侧「床旁区」                │ 右侧「行动面板」              │
│  ├ 患者状态卡（意识/主诉/表情）│  ├ 评估（每项：时长）         │
│  ├ 生命体征面板（最新+趋势）   │  ├ 检查（每项：费用+ETA）     │
│  └ 检查结果卡（异常高亮）      │  ├ 治疗（每项：费用+剂量）     │
│                              │  ├ 沟通（患者/家属）          │
│ 下方「护理记录流」             │  └ 处理（监护/会诊/诊断/报告/  │
│  （原消息流，结构化着色）       │      等待/教练提示）          │
├──────────────────────────────┴─────────────────────────────┤
│ 底部：时间轴 + 教练提示条 + 输入框（斜杠高级路径）              │
└────────────────────────────────────────────────────────────┘
```

- **床旁区**：患者的「存在」——意识、生命体征、检查结果随行动实时更新；让玩家随时能「看病人」。
- **行动面板**：决策面——能做/不能做一眼看清；点击即执行，代价透明。
- **护理记录流**：历史事实的单一记录（原消息流），行动反馈以卡片式条目插入。
- **教练提示条**：常驻一条「现在建议做什么」，随进度升级，可关闭。

### 2.3 行动范式（Action → Result 闭环）

1. **点击行动卡**（评估/检查/沟通/处理：立即执行；治疗：先选剂量再确认）；
2. 时间推进（事件结算，与现行引擎完全一致）；
3. 结果以卡片插入记录流：读数 + 对比箭头（↑3 HR）+ 异常高亮；
4. 床旁区同步刷新（监护面板、患者状态卡、目标清单）；
5. 若行动被拒，按钮已置灰并显示原因，正常情况下不会发生「点了没反应」。

### 2.4 引导体系（三层）

| 层 | 形态 | 触发 | 内容 |
|---|---|---|---|
| 开局简报 | 可折叠简报卡 | 会话开始/可重开 | 患者信息、任务、目标、资源模型、第一步建议 |
| 目标清单 | 常驻 chips/进度 | 全程 | 评估过？有异常证据？监护开？报告？治疗？诊断？ |
| 教练提示 | 阶梯提示条 + `/hint` | 卡住/主动请求/新会话 | L0 开篇建议 → L1 方向 → L2 具体行动 → L3 直接指引（不剧透 hidden） |

教练提示由确定性规则计算（纯函数，可测试，不依赖 LLM），随玩家进度单调升级，低阶不泄露隐藏病程。

## 3. 服务器驱动契约（后端先行）

UI 的一切可交互内容由后端快照下发，前端是「哑渲染器」——新病例/新药/新检查自动长出按钮。

### 3.1 SimulationSnapshot 新增字段

```jsonc
{
  "brief": {                       // 开局简报（由 CaseSpec 派生）
    "patient": "…", "task": "…", "goal": "…",
    "resources": {"diag": 400, "treat": 100, "consult": 120},
    "assessments": ["vitals","drain",…],
    "drugs": ["FLUIDS",…], "labs": ["CBC",…],
    "opening_hint": "建议先评估生命体征建立基线…"
  },
  "objectives": {                  // 目标清单（纯函数计算）
    "assessed": true, "evidence": false, "monitoring": true,
    "treated": false, "reported": false, "diagnosis": false,
    "timely": null                 // "timely" | "delayed" | null
  },
  "hint": {"level": 2, "text": "已有异常证据，可 /report doctor 向医生报告"},
  "patient": {                     // 床旁状态（只含已知信息）
    "consciousness": "清醒",       // 清醒/嗜睡/昏迷
    "monitoring": true,
    "latest_vitals": {…}           // 最近一次已知生命体征
  },
  "actions": {                     // 行动目录（服务器驱动按钮）
    "assess": [{"id":"vitals","label":"生命体征","duration":2,"enabled":true,"disabled_reason":null}, …],
    "order":   [{"id":"cbc","label":"血常规(CBC)","cost":35,"cost_label":"35检查点","turnaround":15, …}],
    "give":    [{"id":"FLUIDS","label":"快速补液","cost":30,"unit":"ml","default_dose":500,"max_dose":1500, …}],
    "talk":    [{"id":"patient","label":"患者", …}],
    "manage":  [{"id":"monitor","label":"开启持续监护","enabled":false,"disabled_reason":"已开启", …},
                 {"id":"consult",…},{"id":"diag",…},{"id":"report",…},{"id":"wait",…},{"id":"hint",…}]
  }
}
```

### 3.2 规则归属

- 行动目录的 `enabled / disabled_reason` 由引擎纯函数计算（`catalog.py`）——规则只在引擎一处，
  前端不复制任何判定；报告置灰原因「需先获得异常证据」等均不泄露 hidden state。
- 教练提示（`coach.py`）、目标清单（`objectives`）、简报（CaseSpec 派生）均为纯函数/数据。
- 消息新增 kind：`PATIENT`（患者台词里程碑）、`HINT`（教练提示），供前端差异化渲染。

### 3.3 兼容性

- 所有新字段为快照增量，旧前端字段（vitals/drain/pain/urine/readings/pending/lab_records…）原样保留；
- 斜杠命令全部保留（`/hint` 新增），行动按钮与命令共用同一 `/actions` 端点与同一引擎；
- 无 DB 结构变更（状态仍在 JSONB），无需迁移。

## 4. 内容纵深（本轮一并落地）

引导与交互的「手感」离不开内容深度，本轮内容扩展：

1. **新评估目标「意识状态」**（全病例通用）：/assess consciousness —— 清醒/嗜睡/昏迷，联动对话可用性；
2. **新病例 MVP-P 社区获得性肺炎**（复用 infection 轴，纯数据）：发热咳嗽、肺部听诊、白细胞、低氧；
3. **新病例 MVP-A 哮喘急性发作**（新 airway 轴 + 内核扩展）：喘息、RR/SpO2 随严重度变化、
   沙丁胺醇缓解（wheeze 呈现在未给药时即存在——修正原内核「给药后才出现 wheeze」的语义）；
4. **新药物 甲泼尼龙（STEROID）**：抑制 airway 轴进展（复用 progression_mult 机制）；
5. **患者台词里程碑**：严重度跨越阈值时患者发出符合病例的台词（口渴/头晕/喘息/呻吟…），
   让病人「活着」，增强互动感与线索感。

## 5. 迁移路径

| 阶段 | 形态 | 说明 |
|---|---|---|
| 当前 | 终端 + 行动面板（原生预览） | 本分支落地：行动面板为主，斜杠保留为高级路径 |
| 中期 | Mantine 工作台 | 同一契约，Mantine 组件重绘（另一分支） |
| 远期 | 场景化 UI（可选） | 动画化床旁、拖拽式医嘱等，契约不变 |

斜杠命令永不作废：它是键盘流、测试与脚本路径，与按钮等价。

## 6. 验收标准（本轮）

1. 新会话开局可见简报卡与目标清单，无需任何输入；
2. 行动面板列出当前病例全部可用行动，代价（时长/资源）可见，禁用项说明原因；
3. 点击评估/检查/治疗/对话/报告等行动与对应斜杠命令产生完全一致的结果；
4. 卡住时（未评估/未监护/有证据未报告等）教练提示按阶梯升级，不剧透隐藏病程；
5. 生命体征面板、患者状态卡随行动实时刷新；
6. 两个新病例（MVP-P/MVP-A）可玩通较好/延误路径，哮喘病例沙丁胺醇/激素有可测的生理效果；
7. 患者台词里程碑按阈值触发一次且顺序正确；
8. 全量 simulations 后端测试 + 前端 vitest + tsc 通过；api-types 重新生成一致；
9. 不污染 `refactor/frontend-mantine` 分支（独立 worktree 开发）。

## 7. 试玩指引（快速上手）

访问 `/simulation`（需登录）。右侧行动面板即主要交互面，斜杠命令为等价高级路径。

**MVP-B 出血（mvpb-1，默认）**：行动面板点「生命体征」→「引流」→「血常规」→「开启持续监护」→
「等待」→「查看」（血常规）→「向医生报告」。留意教练提示条随进度升级，患者台词在恶化时出现。

**MVP-A 哮喘（mvpa-1，新）**：先「肺部听诊」（闻及哮鸣音）→ 治疗组点「沙丁胺醇」（剂量弹层确认）→
「给氧」→「开启持续监护」→「向医生报告」。要点：喘息是疾病本身，未给药即可闻及；
沙丁胺醇可缓解喘息并改善 RR/SpO2；甲泼尼龙抑制病程进展。

**MVP-P 肺炎（mvpp-1，新）**：评估体温/肺部听诊 → 血常规（白细胞升高）→ 抗生素 + 给氧 →
报告。感染轴发热、湿啰音（实变）、白细胞升高随严重度演进。

**想被教练带着走**：开局简报卡给第一步；提示条随时给下一步；`/hint` 主动询问。
**结局复盘**：结束时横幅展示目标清单明细与「及时/迟报」判定，`/status` 查看完整结算。
