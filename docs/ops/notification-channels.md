# 通知渠道（一条事实 = 一条渠道）

面向评审与后续开发：**同一条事实只许出现在一个渠道里**。选错渠道的典型症状是"同一件事
屏幕上出现三遍"（评分失败曾同时在记录页黄纸、评分遮罩、红 toast、通知中心、列表徽章五处出现），
以及"横幅把首屏内容推下去又没法关"。

## 渠道分工

| 事实类型 | 唯一渠道 | 实现 | 生命周期 |
|---|---|---|---|
| 全局、持续、与页面内容无关（断网） | **状态条** | `components/ui/status-strip.tsx` | 条件消失即撤，无关闭按钮 |
| 属于某个对象/区域的状态（评分进度、降级分、成绩说明、表单失败、问卷故障） | **就地内联** | `Alert variant="light"` / `FormMessageBanner` / `ScoreStatusBanner` | 随对象存在 |
| 用户动作的直接结果（保存、删除、提交、复制） | **Toast** | `components/Toast.tsx`（右上、去重、上限 3） | 3–6s |
| 异步、可回看的事件（评分完成/失败、作业、反馈回复、公告） | **通知中心** | `NotificationBell` + `/notifications` | 读到为止 |
| 破坏性操作、阻断前置（确认删除、必答问卷、交卷完成清单） | **弹窗** | `useConfirm` / `Modal` | 用户处理，必须留真实出口 |
| 部署更新提醒 | **跑马灯**（`Layout.tsx` 的 `DeployBanner`） | 独立实现 | **特例**：见下 |

判定口诀：

```
与页面无关 且 会持续        → 状态条
属于某个对象/区域            → 就地内联
我按了按钮，结果如何         → Toast
它自己发生的，我可能回来看    → 通知中心
我不处理它就没法继续          → 弹窗（且必须能退出）
```

## 形式约束

- **状态条**：一条通道一行、高度固定（`py: 5px` + 13px 字 ≈ 26–30px）、单行截断、浅底深字
  （黄 1 底 + 黄 9 字 / 红 1 底 + 红 9 字），`role="status" aria-live="polite"`。**同一页面最多一条**，
  多条条件按优先级合并成一行。不许出现黄底白字（对比度 ≈1.6:1，读不清）。
- **Toast**：右上角（不遮底部输入区与操作栏）、成功 3s / 失败 6s、同一 `type+message` 只保留一条
  （重复触发只刷新计时）、同时最多 3 条。只用于动作结果，不用于后台事件与网络状态。
- **内联**：跟随容器，不把全局布局推下去；同一对象最多一条主提示 + 一条附加说明。
- **通知中心**：服务端 `notifications` / `system_notifications` 两套数据分别服务"我的事件"与
  "平台公告"；不在别处重复造第三份 UI。

## 严重度词表

| 级别 | 含义 | 颜色 | 出现位置 |
|---|---|---|---|
| `info` | 陈述事实/说明，无需动作 | 中性灰/蓝 | 内联、通知中心 |
| `warn` | 能力受损或需要留意，仍可继续 | 琥珀（浅底深字） | 状态条、内联、Toast |
| `error` | 动作失败或功能不可用，需要处理 | 红（浅底深字） | 内联、Toast、整页失败态 |
| `blocking` | 不处理无法继续 | 弹窗 | 必须是弹窗，且提供退出路径 |

`/api/diagnose` 的 `alerts` 与前端告警共用 `warn` / `error` 两级语义（服务端不产生 `info` 告警）。

## 例外：部署更新跑马灯

`Layout.tsx` 的 `DeployBanner` 是**唯一被保留的特殊通道**：运维窗口内必须持续可见、不能被
用户关掉、不能因为页面布局而消失。它刻意不并入状态条，也不走 toast。

已知取舍（不要"顺手修"）：琥珀底白字对比度不达 AA。

清除机制（线上是按预期生效的）：告警态是后端进程内全局（`infra/diagnostics.py` 的
`_deploy_warning`），而部署本身会重启后端容器 —— 新进程起来后 `GET /api/deploy-status`
自然返回 `active:false`，横幅随版本切换消失。残留只发生在**部署没走到重启**的情形
（迁移失败中止、回滚复用旧进程），此时才会一直挂着，需要手工
`DELETE /api/admin/deploy-warning`（`scripts/deploy-banner.sh`）或等下一次成功部署。

## 违反判定

评审时按这三条驳回：

1. 同一事实在两个渠道同时出现（除"通知中心留档 + 当前页一次瞬时提示"这一对有意的配对）。
2. 条件性状态用 toast 表达，或动作结果用横幅表达。
3. 新增横幅时没有说明它"为什么不能就地内联/为什么不能进状态条"。
