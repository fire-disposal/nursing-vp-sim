# 训练区现状观察（2026-11-07）

> 快照性记录，不是运行期契约。后续以代码与 `docs/architecture.md` 为准。
>
> 范围：普通问诊训练（`history_taking`）及其附属实体；同时区分情境训练的 LLM 工具。
> 方法：静态代码观察。未运行 LLM 演练，未接触生产数据，未做学生实测。
> 状态：观察结论与待验证建议，不构成实施承诺。

## 结论

训练区的主要问题不是数据层不可靠，而是**可靠性与扩展框架已明显领先于学生侧任务闭环**。

当前产品更接近“护患对话 + 若干并列工具面板”，还不是一条围绕护理任务自然推进的体验。
因此，下一步不应优先增加 Workflow、插件系统或通用实体，而应把一个病例从进入到复盘重练做穿。

## 已确认事实

- 当前只有 `history_taking` 具备真实学生运行入口；`clinical_reasoning` 仍只支持编写、发布与目录展示，训练入口明确拒绝。
- 普通训练只有三个静态 Activity：床旁检查、护理记录、随堂测验。没有运行时插件发现或安装机制。
- 护理记录是唯一的正式学生产物，也是当前唯一可配置为交卷门禁的产物。
- 护理记录只有已提交的冻结版本进入评分；未提交草稿不进入评分证据。
- 默认不要求提交护理记录，是否必须提交由单个病例声明。界面上的固定“结束前必须提交”提示与此规则不一致。
- 随堂测验是独立辅助能力：不进入患者上下文、不参与评分，也不构成完成产物。
- 床旁检查结果同时进入患者上下文与评分证据；其动作审计时间线已经是训练过程的一部分。
- 情境训练使用另一套由主持人 LLM 调用的世界演绎工具。它与普通训练 Activity 的执行者、状态模型和持久化方式不同，不应为名称一致而合并。

## 待验证的产品假设

**把“聊天窗 + 工具抽屉”改成“证据驱动的护理任务”。**

- 对话和查体负责产生证据。
- 护理评估是主要工作产物，而不是侧栏里的附属表单。
- 结束后的关键选择复盘要能回到具体证据。
- 同例纠正或迁移练习是任务终点，而不是结果页的附加按钮。

该方向优先复用现有训练记录、对话、工具审计、护理记录、评分复盘与再练习能力，不新增证据表。
在验证前，不为它建立新的通用框架。

## 建议的最小实验

1. 只选一个 `history_taking` 病例，不推广到其他病例或新 Workflow。
2. 用现有教学蓝图写清学习目标、关键线索、关键遗漏与典型错误。
3. 为该病例配置真实有用的查体锚点，并明确护理记录是否必须提交。
4. 训练界面围绕“还缺什么证据、护理产物进行到哪一步”组织，而不是只陈列工具入口。
5. 结果页直接使用现有评分关键选择与再练习入口。
6. 找少量真实学生观察，重点看四件事：
   - 是否知道下一步要做什么；
   - 是否主动使用查体；
   - 是否理解护理记录的草稿/提交状态；
   - 是否能从复盘进入同例纠正或迁移练习。

不跑 LLM 自演作为体验证据；自检只做类型检查、构建、浏览器实操和迁移往返等不烧模型预算的验证。

## 暂缓事项

- 暂不补全 `clinical_reasoning` 的学生工作区，除非明确决定把它作为下一阶段唯一主线。
- 暂不建设动态插件机制。
- 暂不为“任务中心化”新增通用数据模型或抽象层。

## 已知清理项

这些是可独立处理的小债，不应与体验实验捆绑：

- 护理记录面板的固定提交提示应改为读取当前病例的实际完成条件。
- 未接入路由的护理记录请求/响应契约，以及未被运行期消费的完成声明字段，应删除或接通；当前属于误导性元数据。
