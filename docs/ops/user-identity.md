# 学生身份与名单导入

## 一条不变量

**同一院校里，一个学号只对应一个学生账号。**

账号是登录凭据，训练记录、LLM/语音日志、问卷、作业接收人都挂在 `users.id` 上。同一学号出现
两个账号，就等于把同一个人的历史劈成两半：班级看板里这人可能是 0 次训练，而真实数据躺在另一个
账号上（2026-10 线上：郑悦霄、王雨佳各两个账号，20 / 14 条已完成训练留在 7 月建的旧号里）。

学生身份 = `(院校, 学号)`；班级**不**参与身份。一个人可以在多个班（`user_class` 多对多），
换班、跨届、试点班里再被收进正式班，都只是给同一个人叠加成员关系，**不迁移、不删除历史**。

### 为什么不落数据库唯一索引

管理/教师账号历史上也用 `student_id` 存内部编号（线上 4 个 admin 共用 `admin-csh`）。
「仅学生、仅本校」的偏唯一索引不是普通唯一索引能表达的，写成触发器/生成列属于为约束加机制。
所以判定放在写入侧的唯一实现 `backend/core/identity.py`，注册、编辑用户、批量导入（预检与提交）
共用同一份；越权/冲突一律拒绝并说明撞了哪个账号。

## 名单导入的语义

一次导入 = 一轮名单。判定顺序：

1. **同学号已存在**：姓名一致 → `并入`（补班级成员；旧号缺学号时补上）；姓名不同 → `跳过`，
   交给人工核对（转专业、名单笔误都可能，自动合并会把两个人并成一个）。
2. **用户名已存在**：同名同校同号 → `并入`；姓名/学号/院校不一致 → `跳过`。
3. 都不命中 → `新建`。

其它拒绝规则：同一批次内学号重复（从第二行起跳过）、密码少于 6 位、非学生角色、学校不存在、
学校与班级所属院校不一致、既没学校也没班级。

**预检与提交共用 `_plan_batch`**：`POST /admin/users/batch/preview` 只读，返回逐行
`create / link / skip(原因)`；`POST /admin/users/batch` 才落库。预检阶段不建班、不建号，
所以被跳过的行不会留下空班。前端未预检不允许提交。

班级按 `(院校, 届别, 班级名)` 解析，本校缺失才新建（`护理241` 只存在于别校不再被误绑定，
2026-10-28 事故）。

## 运维操作

| 场景 | 做法 |
|---|---|
| 名单用户名写错 | 编辑用户改 `username`（登录键）；历史不动，审计记录 before/after |
| 学号相同、两个账号（历史双账号） | 保留**有历史**的账号：改它的用户名为名单用户名 → 加目标班成员 → 删除空账号（有训练记录时服务端会拒绝删除，天然防止误删） |
| 学生换班/多班 | 编辑成员关系叠加，不删旧班（旧班是上一轮的切片）；统计切片由页面筛选决定 |
| 重复导入同一份名单 | 幂等：全部命中既有账号 → `linked`，不新建 |

## 统计口径

- 学校级：`User.id IN (班级成员)`，`IN` 去重 → 一人多班不重复计数。
- 班级级：按班计 → 同一人在两个班各计一次（符合「班级视角」直觉）。
- 真正会把统计弄错的是**双账号**，不是多班；身份不变量就是为此存在。
