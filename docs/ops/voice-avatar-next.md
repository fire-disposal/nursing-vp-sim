# 下一阶段：会动的患者形象 与 语音识别自听

> 状态：评估稿（2026-10-29）。两条都还没定方案；本文只列约束、选项、成本与验收口径，
> 决定权在教研侧。

## 一、现状（代码事实，不是设想）

| 环节 | 现在是什么 |
|---|---|
| 患者形象 | 静态 PNG：按年龄/性别 10 张兜底图 + 病例可声明 6 种情绪立绘（`patient_info.portrait_states`）。无逐帧动画；只有外围呼吸光环/说话高亮 |
| 声音 | 后端火山 TTS 流式 PCM 24k 单声道，前端按句流水线播放（首句到即播）；情绪由当前情绪状态带进请求，不朗读括号旁白 |
| 打断 | 持续对谈模式下麦克风常开，学生开口即停播并取消在途生成（barge-in） |
| 识别 | 浏览器 Web Speech（Chrome/Edge），拿不到原始音频流，无法指定回声消除参数 |
| 部署 | 单实例 Docker，无 GPU；模型调用走外网 API |

两个目标都不是「加个开关」：一个要新增逐帧渲染与口型驱动，一个要改变双工音频的边界。

## 二、目标 1：人像会动、做成视频交互

### 不可绕开的三个约束

1. **TTS 是逐句流式的**：一句合成完就开始播，整段回复不是一次性拿到。任何「整段音频先生成
   视频再播」的方案（SadTalker / Wav2Lip / 离线数字人）都与首句延迟冲突，除非把首句延迟从
   现在的一秒级拉到十秒级——训练体验不可接受。
2. **生产没有 GPU**：本地推理（LivePortrait、EMO 一类）要 GPU 常驻；单实例 Docker 加 GPU
   意味着换机器与常驻成本。
3. **素材是单张立绘**：没有多角度、没有绑定骨骼。所有「会动」都要么在 2D 上做分层/变形，
   要么交给外部服务做音频驱动视频。

### 选项

| 方案 | 做法 | 延迟 | 成本 | 风险 |
|---|---|---|---|---|
| A. 浏览器端微动（可控、先做） | 单张立绘做眨眼、呼吸、轻微头部摆动 + 按音频包络开合嘴部（RMS 驱动，不做音素口型） | 0（本地） | 0 | 口型只是「张嘴」，不逐字；需要为每张图准备嘴部遮罩 |
| B. 分层 2D 绑定 | 把立绘拆成头/眼/嘴层，Canvas/WebGL 变形，音频包络驱动 | 0 | 美术一次性成本（每病例） | 层拆不好会「纸片感」 |
| C. 外部实时数字人 API | 音频流推给供应商，换回视频流（HeyGen Interactive / Tavus CVI / Simli 一类） | 1–3 s 起 | 按分钟计费；第三方汇总的 2026 报价：Tavus CVI 约 $200 / 10 小时（≈$0.33/min），HeyGen API 视频按条计价（约 $2.6–4/min），Simli 有免费 50 min/月档；**需向供应商确认实时档，不能拿视频档报价当实时价** | 网络抖动、按分钟成本随训练时长线性增长、数据出境合规 |
| D. 离线音频驱动视频 | 整段回复生成口型视频再播 | 十秒级 | 低（自建）/ 中（API） | 与流式播放冲突，除非改成「先出字幕、后播视频」 |

参考：[Tavus 价格汇总](https://www.spatius.ai/blog/tavus-pricing-2026/)、
[HeyGen API 价格汇总](https://adsgen.ai/blog/heygen-api-pricing)、
[实时人脸 API 对比（Simli 等）](https://onvid.ai/alternatives/tavus)。

### 建议路径

1. **先 A**：一周量级，验证「会动」是否已经足够支撑临场感（眨眼 + 呼吸 + 说话时嘴部开合 +
   轻微点头）。验收：首帧 <100 ms、口型与音频同起同停、无掉帧、`prefers-reduced-motion`
   下退化为静态。
2. **需要逐字口型再评估 C**：先确认供应商是否给**音素/口型时间戳**（火山 TTS 侧是否有
   viseme 需要实测，文档里没有承诺）。没有时间戳就只能做包络口型，A/B 已达上限。
3. D 只在「复盘/回放」场景有价值（离线生成，不参与实时对话），不进实时链路。

### 2026-10-30 实测：方案 A 已落地为自绘引擎（M2），结论是「抖动图片」不是终点但也到顶了

第一版（M1 `presenters/liveAvatar.tsx`）只是整图平移/旋转，看起来像有人在晃照片。M2 换成
canvas 绘制引擎（`components/training/presentation/engine/`），陈列台 `/presentation-lab`
三栏并排（静态 / M1 / M2），用于逐轮视觉核对。引擎做三件 M1 做不到的事：

| 做法 | 为什么必须这么写 |
|---|---|
| **分层**：扁平插画按「白底 + 半径 0.497 的浅蓝圆盘」合成背景，主体用色差抠出来单独重画 | 不抠图的话头一动，背景圆盘、头发、病号服会一起平移，就是「照片在晃」。抠图在 2 倍分辨率上做，边缘按色差 6→50 羽化，刚好叠回同色背景盘 |
| **位移场**：18×18 切片，逐片求位移后重画 | 切片只平移不旋转：旋转会让相邻切片错开露缝。重叠 4 px（大于相邻片的位移差，小于肉眼可见的重影）。切片源矩形必须同步加同样的 padding，否则每片都在放大自己 |
| **局部重绘**：眨眼=用眼旁实测肤色盖住眼睛 + 眼睑阴影 + 睫毛线；口型=先用嘴上下方真实肤色擦掉原唇线，再按开合度画一张新嘴（口腔暗区/牙/唇线） | 直接拉伸原图会拉出双重嘴唇。原来那条唇线是**微笑弧**，重画必须沿这条弧走（中段比两端低），否则会画成皱眉 |

实测撑得起的效果：眨眼（含双眨）、呼吸起伏、说话时口型跟着音频包络开合、下巴随张口下沉、
绕颈部的头部微转。实测撑不起的：**转头**（单张平面图没有侧脸信息，摆幅只能到 ±1.2°）、**表情变化**
（没法换眉眼神态，只能换立绘）、**逐字口型**（无 viseme，只能用包络近似）。

两条与代码有关的运维事实：

- rig（五官几何）是**数据**，写在 `engine/rig.ts`。立绘换了必须重跑
  `frontend/scripts/extract-rigs.py`（扁平插画按颜色类自动定位，脚本输出的条目可直接贴进 `rig.ts`），
  否则嘴和眼会落在错误位置。写实照片（`realistic/*.png`）是人工标定，脚本不覆盖。
- 写实照片**不进引擎**（2026-10-30 决定）：单张照片抠不出背景，做过的一版只能做「轻微下颌 + 唇缝
  阴影」，观感提升与代码量不成比例，照片继续显示静态图（`engine/rig.ts` 里没有它们的 rig，
  `rigFor()` 返回 null，呈现器自动退回静态图）。

要再往上走只剩两条路，都要新素材或新算力：给每张立绘**分层素材**（头/眼/嘴各自一层，口型可逐字），
或上 GPU 数字人（选项 C/D）。当前引擎没有进生产策略链——`PRESENTATION_CHAIN` 仍是
`realistic → static`，M1/M2 都只在陈列台上看。

## 三、目标 2：患者外放时语音识别把自己说的话也识别进去

### 根因（已确认）

持续对谈要求麦克风常开（否则没有 barge-in），Web Speech 又只给识别结果、不给原始音频，
无法开回声消除。外放场景下患者的声音从扬声器回到麦克风，被当成学生说的话转写并提交。

### 选项

| 方案 | 做法 | 代价 | 保留 barge-in？ |
|---|---|---|---|
| P0 半双工闸门 | 患者出声（`tts:start`）时暂停识别，播完再开 | 最小；学生不能在患者说话时插话 | 否（文字输入仍可） |
| P1 AEC + 本地 VAD | `getUserMedia({echoCancellation:true})` 单独一路做「有人在说话」检测；识别仍用 Web Speech | 中；浏览器回声消除对外放有效但非完美 | 是（检测到人声即停播） |
| P2 换后端流式 ASR | 学生音频走自有 ASR（如火山 BigASR），由我们控制 AEC/静音判句/说话人 | 大；新增 WS 通道、按分钟计费、跨浏览器一致 | 是，且行为统一 |
| P3 提示戴耳机 | 文案约束 | 0 | 是 |

推荐顺序：**P0 止血 → P1 恢复打断 → 视需要 P2**。P0 与 P1 共用「患者是否在出声」这一个状态，
不新增概念；P3 作为兜底提示，不当作解决方案。

### 验收口径（两条目标共用）

- 自听误识别率：外放播 10 句患者台词，转写里出现患者原话的比例（目标 0）。
- 打断延迟：学生开口到停播的毫秒数（P1 目标 <300 ms）。
- 首句延迟不劣化：改造前后同一网络下 TTS 首句到播时间差 ≤200 ms。

## 四、还缺的事实（动手前必须实测）

1. 火山 TTS 流式接口是否返回音素/时间戳（决定 A 与 C 的取舍）。
2. 目标浏览器（Chrome/Edge 版本）上 Web Speech 与 `getUserMedia` 并存时，AEC 是否真的生效
   （用外放 + 固定音频做对照实验，不看文档看波形）。
3. 供应商实时数字人的国内可用性与合规（数据是否出境、是否有境内节点）。
