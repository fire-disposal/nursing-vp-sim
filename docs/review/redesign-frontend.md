# 前端激进重设计（Phase 5-EX）— 业务驱动的新布局体系 + ASR 预留

> 版本：v1（2026-08-15）。基线：master 19730494（Mantine v9 已全量落地）。
> 定位：**核心体验重设计**——不是换皮，是基于业务旅程重构布局思路；全站用 Mantine 重做。
> 硬约束：**新界面体系必须预留 ASR / 自然对答**（导师下一步体验方向），文本与语音走同一语义通道。

---

## 1. 业务旅程（布局的依据，不是美学）

| 角色 | 旅程 | 当前布局问题 |
|---|---|---|
| 学生 | 选病例/作业 → **训练**（对话 + 查体 + 护理记录）→ 结束 → **评分结果** → 回看 | 训练页信息拥挤（面板堆叠）、结果页是"详情页"不是"复盘台" |
| 教师 | 待复核列表 → **逐份复核**（对话回放 + 逐项改分）→ 班级成绩 | 复核工作流散落（列表→详情→复核弹窗），回放与评分不并排 |
| 管理者 | 病例库/作业/用户/成本 | 可保持（管理页非核心体验） |

**核心洞察**：训练页是"对话为轴的沉浸任务"，结果/复核页是"证据为轴的工作台"。两者布局哲学相反——沉浸 vs 并排审阅。新布局体系必须能同时表达这两种范式，而不是统一成一个模板。

## 2. 布局原则（新 layout 思路）

1. **任务优先**：训练页全屏沉浸（无全局导航干扰）；计时器/情绪/患者状态收敛为"环境条"（顶部一条），而非散布角落。
2. **对话为主轴，工具为抽屉**：查体/护理记录从"嵌入式区块"改为"情境抽屉"（桌面右侧滑出 / 移动端底部弹出），对话流始终居中不被挤压。
3. **结果页 = 复盘工作台**：左对话回放（可滚动、证据可跳转），右评分明细（逐项 + fallback 徽标 + 复核编辑），同屏对照。
4. **输入 = 对话通道**（ASR 预留核心）：输入区不是"文本框"，而是"对话通道组件"——文本、语音、未来通话三种来源统一汇入同一条学生消息语义。
5. **布局红线**：无横向滚动条（U1 升级为布局级红线）；任何面板都有移动端降级路径。

## 3. 新 Layout 体系（Mantine 实现）

### 3.1 Shell 层（全站统一）
- 桌面：`AppShell` 左侧栏（可折叠，现状已具备）+ 顶部品牌区 + 内容区 1600 容器约束（现状已具备）——**保留并收敛为唯一规则**；
- 移动端：底部 Tab（现状已具备）——统一为 `AppShell.Footer` 规范；
- 新增强制项：`ScrollArea` 统一滚动策略（`type="hover"`，横向永不出现）。

### 3.2 训练页（沉浸式，全新）
```
┌────────────────────────────────────────────────────────┐
│ 环境条: [←病例] [计时器 25:00] [情绪 4D] [WS状态] [结束] │
├──────────────────────────────┬─────────────────────────┤
│                              │ 情境面板(桌面):          │
│       对话流（居中窄栏）        │  患者信息/体征摘要      │
│       - 患者气泡              │  查体结果              │
│       - 学生气泡              │  护理记录入口          │
│       - 工具结果卡片           │  工具抽屉按钮          │
│                              │  (移动端→底部抽屉)      │
├──────────────────────────────┴─────────────────────────┤
│ 对话通道 ConversationComposer: [文本输入] [🎤语音] [通话] │
└────────────────────────────────────────────────────────┘
```
- 对话流：居中 `max-width: 720px` 沉浸窄栏；工具结果（查体读数/记录保存确认）以"工具卡片"内联进对话流（时序一致）；
- 情境面板：桌面常驻右侧（`hidden on <md`），移动端为 `Sheet` 底部抽屉（`ResponsiveDialog` 复用）；
- 环境条：计时器（D5 硬截止 30 分钟，到期自动交卷已实现）、情绪 4D 微条（U6 在此补真实轨迹入口）、WS 状态点（已实现）。

### 3.3 结果页 = 复盘工作台（全新）
```
┌──────────────────────────────────┬──────────────────────────────┐
│ 头部: [记录信息] [总分大数字]     │ 右侧: 评分明细（滚动）         │
│       [fallback徽标] [复核状态]   │  - 维度折叠列表（逐项 evidence）│
├──────────────────────────────────┤  - 教师复核编辑（内联）         │
│ 左侧: 对话回放                   │  - 情绪轨迹（U6，新）           │
│  - 可滚动完整对话                 │  - 漏问/反馈清单               │
│  - 证据点击 → 高亮对应气泡        │                               │
└──────────────────────────────────┴──────────────────────────────┘
```
- 教师复核页复用同一工作台 + 顶部"待复核"批次列表（去重：`score_review` 已支持）；
- 证据↔气泡联动：评分 evidence 引用对话原文，点击跳转高亮（教学核心价值，当前缺失）。

### 3.4 管理页
保持现有布局（非核心体验），仅统一 shell 规则与新组件。

## 4. ASR / 自然对答预留架构（硬约束）

### 4.1 对话通道抽象（输入层的核心）
```tsx
// ConversationComposer.tsx — 输入区唯一入口，三种模式共用一个语义通道
type ComposerMode = "text" | "voice" | "call";

interface ComposerChannel {
  mode: ComposerMode;
  transcript: string;        // 当前转写/输入文本
  send(text: string): void;  // 唯一出口 → 现有 sendMessage（SSE 管道不变）
  startVoice(): void;        // Web Speech MVP（U2 复活）
  stopVoice(): void;
  enterCallMode(): void;     // 预留：切换到 CallShell（半双工对讲）
}
```
- **语义不变**：无论文本/语音转写/通话转写，最终都是"学生消息文本"→ 现有聊天管道、情绪分析、泄漏守卫、评分全部无感；
- 语音按钮不是装饰：`startVoice()` 接 `webkitSpeechRecognition`，转写进入输入框（MVP），确认后 `send()`；
- 通话模式（未来）：`enterCallMode()` 挂载 `CallShell`（见 refactor-frontend.md §6，与 Mantine 解耦），转写流经 `TranscriptRegion` 确认后 `send()`——同一出口。

### 4.2 后端预留（零侵入）
- 聊天管道不变（`/api/chat/{id}/message/stream` 已接受纯文本）；
- ASR 独立服务层 `infra/asr/`（规划，WebSpeech 不经过后端；volc 流式接入时与 `infra/tts` 同构：circuit/retry/logging 复用）；
- 通话状态机 `CallSession`（规划，复用 simulations 的 wait/clock 语义，实验室轨道 D6）。

### 4.3 验收（ASR 预留的可证明性）
- `ConversationComposer` 三种模式共用 `send(text)` 单一出口（代码级断言）；
- Web Speech MVP：麦克风按钮 → 转写 → 确认 → 进入对话流（当天可验）；
- 通话模式入口存在且切换无损文本模式（不破坏既有输入）。

## 5. 迁移策略（激进但不失控）

1. **先落地 Layout 体系**（Shell 规则 + 布局组件 + ConversationComposer），页面逐批迁移：
   - 批次 A：训练页（最高优先，沉浸式 + 对话通道 + ASR 预留）
   - 批次 B：结果/复核工作台（证据联动 + 情绪轨迹）
   - 批次 C：列表页统一（History/作业/通知——顺带修复 U1 滚动条）
   - 批次 D：管理页只套 shell 规则
2. 新旧布局**路由级并存**：迁移中保留旧路由（`/training-legacy` 等），A/B 完成后移除；
3. 前端 U 类缺陷（U1/U4/U5/U6/U7）**并入重设计实现**，不再单独修补；
4. 不冻结后端工作：布局消费的是已稳定契约（评分双轨/fallback、计时硬截止、工具 HTTP 指令面[Phase 2.5 后]）。

## 6. 执行顺序（与总路线图的关系）

```
Phase 2.5 工具 HTTP 指令面 ──┐
Phase 4 引擎校准            ├→ 契约稳定 → Phase 5-EX 前端重设计（本方案）→ Phase 6 基建
Phase 1/2/3 已完成          ┘
```
- **重设计放最后**：新布局应消费新契约（工具 HTTP 指令面会让训练页交互大幅简化——无 WS pending、查体即请求即响应），先改后端再改前端，避免双端同时漂移（总纲 P6）。
