## 一、仍适用的维护约束

- 查询/导出复用同一筛选源；前后端不要分别计算同一过滤含义。既有范式见 [UI 维护记录 §6.4](ui-improvement-plan-2026-09-26.md)。
- 排序引用关联表时明确 SQL 来源，不依赖 `joinedload` 生成的内部别名。回归覆盖用户可见的排序、范围与身份行为，不只验证代码文本。
- 使用现有 Mantine 主题、FilterToolbar、字段 label 与弹窗档次；新增训练界面复用约定，不全面翻修外围页面。
- 缺陷保留修前/修后判据；最终运行真实路径，不能以静态查询编译或单测通过替代用户验收。
- 审计用于规范化与科研关联，保留“业务事实 + 结构化事件”的边界，不再开启合规平台建设。

## 二、已定取舍

| 主题 | 决定 |
|---|---|
| 账号级登录失败锁定 | 代码保留、默认关闭；不以用错密码阻断正常体验。具体行为以当前配置和实现为准 |
| 审计保存 | 保留期与归档动作按[现行规程](../ops/audit-log-retention.md)；不以旧分区/detach 设计指挥当前普通表 |
| 备份验证 | 包含表数据与完成恢复演练是两件事；未演练不能宣称已通过 |
| 权限与指标 | 沿用已裁定权限边界；本文件不重新授权给指标端点加鉴权 |
| 外围 UI | 仅在 19 实际触及或维护者明确提出时修复；不按旧优先级自动扩张 |
| 发版 | tag 会自动部署；仍须维护者授权。当前文档工作不提交、不推送、不发布 |
