# 训练体验调查：现存断点与实施归属

> 调查日期：2026-09-27；本次收敛为证据记录，不再保留 TX/D 竞争路线、待拍板清单或资源配额方案。
> 唯一实施计划：[19](../19-training-experience-next-generation-plan.md)。临床推理去向：[18](../18-clinical-reasoning-disposition.md)。本文件不代表缺陷已修复。

## 一、调查边界

证据来自代码核验、先前本地临时库/API 观察、浏览器记录，以及本次本地评分标准渲染和线上只读评分元数据查询。各类证据不能互相替代：

- 真实 LLM 评分、患者情绪效果、多 worker 下评分进度、音频与断网全链未完成端到端验证。
- 早期前端验证 harness 曾忽略上游参数而读取生产 API；不能把那批前端观察写成本地数据库验证。该陷阱与本次使用只读事务的 SSH 查询分别记录。
- 当前文档操作没有修改任何业务代码、配置、数据库或历史成绩，也没有发布。

## 二、核心断点

| ID | 观察与证据 | 验证边界 | 实施归属 |
|---|---|---|---|
| E1 学生复核不可见 | `frontend/src/pages/RecordDetail.tsx` 向评分区传 `isReviewed=false`、空复核对象；服务端已提供复核字段。可能显示复核总分却仍标 AI 初评，教师意见未到达学生 | 调用点与渲染逻辑证据；后续以真实学生/教师回路验收 | W1、W5 |
| E2 评分等待/重试语义混淆 | 详情缺少 pending 定时查询；`ScoringPendingBanner` 的“刷新”走重评分命令；`useScoringRetry` 轮询上限与后台等待边界不一致；`ScoreManager` 有合成百分比 | 代码证据；多进程进度缺失是配置与内存状态推断，未实跑真实评分证明频率 | W1 |
| E3 学生自视图权限错位 | `TrainingSelect` 从 `getStudentRanking({limit:200})` 中取自己；端点要求 `stats_view`，默认学生无此权限。本地学生 API 实测 403 | 本地角色/API 已观察；不能因取不到排名就推断学生没有训练 | W1、W5 |
| E4 暂离承诺与请求不一致 | `TrainingEntry` 使用不能附带 Authorization 的 `sendBeacon` 访问受 Bearer 保护的 pause 端点 | 静态证据；必须结合不同训练模式真实刷新/离页验收 | W1 |
| E5 状态与故障归因不准 | WS 中断提示工具不可用，但工具走 HTTP、聊天走 SSE；桌面产物状态主要藏在 tooltip；训练壳缺少明确离线提示 | 代码与界面证据；真实断网恢复尚未完整验证 | W1、W3 |
| E6 保存回执与语音降级不诚实 | `NursingDiagnosisTool` 以定时器切“已保存”，不依据服务端回执；TTS 降级事件未被 UI 消费，浏览器回退失败存在未捕获路径 | 静态证据；当前无病例声明护理诊断时属于潜在路径，不能声称全部学生正在丢数据 | W1 |
| E7 反馈未形成再练习路径 | 结果已有维度明细与证据跳转，但建议为自由文本；缺少与明确目标关联的同例纠正/变式迁移入口 | 现有产品结构证据；不是“只有分数、完全没有反馈” | W2、W4、W5 |
| E8 复核判据与降级可读性 | 教师逐项复核成本高，相关复核响应的降级来源表达不足；学生收到的结果需明确 AI/教师来源 | 代码证据；不据此另建批量采纳 AI 平台 | W4、W5 |

路径入口与后续改动地图统一维护在 19 第五节；不再复制另一份文件改造清单。

## 三、评分问题：事实与假设分开

### 已确认

- 维护者报告历史学生从未拿过优秀、判例偏严、硬编码数字分等第有问题；作为校准工作输入，不重复检查该现象是否存在。
- `scoring/rubric.json` 已含追问、澄清、避免重复、共情等锚点。不能说它只评清单覆盖。
- 实际运行本地 `build_scoring_criteria()`：基础 rubric 有 57 条 anchors，生成文本出现 0 条；header 写每项 1–2，判分实际为 0–2。锚点存在不等于送入模型。
- `prompts/scoring.py` 强制至少两条不足和两条漏问；“无不足”的真实结果无法按该指令自然表达。
- 当前线性展示映射只是算术规则。原始条目换算取整、均分 85/60 分层、不同界面的数值颜色不能共同构成经过教师校准的能力等第。
- 本次只读部署查询发现同一 `nursing_history_v1@1.0` 横跨 57/72 分且每项 3 分、48 分且每项 2 分等历史标度。聚合范围、匿名判例、部署版本与局限见 [19 第二节](../19-training-experience-next-generation-plan.md#二现状证据与尚未成立的结论)。不保存身份与对话全文。

### 尚未成立

- 无证据证明“背模板必然最优”或“患者完全不受沟通影响”。患者已有情绪/行为/主动追问机制，但教学有效性未验证。
- 本地锚点渲染缺口不是所有历史评分偏严的完整因果证明；部署版本与本地版本也不能等同。
- 相同 rubric 标识不是相同量尺的证明；不同量尺转成百分制也不自动可比。
- 教师判例、留出验证、重复评分稳定性尚未完成，不能声称评分已可靠，只差 UI 接线。

评分校准正式归入 19 的 **W0/W4**，不以提高优秀比例为目标，不静默重算历史成绩。

## 四、保留的设计边界

- 引导模式提供领域提示和必要覆盖提醒是教学脚手架，不应作为缺陷一删了之。
- 病例修订、记录快照、manifest、服务端完成政策与工具动作是可复用地基，不因此新增通用平台。
- 已提交产物、草稿、系统终局与评分依据必须区分；不能把运行态中的内容顺手当作已提交证据。
- 临床推理不仅是目录投影和接线；作者、学生工作区、评分、教师复核、校准和维护均有独立成本，去向由18裁定。
- 外围 UI 问题仅在19的训练闭环实际触及时处理；不另开全站重设计、时间配额或多模态扩张路线。
