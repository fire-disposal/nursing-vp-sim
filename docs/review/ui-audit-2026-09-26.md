## P0

### UI-DS-1 深色模式半坏：浅色字面量遍布全仓
- **证据**：`components/ui/data-table.tsx:86` `background: "var(--mantine-color-gray-0)"` —— 深色模式下实测表头 `th` 为 `rgb(248,249,250)` 配 `rgb(148,163,184)` 文字（≈2.4:1），即深色页面上一条白表头条（`/admin/classes` 实测）。同类硬编码：`pages/TrainingSelect.tsx:528` `bg="yellow.0"`、`:534` `c="yellow.8"`（首页"进行中的训练"整行黄底，深色下发灰刺眼）、`pages/MyFeedback.tsx:78-99` `bg="blue.1"/"gray.1"`、`pages/QA.tsx:311`、`components/ui/loading-skeleton.tsx` 与 `error-display.tsx` 的 `c="gray.8"`（深色下深字压深底）。静态扫描：约 63 个文件使用 `gray.0/1/3`、`yellow.0`、`blue.1` 一类浅色字面量。
- **影响**：深色模式下表格、统计卡、空态、进行中标示大面积不可读；用户无法判断是"没加载"还是"样式坏了"。
- **闭环**：把这些字面量替换为语义 token（`--mantine-color-default-border`、`body`、`light`、`-light-color` 系列）；`gray-0` 表头改用 `--mantine-color-default` 或 `light` 变量的深色自适应值；补齐深色视觉回归（至少覆盖 DataTable、StatCard、EmptyState、训练首页进行中态）。
- **成本**：M

### UI-DS-2 主题切换默认不可发现，且首次点击是空操作
- **证据**：`main.tsx:21` `defaultColorScheme="light"` —— 全站默认亮色；`components/ui/mode-toggle.tsx:14,26` 只在挂载时读一次 `localStorage`，`mode` 是本地影子状态，与 `useMantineColorScheme()` 实际值不同步。实测（`/admin`，清空 localStorage 后刷新）：初始 `data-mantine-color-scheme=light`、localStorage 为空、按钮 `aria-label="跟随系统"`；点击一次后 → `light`（**画面无任何变化**）、localStorage 写为 `light`、`aria-label` 仍为"跟随系统"。
- **影响**：① 深色主题对绝大多数用户不可发现（默认亮色且入口只在个人中心/头部图标）；② 第一次点击无反馈，用户判定"按钮坏了"；③ 无障碍名与实际主题状态长期不一致。
- **闭环**：`defaultColorScheme="auto"`（或删除深色入口、不留半套）；`ModeToggle` 改为受控：图标与 `aria-label` 直接来自 `colorScheme`，去掉本地 `mode`；必要时在头部加"亮/暗"文本提示。
- **成本**：S

### UI-TRN-1 「结束训练」按钮：桌面端没有文字、没有可访问名，且文案指向不存在的标签
- **证据**：`components/training/TrainingHeader.tsx:219` `<Text component="span" hiddenFrom="xs">` —— Mantine 的 `hiddenFrom` 是"**该断点及以上隐藏**"，语义写反。实测：视口 1408px 时按钮 `52×36`、`innerText=""`、`aria-label=null`，仅有 `title="查看完成条件"`；视口缩到 484px 时才出现文字"结束训练"（按钮 117px 宽）。同处 `:216` `title={canComplete ? "结束训练并查看评分" : "查看完成条件"}`、`:212` 阻塞态用 `color="red"` 变体：**同一按钮在"可交卷/被阻塞"两态间切换外观与语义，全靠 `title` 承载**，触屏无从得知。引导文案（`components/training/WelcomeScreen.tsx`）写的是"点击右上角"结束训练"提交评分"，而桌面端根本没有那个字样。
- **影响**：训练流程的唯一出口在桌面端表现为一个无标签图标，学生找不到交卷入口；读屏用户拿到的是无名按钮。
- **闭环**：改为 `visibleFrom="xs"`（桌面本就放得下，建议两态都常显"结束训练"）；阻塞态改用 `variant="light"` + 常驻说明文案，不把状态语义塞进 `title`；WelcomeScreen 文案与控件保持一致。
- **成本**：S

### UI-A11Y-1 次级文字与品牌色系统性不达 WCAG AA
- **证据**：`--mantine-color-dimmed` = gray.6 `#868e96`，白底实测 **3.32:1**；品牌绿 `#2c9a82` 的白字（按钮）与白底绿字（如"下午好，学生1"）实测 **3.47:1**；均低于 4.5:1，而命中文本多为 11–14px 正文级字号。逐页命中数见上表（`/admin/records` 365、`/admin/stats` 343、`/admin/users` 298）。典型：页头副标题、表格时间/时长、`共 N 条`、导航项描述、顶部版本号 `v2026.09.26-3`（11px dimmed 且是个按钮）。
- **影响**：教室投影/机房低亮度屏幕下大量说明文字不可读；这也是"整站发灰"观感的第一来源。
- **闭环**：dimmed → gray.7 `#495057`（7.0:1）；品牌色文字态改 `brand.7`；字号 <12px 的说明文字一并抬到 ≥12px；把该口径写进 theme 而不是逐页调。
- **成本**：S

### UI-ADM-1 管理端仪表盘指标失真，且动态流无日期导致自相矛盾
- **证据**：`pages/admin/dashboard/TeachingDashboard.tsx:29-30` 拉 `getRecords({ limit: 10 })`，`:44-60` 在这 10 条上 `filter` 出"今日活跃学生/今日训练次数（另取后端 `stats.today_records`）/本周完成率/待批阅"，`:67` 动态时间只用 `toLocaleTimeString` **不带日期**。线上实测（`/admin`，2026-09-26 18:0x）：动态流显示 `15:12 王雪菲 完成了 …50分`、`11:40 …开始了训练`，而卡片"今日活跃学生 0""今日训练次数 0"；`本周训练完成率 13%（7/53 人）` 的分子受 `limit:10` 封顶，与 `/admin/records` 同屏可见的 `481 筛选结果 / 39 已完成` 直接矛盾。
- **影响**：教师端首页是决策入口，却给出系统性偏小、且与自身动态流冲突的数字；动态流不显示日期会让人把 9/24 的事件读成"今天"。
- **闭环**：后端补聚合（`today_records`、`today_active_students`、`pending_review`、`completed_week` 真实计数），前端不再从列表窗口推导；动态流按日期分组或直接显示 `MM-DD HH:mm`。
- **成本**：M

### UI-ADM-2 作业列表静默截断，筛选作用于截断集合
- **证据**：`pages/admin/AssignmentsPage.tsx:119` `const params = { limit: 100 }` 且未向 `ResponsiveTable` 传 `total/offset/onOffsetChange` → 不渲染分页、无"共 N 条"。搜索/筛选在客户端对已截断的 100 条做过滤。
- **影响**：作业超过 100 条后列表静默丢失尾部；搜索会给出"暂无作业"的**假阴性**结论 —— 教师据此误判"没建过这个作业"。
- **闭环**：接入服务端分页（接口已支持），或至少在截断时显示"仅显示前 100 条"；客户端筛选改为服务端筛选。
- **成本**：S–M

### UI-ADM-3 `/admin/stats` 有权限、无入口
- **证据**：`components/shell/navigation.tsx:144` `{ path: "/admin/stats", element: <StatsPage />, permission: "stats_view", activity: "manage" }` —— 无 `nav` 字段；全仓检索 `/admin/stats` 无任何链接/跳转；`stats_view` 授予 `super_admin`/`admin`/`teacher`。
- **影响**：整块教师统计页（学生训练量、得分趋势、班级对比）对用户不可达，只能手输 URL；与"成绩管理"职责重叠但无人知道以谁为准。
- **闭环**：加 nav 项并厘清与 `ScoreboardPage` 的分工（合并或明确"统计 vs 排名"），否则删除该页。
- **成本**：S

### UI-NAV-1 导航标签与页面标题不一致（4 处）

- **闭环**：一个实体一个名词，nav 标签直接取页面标题（或反过来）。

### UI-NAV-2 分组语义与顺序不自洽
- **证据**：`navigation.tsx:299` `用户反馈` 归入 `system` 组（与运维仪表盘、系统通知同组）；`navigation.tsx:232` `教学看板` 是 `/admin` 的落地页，却排在"教学"组第 4 位（`病例库/作业管理/成绩管理/教学看板/训练记录/问卷管理/评分标准`）；对 `teacher` 角色（`backend/core/roles.py`）"人员"与"系统"两组各只剩 1 项。
- **影响**：教师按"我想看反馈"去找，会落在系统组里只有一个无关项；组内首个条目不是该组代表页。
- **闭环**：把"用户反馈"移到教学/运营组；组首放落地页；单项目组退化为平铺项。
- **成本**：S

### UI-NAV-3 折叠组只在挂载时展开，深链后当前位置不可见
- **证据**：`components/shell/SidebarNav.tsx:51` `defaultOpened={group.defaultOpen || hasActive}`（`defaultOpen` 对"人员/系统"为 `false`，"教学"为 `true`）。`defaultOpened` 仅首次挂载生效。
- **影响**：从页面卡片跳到"成本管理"、或刷新到非默认组页面时，组是收起的，当前项不可见，用户失去方位感与返回路径。
- **闭环**：受控 `opened = hasActive || userToggled`，`hasActive` 变真时自动展开，并按组持久化用户手动开合。
- **成本**：S

### UI-NAV-4 图标复用，收起侧栏后图标成为唯一线索
- **证据**：`navigation.tsx:88` 教学组头 `IconSchool` 与 `:187` 班级管理同图标；`:89` 人员组头 `IconUsers` 与 `:167` 用户管理同图标；`:137` 记录 / `:201` 作业管理 / `:261` 问卷管理同用 `IconClipboardList`。
- **影响**：侧栏收起态（实测存在"折叠侧边栏"按钮）下，图标无法区分目标；组头与组内项视觉同形。
- **闭环**：组头与条目图标去重（`IconUsersGroup`/`IconUserCog`/`IconClipboardCheck` …），并加一条"无重复图标"的断言测试。
- **成本**：S

### UI-NAV-5 无权限访问静默重定向
- **证据**：实测以 `student1` 直接访问 `/admin/records` → 落在 `/training`，无任何提示；全站唯一兜底是 `App.tsx` 的 `*` → `/login`。
- **影响**：用户以为"点了没反应"或"页面跳错了"，无法区分是权限问题还是故障。
- **闭环**：`RequirePermission` 失败时渲染 403 说明页（含"返回首页"），而非静默替换目标。
- **成本**：S

### UI-TRN-2 训练页工具轨与关键控件过小、无文字
- **证据**：右侧工具轨三个按钮实测 `36×36` 纯图标（无文字、无 label 说明，只有一个带角标）；"清单 0/14" 按钮 `91×18`（11px dimmed 文字）；阻塞提示里的"去处理" `53×22`。
- **影响**：训练主场景（触屏/机房鼠标）里的高频操作低于 24×24 触控下限；图标语义靠猜。
- **闭环**：工具轨 ≥44×44 并加文字或 tooltip + `aria-label`；"清单"与"去处理"提到 ≥32px 高并提高对比度。
- **成本**：S

### UI-TRN-3 训练页信息密度失衡（左栏大面积空白 + 过大头像）
- **证据**：`/training/605` 实测：`aside` 280×836，患者头像约占面板 40%，其下 ~350px 为空；主区单条患者气泡下方也有大段空白。

- **成本**：M

### UI-STU-1 训练首页同一指标出现两种口径
