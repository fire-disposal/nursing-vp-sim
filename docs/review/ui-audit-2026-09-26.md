## P0

### UI-DS-1 深色模式半坏：浅色字面量遍布全仓
- **证据**：`components/ui/data-table.tsx:86` `background: "var(--mantine-color-gray-0)"` —— 深色模式下实测表头 `th` 为 `rgb(248,249,250)` 配 `rgb(148,163,184)` 文字（≈2.4:1），即深色页面上一条白表头条（`/admin/classes` 实测）。同类硬编码：`pages/TrainingSelect.tsx:528` `bg="yellow.0"`、`:534` `c="yellow.8"`（首页"进行中的训练"整行黄底，深色下发灰刺眼）、`pages/MyFeedback.tsx:78-99` `bg="blue.1"/"gray.1"`、`pages/QA.tsx:311`、`components/ui/loading-skeleton.tsx` 与 `error-display.tsx` 的 `c="gray.8"`（深色下深字压深底）。静态扫描：约 63 个文件使用 `gray.0/1/3`、`yellow.0`、`blue.1` 一类浅色字面量。
- **影响**：深色模式下表格、统计卡、空态、进行中标示大面积不可读；用户无法判断是"没加载"还是"样式坏了"。
- **闭环**：把这些字面量替换为语义 token（`--mantine-color-default-border`、`body`、`light`、`-light-color` 系列）；`gray-0` 表头改用 `--mantine-color-default` 或 `light` 变量的深色自适应值；补齐深色视觉回归（至少覆盖 DataTable、StatCard、EmptyState、训练首页进行中态）。
- **成本**：M

### UI-DS-2 主题切换默认不可发现，且首次点击是空操作**【已处置 · Q3】**
- **处置**：`ModeToggle` 去本地影子状态，图标与 `aria-label` 取自 `useMantineColorScheme().colorScheme`。实测后值：首点 `light → dark` 生效、aria 同步。
- **证据**：`main.tsx:21` `defaultColorScheme="light"` —— 全站默认亮色；`components/ui/mode-toggle.tsx:14,26` 只在挂载时读一次 `localStorage`，`mode` 是本地影子状态，与 `useMantineColorScheme()` 实际值不同步。实测（`/admin`，清空 localStorage 后刷新）：初始 `data-mantine-color-scheme=light`、localStorage 为空、按钮 `aria-label="跟随系统"`；点击一次后 → `light`（**画面无任何变化**）、localStorage 写为 `light`、`aria-label` 仍为"跟随系统"。
- **影响**：① 深色主题对绝大多数用户不可发现（默认亮色且入口只在个人中心/头部图标）；② 第一次点击无反馈，用户判定"按钮坏了"；③ 无障碍名与实际主题状态长期不一致。
- **闭环**：`defaultColorScheme="auto"`（或删除深色入口、不留半套）；`ModeToggle` 改为受控：图标与 `aria-label` 直接来自 `colorScheme`，去掉本地 `mode`；必要时在头部加"亮/暗"文本提示。
- **成本**：S

### UI-TRN-1 「结束训练」按钮：桌面端没有文字、没有可访问名，且文案指向不存在的标签**【已处置 · Q2】**
- **处置**：标签常显（去 `hiddenFrom="xs"`），可见文案与 `aria-label` 共用同一变量。实测后值：1408/484 两视口 `innerText=结束训练`、`aria=结束训练，完成条件尚未满足`；红色 4.52:1（曾试橙色 3.62:1 不合规，已回退）。
- **证据**：`components/training/TrainingHeader.tsx:219` `<Text component="span" hiddenFrom="xs">` —— Mantine 的 `hiddenFrom` 是"**该断点及以上隐藏**"，语义写反。实测：视口 1408px 时按钮 `52×36`、`innerText=""`、`aria-label=null`，仅有 `title="查看完成条件"`；视口缩到 484px 时才出现文字"结束训练"（按钮 117px 宽）。同处 `:216` `title={canComplete ? "结束训练并查看评分" : "查看完成条件"}`、`:212` 阻塞态用 `color="red"` 变体：**同一按钮在"可交卷/被阻塞"两态间切换外观与语义，全靠 `title` 承载**，触屏无从得知。引导文案（`components/training/WelcomeScreen.tsx`）写的是"点击右上角"结束训练"提交评分"，而桌面端根本没有那个字样。
- **影响**：训练流程的唯一出口在桌面端表现为一个无标签图标，学生找不到交卷入口；读屏用户拿到的是无名按钮。
- **闭环**：改为 `visibleFrom="xs"`（桌面本就放得下，建议两态都常显"结束训练"）；阻塞态改用 `variant="light"` + 常驻说明文案，不把状态语义塞进 `title`；WelcomeScreen 文案与控件保持一致。
- **成本**：S

### UI-A11Y-1 次级文字与品牌色系统性不达 WCAG AA**【部分处置 · Q4，残留转 Q5】**
- **补充发现（2026-09-26 升级期）**：`variant="outline"` 的文字色取 `--mantine-color-{c}-filled`（= `primaryShade`，浅色 7 档），蓝/红系在白底仅 4.2–4.4:1（实测 `/admin/users` 班级 chip 45 处命中，**Q5 的 light/text token 覆盖不到这条路径**）。已按调用点修复（chip 改 `default`、红色危险按钮改 `light`），实测该页 45 → 0。
- **处置**：`cssVariablesResolver` 按浅/深分别给 `--mantine-color-dimmed`（浅色 gray-6 → gray-7）；`primaryShade.light` 6 → 7。实测后值：`/admin/records` 365 → **112**、`/admin/users` 298 → **91**、`/training` 18 → **0**；剩余为 11px 徽章与 16px `blue-7` 数字（见计划 Q5）。
- **证据**：`--mantine-color-dimmed` = gray.6 `#868e96`，白底实测 **3.32:1**；品牌绿 `#2c9a82` 的白字（按钮）与白底绿字（如"下午好，学生1"）实测 **3.47:1**；均低于 4.5:1，而命中文本多为 11–14px 正文级字号。逐页命中数见上表（`/admin/records` 365、`/admin/stats` 343、`/admin/users` 298）。典型：页头副标题、表格时间/时长、`共 N 条`、导航项描述、顶部版本号 `v2026.09.26-3`（11px dimmed 且是个按钮）。
- **影响**：教室投影/机房低亮度屏幕下大量说明文字不可读；这也是"整站发灰"观感的第一来源。
- **闭环**：dimmed → gray.7 `#495057`（7.0:1）；品牌色文字态改 `brand.7`；字号 <12px 的说明文字一并抬到 ≥12px；把该口径写进 theme 而不是逐页调。
- **成本**：S

### UI-ADM-1 管理端仪表盘指标失真，且动态流无日期导致自相矛盾
- **证据**：`pages/admin/dashboard/TeachingDashboard.tsx:29-30` 拉 `getRecords({ limit: 10 })`，`:44-60` 在这 10 条上 `filter` 出"今日活跃学生/今日训练次数（另取后端 `stats.today_records`）/本周完成率/待批阅"，`:67` 动态时间只用 `toLocaleTimeString` **不带日期**。线上实测（`/admin`，2026-09-26 18:0x）：动态流显示 `15:12 王雪菲 完成了 …50分`、`11:40 …开始了训练`，而卡片"今日活跃学生 0""今日训练次数 0"；`本周训练完成率 13%（7/53 人）` 的分子受 `limit:10` 封顶，与 `/admin/records` 同屏可见的 `481 筛选结果 / 39 已完成` 直接矛盾。
- **影响**：教师端首页是决策入口，却给出系统性偏小、且与自身动态流冲突的数字；动态流不显示日期会让人把 9/24 的事件读成"今天"。
- **闭环**：后端补聚合（`today_records`、`today_active_students`、`pending_review`、`completed_week` 真实计数），前端不再从列表窗口推导；动态流按日期分组或直接显示 `MM-DD HH:mm`。
- **成本**：M

### UI-ADM-2 作业列表静默截断，筛选作用于截断集合
- **证据**：`pages/admin/AssignmentsPage.tsx:119` `const params = { limit: 100 }` 且未向 `ResponsiveTable` 传 `total/offset/onOffsetChange` → 不渲染分页、无"共 N 条"。搜索/筛选在客户端对已截断的 100 条做过滤。
- **影响**：作业超过 100 条后列表静默丢失尾部；搜索会给出"暂无作业"的**假阴性**结论 —— 教师据此误判"没建过这个作业"。
- **闭环**：接入服务端分页（接口已支持），或至少在截断时显示"仅显示前 100 条"；客户端筛选改为服务端筛选。
- **成本**：S–M

### UI-ADM-3 `/admin/stats` 有权限、无入口

- **成本**：S

### UI-NAV-2 分组语义与顺序不自洽
- **证据**：`navigation.tsx:299` `用户反馈` 归入 `system` 组（与运维仪表盘、系统通知同组）；`navigation.tsx:232` `教学看板` 是 `/admin` 的落地页，却排在"教学"组第 4 位（`病例库/作业管理/成绩管理/教学看板/训练记录/问卷管理/评分标准`）；对 `teacher` 角色（`backend/core/roles.py`）"人员"与"系统"两组各只剩 1 项。
- **影响**：教师按"我想看反馈"去找，会落在系统组里只有一个无关项；组内首个条目不是该组代表页。
- **闭环**：把"用户反馈"移到教学/运营组；组首放落地页；单项目组退化为平铺项。
- **成本**：S

### UI-NAV-3 折叠组只在挂载时展开，深链后当前位置不可见
- **证据**：`components/shell/SidebarNav.tsx:51` `defaultOpened={group.defaultOpen || hasActive}`（`defaultOpen` 对"人员/系统"为 `false`，"教学"为 `true`）。`defaultOpened` 仅首次挂载生效。
- **影响**：从页面卡片跳到"成本管理"、或刷新到非默认组页面时，组是收起的，当前项不可见，用户失去方位感与返回路径。
- **闭环**：受控 `opened = hasActive || userToggled`，`hasActive` 变真时自动展开，并按组持久化用户手动开合。
- **成本**：S

- **空态卡不是"孤卡"**：`/training` "待完成作业"与右卡并排时的高度差是 `align` 拉伸留白（UI-LAY-4），不是容器声明错误。
- **深色下批量条等 `fixed` 元素在页头/侧栏层不受影响**：`AppShell.Header/Navbar/Footer` 是 `main` 的兄弟节点，不在 `ShellTransition` 的 `will-change` 容器内（受影响的只有 `main` 之内的悬浮元素，实测仅批量条一例）。

### 与静态审计的分歧（以实测为准）
1. **`TrainingHeader` 标签方向**：静态审计判为"手机上隐藏标签"，实测**相反** —— `hiddenFrom="xs"` 使标签在 ≥576px 隐藏、<576px 显示；缺失的可访问名只发生在桌面（移动端有文字名）。修法因此是 `visibleFrom="xs"`。
2. **"管理后台建议使用桌面端访问以获得完整体验"**：静态审计当作 banner，实测是**一次性 toast**（截图不显示、探针文本中存在），意味着移动端管理员没有持久提示。
3. **`FilterToolbar` 消费者数**：已核实仅 `History.tsx:134` 一处（见 UI-ADM-5）。
4. **"UsersTab 有删除用户"**：本轮静态审计曾认定为有，复核不成立 —— `_handleDeleteUser`（`UsersTab.tsx:306`）全仓无调用者，删除入口实际不可达（见 UI-CRD-1）。
5. **"第一行 2 卡 + 第三张孤零零"**：47 处网格中仅 3 处固定项数必然缺格，多数为数据驱动末行或"3 塞 4 列"（见 UI-LAY-3）；观感成因与初始判断不同，修法也不同。

### UI-LAY-1 批量操作条被祖先 `will-change` 挡在视口外（P0）**【已处置 · Q1】**
- **处置**：`ShellTransition` 去掉常驻 `will-change`（附防回潮注释）；批量条改用 Mantine `Affix`（Portal 到 body）。实测后值：`top=798 / bottom=868`（视口 884，原 2616）。
- **证据**：`components/shell/ShellTransition.tsx:21` 给每个页面的内容包裹层设 `style={{ willChange: "opacity, transform" }}` → 该元素成为 `position: fixed` 后代的包含块；`components/admin/users/BatchActionBar.tsx:28` 声明 `position: fixed; bottom: 16px; zIndex: 40`。线上实测（选中 1 名用户后）：`barTop=2616px`、`innerHeight=884`、`visibleOnScreen=false`、`cssPosition=fixed`、`cssBottom=16px`；祖先链实测 `DIV[style="will-change: opacity, transform; opacity: 1; transform: none;"]` → `div(max-width: calc(100rem …))` → `main.mantine-AppShell-main` → `div.mantine-AppShell-root`。
- **影响**：勾选后屏幕上没有任何可见反馈（唯一变化是复选框打勾）；"已选 1 人 / 添加到班级 / 从班级移除 / 批量重置密码"必须滚过 50 张卡片才出现 —— 批量功能事实上不可用。
- **闭环**：去掉内联 `willChange`（或只在过渡进行时通过 class 开启）；批量条改用 Mantine `Portal`/`Affix`（`<Affix position={{ bottom: 16 }}>`）。同坑位风险：`showcase/components/VideoModal.tsx:34`（同在页面内容层内）。
- **成本**：S

### UI-LAY-2 双列网格只挂 1 个子项，右半永久空白（P1）
- **证据**：`pages/TrainingSelect.tsx:586` `cols={{ base: 1, xl: 2 }}`，网格内只有 1 个子项 → ≥1408px 时右半列无内容（静态审计唯一确定性网格 bug）。

### UI-LAY-3 固定列数 + 固定项数导致末行缺格（P1）
静态枚举 47 处网格容器，其中**仅 3 处**是"固定项数必然缺格"：`components/admin/cases/FormView.tsx:34`（`cols={{base:1,sm:2}}` 放 3 个字段 → sm 下末行 1 项占半行）、`pages/admin/RolesPage.tsx:232`（静态 `cols={3}` 放 14 项 → 末行缺 1，且无移动回退）、`components/admin/scoreboard/StudentTrendDialog.tsx:186`（`cols={{base:2,sm:5}}` 放 5 项 → <768px 末行 1 项）。
线上实测另有四类更刺眼的形态：
- **3 塞 4 列**：`pages/admin/cost/CostDashboard.tsx:53` 3 张 StatCard 放 `lg:4` 网格 → `/admin/costs` 实测容器 `cols=4 / 子项=3`（右侧空一格）。
- **筛选区末格不齐**：`/admin/records` 筛选区 `cols=4` 放 8 项，算术满格，但第 8 格是"排除试跑 + 清除过滤"（无标签）→ 实测 `top=259` vs 同行邻居 `236`、`h=36` vs `59`，同行内高度/基线不一致（用外边距手调对齐的痕迹）。
- **数据驱动末行**：`components/admin/UsersTab.tsx:409` `lg:3` 网格取每页 50 条 → `/admin/users` 实测形状 `[3,3,…,3,2]`（末行 2 项、缺 1），且缺格数随 total % 3 变化。
- **注意探针口径**：`/admin/records` 的筛选网格在探针里报 `[4,3,1]`，其中"1"不是独立一行，而是第 8 格（无标签控件）比同行下移 23px 被分到另一组 —— 与上一条是同一现象。
- **结论（对维护者观感的修正）**：主统计条多为 4 项/4 列满格（`/admin` 实测 4/4 与 3/3 均满、`/training` 首页 2/2、3/3 满），"到处都缺一张"的观感主要来自上述 3 塞 4 列、数据驱动末行与筛选区末格不齐三处，而非普遍存在的 2+1 布局。
- **闭环（Mantine 原生）**：`SimpleGrid` 用响应式 `cols={{ base: 1, sm: 2, lg: 3 }}` 并让项数按档位设计；刚好 3 项用 `cols={{ base: 1, sm: 3 }}`；"主 + 次"不成对时用 `Grid` + `Grid.Col span`；筛选区末格改用 `Group align="flex-end"`，或把"排除试跑/清除过滤"移出网格、放到筛选行之外的工具栏。
- **成本**：S–M

### UI-MAN-1 Mantine 原生对齐路线（整改主线，P1）
**现状（实测）**：`components/ui/*` 20 个组件全部基于 `@mantine/core`（**无 radix / 无 tailwind 依赖**）；`theme/index.ts` 已集中 8 个组件的 `defaultProps`（Button/ActionIcon/Badge/Modal/Notification/Tooltip/Card/Paper/Table），但页面仍大量内联外观与自研替代品。

**选型依据（2026-08-13 ADR，迁移已完成，该 ADR 于 2026-09-26 删除；正文见 git 历史）**：用一套 Mantine 取代当时并存的三套范式（Tailwind 工具类 + shadcn 风格自建原语 + `next-themes`/`sonner`/`cmdk`/`cva` 等冗余依赖），目标是依赖精简与按需分包、并利用 Mantine 的 CSS 变量/style props/内置暗色与 `@mantine/hooks|form|notifications|modals|spotlight` 生态。**边界：不做逐像素还原，只要求整体观感与一致性到位** —— 本路线应遵守同一边界。

**五步对齐（按性价比）**：
1. **默认值全部收进 theme**：补齐 `Paper/Table/Tabs/Select/TextInput/PasswordInput/Checkbox/Modal/Drawer/Pagination/SimpleGrid/Tooltip` 的 `defaultProps`；页面 `style={{}}` 中属于外观（背景/边框/圆角/间距/阴影）的部分迁回 theme 或 Mantine props —— UI-DS-3（半径/字号/图标无比例尺）、UI-NEST-2（面板策略不一）由此一次性收敛。
2. **`cssVariablesResolver` 定义深色安全语义变量**：替代 `gray.0/1/3`、`yellow.0`、`blue.1` 等字面量（UI-DS-1），这是 Mantine 官方的深色模式通路，不必逐文件改色。
3. **用原生组件替换自研**：底部面板 `bottomsheet.tsx` → `Drawer position="bottom"`（自带 `role="dialog"`/焦点陷阱/Escape/滚动锁，见 UI-DS-4）；行内图标按钮 → `ActionIcon` + `aria-label`（`title` 只作补充，见 UI-ADM-6/UI-A11Y-4）；宽表 → `Table.ScrollContainer`（修 UI-ADM-4 的整页横滚）；悬浮条 → `Affix`（修 UI-LAY-1）；分页 → Mantine `Pagination`（统一尺寸与 a11y）；确认弹窗 → `modals.openConfirmModal`（替代自研 `confirm.tsx`，20 个调用点）；日期输入 → `@mantine/dates` 的 `DatePickerInput`（当前是原生 `<input type="date">`，占位形态随浏览器 locale 变化，见 UI-ADM-5 与更正）。
4. **布局用语义件**：`SimpleGrid cols={{…}} align`、`Grid`+`Grid.Col span`、`Stack`/`Group` gap 取代内联 flex 与 `calc()` 魔法高度（`pages/QA.tsx:257` 的 `calc(100dvh - 6.5rem)`）。
5. **补齐依赖**：`@mantine/dates`（日期）；可选 `@mantine/charts`（当前直接依赖 recharts，图表配色/提示未跟随主题，见 UI-A11Y-5）。

**与既有批次的关系**：第 1/2 步并入 B1，第 3/4 步并入 B3，第 5 步与 B4 一起评估；执行顺序建议 B1 → B5（本轮布局）→ B6（本轮 CRUD）→ B3。
