# 训练界面与方向（一页）

> 2026-09-27。取代 `ui-redesign-brief` / `ui-redesign-spec`（已删）。截图：[ui-screens-2026-09-27/](ui-screens-2026-09-27/)。

## 诊断（按影响排序）

1. **门禁曾以一行 13px 橙字出现在对话列**（无容器、无语义、在与视线相反的位置）→ 已改为**输入区上方 Alert**（`aria-live`）+ 顶栏按钮计数徽章 + 完成清单逐条动作。
2. **步骤芯片像调试标签**，不传达"在哪一步、还差什么" → 待改为有序步骤 + 状态（顺序取 `ui.order`，状态取 `artifacts[].state`）。
3. **工具面板与触发它的图标没有视觉关联** → 面板改**常驻 Aside**（不遮挡对话），rail 激活项实心 brand（已做）。
4. **空/加载/错误态没有设计**（评分等待只有进度条）→ 待补。
5. **任务卡会被滚动冲走**，且手机首屏被其文案占满 → 待做：任务卡常驻对话列顶部，滚出若干条后折叠为一行进度。

## 已采纳并已实施

- 桌面：患者列 **248** · 对话列弹性 **max 800** · rail **48**（图标 + Tooltip + 激活实心）· 面板 = 常驻 Aside。
- 手机：患者条（身份 + 主诉 + 采集进度 + 情绪）+ 能力条 + 输入区；顶栏只留计时/音量/交卷。
- 字号进主题：正文 **15/1.55**、辅助 **13**、元信息 **12**（弃 11px 正文）。
- **信息一个归属**：患者身份 → 患者列/条；采集进度 → 患者卡/条；门禁 → 输入区 Alert + 顶栏徽章 + 完成清单；流程明细 → 完成清单。

## 核对过的外部说法

| 说法 | 实测 | 结论 |
|---|---|---|
| 「11–12px `dimmed` 对比度 < AA」 | 本仓主题已把 `dimmed` 指到 gray-7，实测 `#495057` ≈ **8.2:1** | 对比度无需改；**字号偏小成立**，已提级 |
| 「对话列 768 不该动」 | 15px 中文 ≈ 每行 48 字，正处可读甜区 | 采纳：用两侧列填充留白，不拉宽 |
| 「头像问题在裁切」 | 同一张图在 36px 圆头像里干净 | 采纳：4:5 + `cover` |

## 技术边界（不是禁令）

- 状态只来自服务端 manifest；Alert/徽章/清单都只是渲染层，想改口径去改声明或评分政策。
- 不引入第二套 UI 库（单人维护：主题、暗色、无障碍只有一套）。
- 交互通道（对话 SSE / 工具 HTTP）不重写；双工语音等在**通道之上**加层，见 [ideas/next-phase-directions-2026-09-27.md](../ideas/next-phase-directions-2026-09-27.md)。
