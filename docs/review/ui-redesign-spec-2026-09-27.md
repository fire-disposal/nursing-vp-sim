## 一、采纳的设计方向

| 位置 | 方向一（**采纳为目标**） | 方向二（记录为备选，触发条件如下） |
|---|---|---|
| 桌面 | **AppShell 三列**：患者列 248px + 对话列（弹性，最大 800）+ 工具 rail 48px + **面板改 `AppShell.Aside` 常驻**（非模态、不遮挡对话，"边检查边对话"） | 顶栏承载患者与状态 + 单栏对话；工具面板仍用 Drawer。**仅当"必须在极短deadline前冻结 SUS 候选"时**才退到这条 |
| 手机 | **任务卡折叠为一行进度条**（点击展开完整任务卡 Sheet）+ 门禁 Alert + 能力条 + 输入区 | 任务卡原位默认 `Collapse` 收起。**不采用**：任务卡仍会被滚动冲走 |

两个**推进阶段**（采纳其执行建议）：

1. **阶段一（无布局风险，先做）**：条目 1–7 —— 头像裁切、门禁 Alert、主题 token、步骤进度、输入区 Card 化、
   工具 rail 44px 与激活态、空/加载/错误态。
2. **阶段二（结构与断言，单独一轮，SUS 开跑前冻结）**：条目 8–10 —— 手机任务卡→进度条+Sheet、
   桌面 Drawer→`AppShell.Aside`、患者列加宽与体征网格。

## 二、本仓核对（采纳前先验证，结论写在这里）

| 评审的说法 | 本仓实测 | 结论 |
|---|---|---|
| 「11–12px `dimmed`（gray-6）白底 ≈4.0:1，不满足 AA 4.5:1」 | **`dimmed` 在本仓已被主题覆写**：`theme/index.ts` 把浅色 `--mantine-color-dimmed` 指到 `gray-7`，页面实测 `#495057`（≈8.2:1）；注释里就写着默认 gray-6 `#868e96` 白底 3.32:1 不达标（我独立算得同样 3.32:1）。暗色用 `gray-3`。 | **对比度这条本仓已解决**，不需要再改色。**但它关于字号的建议成立**：11–12px 作为正文偏小 → 阶段一统一到最小 13px、正文 15px/1.55 |
| 「A2 的 768px 不该动，问题在两侧留白无归属」 | 同意：中文 15px 下 768px ≈ 每行 48 字，处于可读甜区 | **采纳**：不改对话列宽度，用两列填充留白 |
| 「B4 根因是裁切，不是素材」 | 同意：同一张图在 36px 圆头像里干净 | **采纳**：`fit="cover"` + 固定纵横比，不换素材 |
| 「任务卡会被滚动冲走」（我清单里漏了） | 成立：任务卡目前是对话流的第一条消息 | **采纳**：任务卡拎出消息流、常驻对话列顶部，滚出若干条后自动折叠为一行进度摘要 |
| 「工具面板改 Aside 对 jsdom 更友好」 | 成立：`AppShell.Aside` 的声明式宽度可直接断言，Drawer 的过渡态不行 | 采纳（阶段二） |

## 三、主题 token（阶段一，一次性进 `createTheme`）

```ts
fontSizes: { xs: '12px', sm: '13px', md: '15px', lg: '17px', xl: '22px' },
lineHeights: { xs: '1.45', sm: '1.55', md: '1.55', lg: '1.35', xl: '1.3' },
radius: { sm: '8px', md: '12px', lg: '16px' },
spacing: { xs: '8px', sm: '12px', md: '16px', lg: '24px', xl: '32px' },
shadows: { xs: '0 1px 2px rgba(0,0,0,.06)', sm: '0 2px 8px rgba(0,0,0,.08)', md: '0 8px 24px rgba(0,0,0,.12)' },
```

规矩：**正文统一 15px/1.55，标题 1.3–1.35，最小正文 13px（弃用 11/12px 正文用法）**；不允许组件内联
style 再出现字号/行高/圆角字面量——这是单人维护下控制散落的唯一可行手段（暗色态也因此免费获得）。

## 四、组件规格（阶段一逐条）

1. **头像裁切**：固定 4:5 容器 + `fit="cover"`（`Image radius="md"` 或 `Avatar`），禁止拉伸；暗色下给容器
   `bg="gray.1"` 兜底（近白抠图在暗色会反显成亮块）。
2. **门禁 → `Alert`**：`variant="light" color="orange" radius="md" icon={<IconAlertTriangle/>}`，
   `title="还不能交卷"` + `aria-live="polite"`（门禁由 manifest 驱动，出现/消失要能被辅助技术感知）。
   位置：输入区正上方（视线终点），出现/消失用 `Collapse` 包裹；顶栏「结束训练」保留数字徽章。
   **只有声明了门禁的病例才会出现**（见 [../15](../15-workflow-activity-contract.md) §五）。
3. **步骤进度 → `Progress.Root/Section`**（不用 `Stepper`：40px 高放不下四段中文标签）：
   完成段 brand、当前段 brand.4、未到段 gray.3；每段配 `Text size="sm"`；完成态 `ThemeIcon` + `IconCheck`。
   文案全部留在 DOM（jsdom 可断言）。
4. **输入区 → `Card withBorder radius="lg" shadow="sm"`**：`Textarea autosize` + 左下 `Kbd` 快捷键提示
   （手机隐藏）+ 右下 44px 发送钮；语音状态改挂 Card 内 `Badge`。
5. **工具 rail**：48px 宽、44px 触控、`Tooltip`；激活 `variant="filled" color="brand"`（与 Aside 左边框贯通，
   解决"面板是谁打开的"）；角标点表示待处理；`aria-label` 原样保留（测试依赖）。
6. **空/加载/错误态**：评分等待文案化（区分"在算"与"卡住"）；面板空态 `Paper` + `ThemeIcon` + 一句话；
   首帧"正在接入患者"用空态占位而不是纯空白。
7. **气泡**：患者左对齐 `Paper bg="gray.0"`，学生右对齐 `bg="brand.0"`（暗色自动），`maw="75%"`，15px/1.55。

## 五、响应式降级顺序（先牺牲 → 最后牺牲）

1. Aside 常驻 → Drawer 覆盖（<1200px）
2. 患者列 248 → 200px（<1100px）→ 顶栏患者条（<768px）
3. rail 标签文字（<600px 只留图标）、建议开场芯片数量
4. 任务卡正文 → 折叠进度条（<600px）
5. **绝不舍弃**：输入框与发送钮、门禁 Alert（任何一级都必须是 Alert，不降级成纯文字）、结束训练按钮
   （可缩成图标 + 徽章，`aria-label` 不变）、计时

矮视口（844×390）：顶栏并成单行、患者条并入顶栏、任务卡强制折叠、Aside 一律禁用改 Sheet。

## 六、明确不做（与评审一致）

不新增状态源；不改评分/门禁语义（Alert 只是渲染层，条件仍由 manifest 决定）；不引入图表或动画库；
不重写交互协议。
