# SP 剧本标准与仓库对应物

> 2026-11-17 整理，外部领域参照，**不是运行期契约**，也不构成本项目的验收条件。
> 用途：写病例、复查病人扮演提示、讨论评分条目来源时可对照。
> 领域合理性由领域的人判断（见 `AGENTS.md` 责任边界），此处只记录标准长什么样。

## 结论

标准化病人（SP）的剧本没有强制统一标准。ASPE 的 Standards of Best Practice 与 INACSL 的
Healthcare Simulation Standards 只规定案例开发必须包含什么，模板由各机构自定；
国内 OSCE 与执业医师技能考试同样各考点自建。

事实上的通用骨架固定为十一节：病例头信息、患者画像、开场台词、现病史、既往史与敏感项、
阳性阴性三档清单、情绪与行为设定、模拟体征与查体配合、红线条款、安全条款、反馈提示。

三条跨体系硬规则：

1. SP 版剧本不写诊断名称，只写症状与行为，防止无意泄露。
2. 每个评分点都能在剧本里找到对应的可观察行为。
3. 一切回答写成可表演的具体行为，不写无法校准的心理描述。

书写格式有三种：叙述式、问答双栏、触发式条目。计分场景用问答双栏，一致性最好。

配套文档通常是四件套：病例卡（含诊断与教学目标）、SP 剧本（无诊断名）、考官与评分手册、
SP 培训手册。SP 本人在上岗前要过剧本掌握、表演一致性、模拟体征、评分校准、反馈技巧、
保密与安全边界、心理调适等训练，并以试演加录像抽查验收。

## 与仓库的对应

| 剧本要素 | 仓库里的对应物 |
|---|---|
| 病例头信息与教学目标 | `case.toml` 的 meta，`case.md` 的教师备注 |
| 病史、触发式回答 | V1 病例的问诊条目；V3 `actors[].knowledge` |
| 阳性与阴性三档 | V3 的线索揭示记录，也就是判读账本 |
| 情绪与行为设定 | 病人扮演提示的语段；V3 `case.md` 的人物段 |
| 模拟体征 | 床旁检查的现状范围，仅生命体征、皮肤黏膜、疼痛评分 |
| 红线条款 | 提示里不得说出诊断名，不得提供未问信息 |
| 评分点映射 | 评分条目与护理记录证据、问诊条目的对应 |
| 反馈提示 | 训练回顾与教师复核 |
| 安全条款 | 无真人，不适用 |

## 已知边界

- 只用来对照结构，不据此新增字段、校验或门禁。改病例格式先看 `scenario.md` 的拆分原则：
  同一份事实一处落点。
- 「AI 虚拟病人每场是否演得一样」是产品问题，标准里的一致性靠剧本写死加人工校准会达成，
  搬不到模型上，也没有对应的自动化手段。
- ASPE 与 INACSL 的条款序号、版本年份未核原文，本文只用到名称与大致分工。
