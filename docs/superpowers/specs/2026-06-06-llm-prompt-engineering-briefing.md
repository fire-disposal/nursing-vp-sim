# 虚拟患者 LLM 提示词工程重构简报

> 分支: `feat/patient-interaction-v2` | 提交: 30+ commits | 状态: 开发调试阶段

---

## 一、重构动机

**旧版问题：**
- 患者回复机械，一问一答无主动性
- 关键词解锁机制（hidden_info_rules）需要学生问到特定词才披露信息，不自然
- Guard 模式过于激进（26 条正则），误拦率高达 70%（"病例""该问的"等日常用语被拦截）
- 无情绪反馈——无论学生说什么，患者态度不变
- 无法执行护理操作（测体温/血压/查体）

**目标：** 从"考核优先的内容管控"转向"模拟自然的语境塑造"

---

## 二、核心技术变更

### 2.1 Prompt 架构：Character Card 格式（借鉴 SillyTavern）

```
旧: 单一长 prompt (~800 tokens)，全部变量嵌入一个模板
新: 三层架构
  Layer 1: Character Card (角色+性格+规则) → DeepSeek prefix cache 全局复用
  Layer 2: Patient Dynamic (病情+背景+示例对话) → per-session ~200 tokens
  Layer 3: Author's Note (情绪/操作上下文) → 每轮注入到用户输入之前
```

**Author's Note 位置**是最关键的改动——借鉴 AI 酒馆社区经验，注入到聊天记录之后、用户输入之前，作为 LLM 生成前的最后一条指导指令。

### 2.2 患者人格模型（4 维度）

| 维度 | 值 | 对对话的影响 |
|------|-----|-------------|
| health_literacy | low/normal/high | 医学术语理解能力（低→需通俗解释，高→久病成医） |
| verbosity | terse/normal/verbose | 回复长度和跑题倾向 |
| anxiety_trait | calm/normal/anxious | 反问频率、担忧表达 |
| patience | low/normal/high | 持续回答的耐受轮数 |

人格信息直接注入 Character Card 的 `## 你的性格` 段落，LLM 每轮都可见。

### 2.3 5 态情绪状态机

```
withdrawn(-2) ↔ defensive(-1) ↔ neutral(0) ↔ relaxed(+1) ↔ open(+2)
```

**纯规则驱动**（不调 LLM），根据学生意图分类调整：
- 关心/共情 → +1 | 粗鲁/指责 → -1 | 解释原因 → 0
- 输出为一行 Author's Note：`【当前: 患者放松配合，语气友好】`

### 2.4 知识注入（替代 hidden_info）

```
旧: hidden_info_rules → 关键词触发 → 解锁信息
新: deep_background → 始终可用 → 按性格自然使用
```

患者背景信息始终在 prompt 中，LLM 根据人格决定是否主动提及（絮叨的可能主动说，寡言的被问到才回答）。

### 2.5 示例对话（Example Dialogues）

病例可定义 2-3 组 `护士问 → 患者答` 示例。LLM 在 Character Card 中看到这些对话后，天然模仿其语气/节奏/信息透露方式。这是 AI 酒馆社区验证的**最有效的角色一致性技术**。

### 2.6 Guard 精简

```
旧: 26 条正则 → 角色泄露/诊断泄露/教学泄露/隐藏信息泄露
新: 11 条 → 仅身份泄露检测（"我是AI""评分标准"等无法用 prompt 约束的硬违规）
```

**废弃**：诊断泄露检测、教学指导检测、关键词匹配、LLM 二次修正。这些改为 prompt 工程预防。

### 2.7 患者主动行为引擎

避免沉默等待——患者根据性格/情绪/等待时长，从行为池中抽取自然反应：

| 池 | 示例 | 触发条件 |
|----|------|---------|
| 焦虑桶 | "护士……我这情况严重吗？" | 情绪负面 + 焦虑人格 |
| 催促桶 | "怎么问来问去的……" | 低耐心 + 等待过长 |
| 闲聊桶 | "对了，我还想起一件事……" | verbose 人格 |
| 非语言 | "[叹气][不安地挪动身体]" | withdrawn/defensive 状态 |

**触发机制**：基础 30s 阈值，人格/情绪调整（15-90s），打字时冻结，两次触发间隔 ≥8s。

### 2.8 双通道操作（查体/测量）

学生可触发护理操作（测体温/血压/血氧/查体等），系统直接从病例锚点数据返回结果，LLM 通过 Author's Note 获知并做出自然口头反应。

## 三、收益

| 维度 | 改善 |
|------|------|
| 角色一致性 | Character Card + 人格模型 + 示例对话 → 患者行为符合设定的性格 |
| 对话自然度 | 情绪动态响应 + 主动追问 + 非语言线索 → 不再是一问一答 |
| 教学闭环 | 可执行护理操作 → 不止"问"，还能"做" |
| 工程可维护性 | Guard 从 189 行降到 25 行；AI 模块统一入口 `patient_ai/` |
| 提示词效率 | 分层缓存 → prefix cache 命中后增量推理 < 500 tokens |
| 可调试性 | 调试工坊实时显示情绪/人格/操作/追问倒计时 |

---

## 四、风险与副作用

| 风险 | 等级 | 说明 | 应对 |
|------|------|------|------|
| 旧病例兼容性 | 🟡 中 | 旧格式没有 personality/deep_background/example_dialogues | 启动时自动注入默认值；已有迁移脚本 |
| Guard 误漏 | 🟡 中 | 删除了诊断泄露检测，依赖 prompt 约束 | 监控线上患者回复质量；必要时恢复特定模式 |
| 情绪准确性 | 🟢 低 | 纯规则匹配，意图分类粗糙 | 可后续升级为轻量 LLM 分类 |
| 主动追问时机 | 🟡 中 | 阈值调整依赖经验值 | 调试工坊可实时观察；阈值可通过 SessionConfig 配置 |
| Token 增量 | 🟢 低 | 人格+背景+示例对话增加 ~150 tokens | 在 DeepSeek prefix cache 范围内，无额外推理成本 |

---

## 五、下一步建议

1. **线上灰度**：先在自由探索模式下开放，收集真实对话质量反馈
2. **病例补齐**：为病例 6-10 补充针对性 personality + example_dialogues
3. **情绪分类升级**：将关键词匹配改为轻量 LLM 意图分类（1 次 cheap model 调用）
4. **动态事件**：情境模拟模式下，系统可主动触发事件（如"患者突然捂着胸口"）
