# 虚拟患者交互性升级 Spec

## 概述
当前系统为回合制问答，学生提问→患者回答。目标升级为更沉浸的仿真交互体验。

---

## 1. 随机病例生成

### 现状
5 个固定 JSON 文件，训练多次后学生产生记忆效应。

### 方案
- 每次 start_training 时调用 LLM 实时生成一个唯一病例
- 生成维度：姓名、性别、年龄、职业、教育程度、家庭结构、经济状况、性格特点、生活习惯
- 主诉 + 现病史 + 既往史 + 用药史 + 过敏史 + 家族史 + 社会心理
- required_inquiries（必须采集的护理关键点）
- hidden_info（需追问才透露的敏感信息）+ 触发条件
- communication_style（口语化风格描述）
- 病例保存到 DB 供评分使用

### 约束
- 随机但不荒谬（年龄与主诉匹配、职业与生活习惯一致）
- 包含角色内在矛盾（如"知道该戒烟但戒不掉"）
- 每次生成 1 个，不批量

---

## 2. 实时对话提示

### 现状
训练结束后一次性评分，过程中学生不知道漏了关键信息。

### 方案
- 对话区顶部展示本场景必须采集的护理关键点列表
- 已采集 → 绿色，未采集 → 灰色
- 后端在每轮对话后扫描学生消息，检测是否涉及关键点
- 纯规则匹配（关键词 + LLM 分类），不增加延迟

### 交互
- 可折叠/展开，避免干扰
- 训练结束时对比"已采集"与"应采集"，作为评分维度之一

---

## 3. 患者情绪状态机

### 现状
患者情绪在 prompt 中静态描述，无动态演化。

### 方案
- 5 态模型：neutral → relaxed → hesitant → defensive → withdrawn
- 触发规则：
  - 学生表达关心/共情 → +1 向 relaxed
  - 学生语气粗鲁/打断 → -1 向 defensive
  - 追问隐私未解释原因 → -1 向 hesitant
  - 长时间沉默（n 轮无消息）→ -1 向 withdrawn
  - 学生道歉/安抚 → +1 向 neutral
- 每轮对话后 guard 更新状态
- 下一轮 prompt 注入 `{#emotional_state#}` 变量

### 效果
- relaxed：更愿意配合，可能主动透露信息
- defensive：回答简短、回避眼神（[低头]），需要安抚
- withdrawn：沉默或敷衍（"没什么""还好"），需要道歉拉回

---

## 4. 时间循环（回合→自然节奏）

### 现状
纯回合制——学生发消息→患者立即回，不考虑时间流逝。

### 方案
- 引入"会话轮次"追踪
- 患者可以在学生沉默时主动发起话题（"你还有什么想问的吗？"）
- 模拟真实问诊的时间感：
  - 如果学生 3 轮都在问同类问题，患者表达不耐烦
  - 如果学生很久（n 轮）没说话，患者主动问"要不今天就到这？"
- 技术实现：后端 asyncio 等待超时事件触发患者主动发言

### 复杂度
需要 WebSocket/SSE 双向流，前端要支持"患者先说话"的推送。**当前架构最难实现**，建议作为远期目标。

---

## 实施优先级

| 顺序 | 功能 | 难度 | 收益 |
|------|------|------|------|
| 1 | 随机病例生成 | 低 | 极高 |
| 2 | 情绪状态机 | 中 | 高 |
| 3 | 实时对话提示 | 中 | 中 |
| 4 | 时间循环 | 高 | 中 |

```
lab/

├── experiment_01_random_case.py    # 随机病例生成实验
├── experiment_02_emotion_state.py  # 情绪状态机实验
├── experiment_03_realtime_hints.py # 实时对话提示实验
├── experiment_04_time_loop.py     # 时间循环实验（远期）

```
